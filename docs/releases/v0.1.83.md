# v0.1.83 — demanded recursive type provenance

Recursive generic functions can forward compact prerequisite DAGs without eagerly
materializing every typed witness path. The source checker discovers the complete
exact callable-context graph, then follows incoming provenance from declaration
type parameters. Every expanding cycle remains in this closure. Exact selected
identities, lexical scopes, witness positions and independent source admission
remain unchanged.

The new ordinary public workload admits and exports a 24-layer recursive generic
library before any concrete implementation exists. Bounded concrete consumers keep
distinct same-Self readers, borrow the original owner, preserve identities across
an edit and restore, and execute independently after authoring sources are removed.
The predecessor's corrected public input fails with a resource diagnostic rather
than mutating accepted meaning.

Matched proof probes record substantial reductions for deeper recursive cases and
retain the extra work on the smallest cases. These are source-proof work and
conservatively reserved metadata, not runtime speed, RSS, or API-cost claims. The
limits are not raised. Expanding recursion, scope errors, invalid unused operands,
work exhaustion and cancellation retain separate outcomes.

No meaning-graph, interface, type-object or artifact encoding change is introduced.
This derived proof change does not require a data migration. All components of the
product identifier remain opaque; they do not promise compatibility or maturity.
Concrete prepared-witness materialization and general context/path growth remain
separate bounded costs.
