# v0.1.62 — opaque product identifiers

Development notes; this is not a public release announcement. [Status](../status.md)
separates source integration, candidate acceptance and public availability. This
identifier distinguishes this source from the frozen v0.1.61 candidate; it does
not classify the size or compatibility impact of the change.

## Every component has the same role

The owner's 2026-10-01 decision makes every component of `A.B.C` an identifier,
not a major/minor/patch signal. No component denotes stability, compatibility,
change size, required migration or feature availability. A leading `1` is not a
stability promise and a leading `0` is not an instability declaration. Exact
contracts, capability discovery and tested behavior remain authoritative.

Default, focused and cached capability discovery now includes
`version-policy=opaque-triplet` in its product record and complete capability
digest. The `--version` line remains `lkjscript A.B.C`. Strict capability clients
must admit the added field and refresh their cached discovery. Re-plan retained
review requests after changing executable context; do not rewrite their bases.

## One tag validator across release boundaries

Production, verifier handoff and installation share the release-container
validator. It accepts exact canonical `vA.B.C`, with three nonempty ASCII decimal
components, no leading zero except `0`, and at most 64 bytes including punctuation.
It does not parse integers, resolve ranges, select a numeric latest or infer
compatibility. The previous contributor producer and handoff validators could
admit 65-byte tags that the container rejected; both paths now enforce the existing
container bound. Historical canonical tags remain admitted unchanged.

No graph, compiler, artifact, manifest or application-data encoding changes.
No external dependency versions, published assets, runtime selection, service,
secret or operational data is changed. The v0.1.61 candidate retains its original
source and cannot be relabeled as containing this increment.

The [identity contract](../spec/product-surface.md#opaque-three-component-identifiers)
and [continuation](../campaigns/20261001-version-policy.md) own the policy and
exact-source evidence.
