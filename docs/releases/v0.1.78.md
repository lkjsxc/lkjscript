# v0.1.78 — Source-tied borrowed results

Pure functions and owned-contract methods can return read-only views tied to one
exact borrowed input. A lexical `borrow-call` keeps the input and required
ancestors protected until its body completes. The view can cross named helper
boundaries without consuming or copying the underlying owned element.

Declare a function result with `(returns T (borrow-from storage))`; a contract
method identifies the corresponding zero-based parameter position. Exact source
identity is checked through generic substitution, package interfaces, transport,
compilation and execution. Returning from another input remains invalid even
when the two inputs alias the same allocation.

The native `IndexRead<Item>` witness selects the first maximal element from flat
and chunk32 collections of cells and buffers. After observing the selected view,
its consumer drains the unchanged collection and reuses its empty owner. The
generic library is authored before its implementations, and detached artifacts
run after authoring projects have been removed.

Result handoff preserves the selected read token and its necessary lifetime guards
before callee cleanup. Cancellation, traps and failed adoption retain one cleanup
owner. Borrowed-result functions do not perform tail-call activation replacement
in this release. Mutable views, alternative source roots, first-class borrowed
callables, stored references and asynchronous borrowed results remain unsupported.

This release selects graph/owner 27, package interface 15, compiler unit 27,
bytecode 22 and artifact 34. Rebuild experimental derived bundles with the new
executable; no migration layer is provided. Existing immutable publications and
their evidence keep their original identities.

See the [guide](../guides/native-owned-read-results.md) and
[specification](../spec/owned-read-results.md). [Status](../status.md) records
accepted source, exact candidate bytes and publication separately.
