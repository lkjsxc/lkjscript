# v0.1.91 — nominal owned records

This identity selects nominal owned records with module-private representations.
[Current status](../status.md) owns actual source acceptance and publication.

An `owned-record` has an exact package/declaration identity and ordered generic
arguments. Empty and data-only instances are affine. Its defining module alone
can construct, decompose or project its fields; consumers compose public functions
and exact implementation witnesses without field authority. Source-tied reads,
transfer and sharing retain their existing independently checked obligations.

The standard FIFO now exposes `Fifo<T>` instead of its two-stack product. Its
native operations retain their ordering, owner-returning outcomes and borrowed
front behavior. Runtime storage retains one custody envelope and the exact
nominal type; this increment does not add a wrapper allocation or a general cast.

The [specification](../spec/owned-records.md) defines complete layout admission,
private transport evidence and failure behavior. Recursive owned representations,
nominal owned variants, mutable borrowing and user-defined cleanup remain outside
this increment.

The intentional format cut selects Graph 32, interface 20, compiler 32, bytecode
27 and artifact 39. Authored changes use codec 36, compact changes 40, function
definitions 21, registry 25 and CLI 45. Existing named/applied type envelopes are
unchanged. Rebuild experimental derived artifacts; no migration shim is provided.

Final-byte acceptance generation 8 requires the nominal-record public witness
family in addition to the existing FIFO and other maintained public families.
Source verification, finalized executable acceptance and immutable publication
remain distinct; these notes alone claim none of those terminals.
