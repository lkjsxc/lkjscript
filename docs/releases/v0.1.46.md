# Native forms and a durable browser editor

## General byte operations, ordinary form logic

`bytes-from-list(List<I64>) -> Bytes` constructs unsigned octets and traps on any
value outside 0 through 255. `bytes-to-text-result(Bytes)` returns an explicit
`{valid: Bool, value: Text}` result for strict UTF-8: invalid encoding is false with
empty text, while valid empty input is true. Operational failures remain failures.
The existing trapping byte-to-text operation is unchanged.

These general operations support an ordinary lkjscript URL-encoded form library.
It applies explicit byte/field limits, strict percent/UTF-8 decoding and ordered
duplicate preservation. Application-specific validation and admission are not
hidden in a new HTTP/form runtime intrinsic. The byte operations and codec were
integrated after the frozen v0.1.45 source and first select distribution here.

## A useful native application

The ordinary UI library adds fixed POST forms, hidden fields, labeled multiline
inputs and line-preserving text blocks. The new shared-note editor combines it
with the form library, configuration, independent credential verification and the
existing transactional store. App authors write lkjscript, not HTML/CSS/JavaScript.
The library emits fixed HTML/CSS and the browser needs no application script.
The Rust kernel remains a supported implementation boundary.

Saves require an authenticated request with an exact configured Host and Origin,
a bounded valid form and a current base revision. The read and conditional write
share a completed transaction. A successful save redirects to a read-only GET;
competing writers see the saved version alongside their retained draft and must
review and explicitly save again. There is no automatic overwrite or effect retry.
Malformed stored data and version exhaustion are not silently treated as empty.
An absent response does not prove that a commit failed.

The example includes public authoring/import instructions, native tests, a tested
loopback descriptor and source-free restart. It is a bounded single shared note,
not accounts, sessions, an identity-provider integration, a rich-text editor or a
complete framework. Basic access requires TLS on an untrusted network. Inbound TLS,
encrypted storage and hostile multi-tenant containment are not supplied here.

## Compatibility and evidence

New byte closures require a compatible runtime; immutable v0.1.45 rejects them.
Retain old executable/artifact pairs for old deployments. Runtime installation or
selection does not migrate application data. The UI extension is an explicit exact
package update, not an automatic upgrade; exhaustive matches on its closed node
variant need the added cases. The form/UI/editor proposals are repository examples,
not an application-specific built-in package or a silently installed server.

The maintained public-CLI workload covers fresh ordinary authorship, exact suppliers,
strict rejection, conditional saves, two-process contention, operational write failure,
joined shutdown, source-free restart and invalid-store/version boundaries. An independent
Chromium trial performs actual authenticated POST/redirect/GET and two-tab conflict
review with page JavaScript disabled. It caught the initial no-referrer/Origin-null
incompatibility; the corrected same-origin policy preserves strict admission.

Distribution remains the static x86_64-unknown-linux-musl executable, archive,
checksum and installer. Source, finalized-candidate, immutable-publication and
anonymous installed verification are separate claims. The actual delivery state
and original identities are recorded in docs/campaigns/202609251211.md and
docs/release.md; these notes alone do not establish publication.
