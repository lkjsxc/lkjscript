# lkjscript v0.1.39

This release selects the integrated general-purpose authoring, runtime and application-data
improvements after v0.1.38. The [release lineage](../campaigns/202609201910.md) and
[delivery continuation](../campaigns/202609210911.md) record the exact accepted producer and
publication state. These capability and compatibility notes are not an acceptance receipt.

## Capabilities and corrections

Persistent ordered maps share unchanged subtrees and retained entry payloads instead of copying
the entire map for each immutable update. Retained versions and branches remain independent.
Key ordering, map operations and canonical encodings are unchanged. Storage reservations still
precede growth; failed reservations and cancellation do not expose a partial map. Deep map
comparison and retained-state validation also avoid the diagnosed default-profile stack overflow.

Reviewed `set.parameter-type` allows a callable's input contract to evolve while preserving the
parameter's identity. Body, caller, port and exact dependency repairs can be reviewed and accepted
as one complete change. Incomplete repairs are rejected rather than partially published. The
integrated HTTP response correction is included.

Application-data pagination seeks directly to the selected namespace, space, typed key prefix
and exclusive continuation. It no longer rescans preceding pages and unrelated records before
charging logical scan work. Forward/reverse order, byte/item/work bounds and snapshot-bound
continuations remain intact. This optimizes record selection, not whole-snapshot transaction
loading, persistence, serialization or end-to-end application latency.

Data readers reject empty stored/resume keys, duplicate or out-of-order records and schema keys,
and physical ancestry inside logical backups. An empty scan selector remains valid. Invalid
backups reject before a destination is published, rather than being silently normalized.

## Distribution, compatibility and recovery

The Linux x86-64 musl distribution contains the executable, license, third-party notices and a
publication-neutral release-content manifest. The public assets remain
`lkjscript-x86_64-unknown-linux-musl.tar.gz`, `SHA256SUMS` and `install.sh`.
Candidate acceptance and publication authority are separate: the accepted assets are promoted
unchanged, and failed transfer or publication boundaries can resume without rebuilding a healthy
candidate or repeating completed broad behavioral owners.

Older native managers may reject the new neutral container format. Use this version's exact
bootstrap to acquire its new manager; do not rewrite older installed receipts or manifests.
Retain the matching predecessor executable and immutable runtime slots for recovery. Runtime
installation or selection neither changes running processes nor grants application authority.

The callable-input operation is an additive public authoring operation with current semantic
validation. Historical acceptance is preserved but is not present execution permission: projects
or artifacts with invalid ports or invalid fixed externals must be repaired through a reviewed
change or run with their matching preserved predecessor when appropriate. New authoring meaning
requires a supporting executable. This release selection itself introduces no further graph,
compiler, artifact or application-data format generation.

Valid application-data store, backup and continuation encodings are unchanged. Malformed physical
roots that previously loaded may now reject; preserve them for explicit recovery instead of
deleting or silently rewriting them. Keep application-compatible backups and check restored data
in an absent destination before explicitly switching a deployment descriptor. Neither installation
nor a runtime rollback migrates application schemas or reverses accepted program edits.

Whole-snapshot transaction reads/writes and historical storage growth remain important limitations.
No guarantee of indefinite real-time simulation, universal throughput or hostile-code isolation is
made. Immutable earlier releases, their assets, and genuine historical failures remain unchanged.
