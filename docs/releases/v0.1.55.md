# v0.1.55 — ordinary generics with scoped resources

Development source, not a public release. The [campaign](../campaigns/202609281735.md)
owns exact verification and integration evidence. Public availability is recorded
in [status](../status.md); a version in Cargo metadata does not publish a binary.

## What changes

A private same-package task helper with one final direct capability-resource
parameter may now declare ordinary type parameters. Preceding ordinary values,
resource-free callbacks and ordinary results use the existing explicit rank-one
type substitution. Both `(use borrow)` and `(use consume)` compose with these
types, and a borrowing helper can pass its type argument through another direct
borrowing helper. The resource interface and exact requirement binding remain
concrete; an ordinary type parameter does not abstract deployment authority.

The [literal queue consumer](../../tests/fixtures/type-generic-resources.lkjc)
uses the same generic borrowed reader with two different decoders: a list of
integers and Unicode text. It borrows through a nested helper, reads again, then
moves the one resource into a generic completing helper and returns ordinary
data. The public test drafts and rebuilds accepted meaning, removes the authoring
project from its original path, runs the detached artifact four times, and checks
the raw persisted jobs independently of the helper's return value. A separate
failure witness traps inside the nested borrowed decoder, verifies that the
claimed job remains leased without a completion result, and completes another
ready job without changing the failed job. Invocation cleanup is not durable
rollback, implicit completion or permission to retry blindly.

The implementation removes the ordinary-type prohibition from canonical
signature checks, the independent affine reference and hostile preparation.
It does not add an execution engine, syntax family, collector or object encoding.
Exact canonical type-parameter and resource-binding comparisons remain intact.
The `affine_capability_resources` validator feature advances from 3 to 4 so cached
validation evidence cannot silently stand in for the changed semantic boundary.

## Unchanged boundaries

The final parameter is still the only resource parameter, used only by a direct
named acyclic call with matching exact requirement/interface authority. A borrowed
view cannot be consumed, retained, returned or passed through an ordinary generic
argument. Public/package-visible helpers, effect/requirement-polymorphic resource
signatures, indirect resource calls, asynchronous borrowing and cross-package
resource transfer remain outside this increment. Automatic extraction retains its
existing nongeneric, consuming-resource eligibility.

No memory-reference/lifetime language, trait implementation system, region heap,
zero-copy data path, parallel scheduler or speed improvement is claimed. The
maintained non-generic worker remains compatible; this literal generic workload
is a separate public-language consumer, not a claim that all existing applications
were migrated. No application data or running service is changed.

## Delivery

The existing v0.1.54 producer stays bound to its original accepted source. This
continuation neither replaces it nor promotes a different tree under its identity.
A v0.1.55 publication requires its own fresh source acceptance, normal mainline
integration, final-candidate admission and all three public generic-resource tests
against the executable extracted from the exact final archive before promotion.
Original failures remain failures; subsequent corrections require their own proof.
