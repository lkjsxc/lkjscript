# v0.1.57 — exact resource contracts across packages

This development increment extends ordinary graph-authored resource contracts to
public libraries. [Status](../status.md) owns public availability and the
[campaign](../campaigns/202609290026.md) owns exact-source acceptance and delivery.
A Cargo version is not a published executable.

## One contract at every boundary

A public task helper may borrow or consume one final direct capability resource.
Its signature retains ordinary type parameters, the exact resource interface,
parameter use, concrete requirement binding and closed task effect. Private and
package-visible dependency members stay hidden. A public forwarder may retain the
original supplier requirement instead of inventing a caller-local authority alias.
Recursive helpers retain the same per-body affine obligations.

The consumer entry port explicitly names imported concrete requirements in its
closed top-level task row. These become deployment obligations alongside existing
component-owned slots. Calls inside the implementation, callback types and unused
supplier requirements do not imply authority. Actual grants remain mandatory.
The same-name, same-interface resource of a different requirement cannot satisfy
the parameter contract.

Canonical checking, independent affine flow, public package interfaces, linking,
strict artifact loading and normalized preparation retain those exact fields.
Foreign requirement metadata comes from its owning dependency, not a copied local
definition. Command and HTTP entry admission agree about declared imported effects.
No new compiler primitive, execution engine, storage encoding or runtime host is
introduced. Affine validator feature 6 and qualified-task feature 2 distinguish
this semantic boundary from predecessor evidence.

## Native evidence

The literal [library](../../tests/fixtures/package-resources-library.lkjc) exports
a recursive generic borrower and generic consumer. The
[consumer](../../tests/fixtures/package-resources-consumer.lkjc) forwards both
contracts, decodes integer lists and Unicode text, consumes completed queue leases,
and observes absent results on repeated execution. Public tests export/stage the
packages, draft accepted meaning, build and run after deleting the source projects.
A third exported forwarding package preserves the original supplier authority.

Separate cases cover a failed recursive borrow without durable completion,
HTTP request/shutdown/restart, missing and unnecessary grants, same-name distinct
obligations, private/package members, borrower escalation, moved-owner reuse and
indirect calls. Rejected authoring leaves the project unchanged; rejected deployment
leaves application data unchanged. Rehashed hostile artifacts and the disjoint
affine oracle test exact parameter and signature integrity.

## Boundaries

One final direct resource parameter remains the limit. Ordinary values, callbacks
and results stay resource-free. Resource returns, requirement/effect-polymorphic
transfer, resource-capturing closures, asynchronous borrowing and cross-instance
ownership are not added. Existing automatic extraction remains nongeneric and
consume-only.

The current deployment descriptor selects grants by name. Distinct obligations
with the same name cannot share one grant or both be addressed by that format;
use distinct requirement names. This is not a general memory-reference/lifetime
language, trait implementation system, region allocator, zero-copy payload path
or measured performance improvement. Running applications and data are unchanged.
