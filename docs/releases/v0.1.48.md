# Immutable deployment builds

## Rebuild without manual bundle names

After a reviewed native edit and `lkjscript check`, run:

```sh
lkjscript build --deployment service.deployment.json
```

The new selector builds the current accepted graph and derives a complete
content-addressed artifact plus a sibling deployment descriptor. Use the returned
`deployment.path` explicitly with `serve --deployment` or `run --deployment`.
Repeated unchanged builds verify and reuse the same exact files, including when
independent cooperating builders run concurrently. A generated snapshot can itself
be used as a template without proliferating names for unchanged content.

The existing `build --output PATH` route is unchanged: its destination must be
absent, even when an existing file would contain identical bytes. The two selectors
are mutually exclusive. Use `capabilities build` to discover the selected runtime's
actual support; older releases do not gain the new command retroactively.

## Preserve operational authority

Build observes one strict bounded ordinary operator descriptor and statically
admits its exact target, runner policy and grants against the newly prepared
program. It does not read the old artifact, require environment secrets, open
adapters, initialize data, bind listeners or start a server. Graph tests remain
an explicit `check` operation, not an implicit claim of build success.

Only the descriptor's artifact value changes. Other JSON values and omitted fields
are retained. Its placement beside the template preserves relative local-data,
object-store and durable-queue roots. Outputs inside those declared roots reject.
The operator template, original bundles, accepted graph and running processes
remain unchanged. No automatic reload, default selection, migration or cleanup of
old versions occurs. Selecting an older program is not a rollback of saved data.

## Exact reuse and failure handling

Names are derived from complete output bytes, but a digest-shaped filename alone
is not trusted. Existing files are reused only after bounded exact-byte comparison.
Different bytes, symbolic links, nonregular files and invalid parents reject
without overwrite. New deployment descriptors are owner-only from their first
staged byte, even under a permissive process umask. Existing descriptors require
current-user ownership and no group/other access before exact reuse. A mismatch
rejects before artifact publication and never changes permissions or ownership.
Sharing configuration with another runtime account remains an explicit operator
choice. Ordinary artifact-output permissions are unchanged.

The common deployment reader now rejects duplicate JSON keys in configuration
maps instead of silently selecting the last value. Identical duplicates and
escaped spellings of the same key also reject. This applies to ordinary run/serve
as well as snapshot builds, before artifact loading or external effects. Existing
ambiguous descriptors need an explicit operator decision to retain one value;
valid descriptors and the full signed/unsigned 64-bit policy range remain supported.
No descriptor or application data is rewritten automatically.

The build preflights both outputs and publishes the complete
artifact before its descriptor through the existing create-new publication owner.

A late conflict or write failure may retain an inert complete artifact; no partial
new descriptor is exposed and another writer's file is not removed. Receipts report
creation or exact reuse, actual durability and stage cleanup. A cleanup failure is
not disguised as successful reuse. Content addressing does not prevent a local
owner or hostile concurrent filesystem writer from mutating files. Retention is
explicit; build never deletes old pairs to obtain disk space.

## Verification and boundaries

Focused tests cover byte/path limits, strict descriptor decoding, symlinks,
nonregular files, conflicting content, local-data separation and concurrent exact
publication. A controlled permissive-umask regression checks private creation,
unsafe-reuse rejection, unchanged source permissions and explicit operator repair.
Copied-executable command workflows compare snapshot artifacts with
ordinary builds, exercise four concurrent processes and reject conflicting
outputs without replacing originals.

A normal native persistent task saves data, receives an identity-preserving edit,
builds without changing the data head, and runs both new and retained old bundles
against the same store after the authoring graph is removed. A separate web
workflow changes the page title while the old server is running, validates all
107 graph tests, serves independently selected old/new pages and restarts both
snapshot files without the graph. A separate command workflow relocates complete
snapshots and a stopped data store through paths containing spaces and Japanese
text, reuses the same exact outputs, and runs from an unrelated working directory
without source. Store identity survives and transactions still complete. A copy
containing only code and configuration rejects rather than creating missing data.
These are HTTP, filesystem and lifecycle observations, not a new browser-rendering,
application-performance or live-backup claim.

The mechanism changes no language syntax, standard supplier or application UI
renderer. Hosting still uses one compatible lkjscript executable; bundles are not
self-contained native executables. The Rust runtime and static x86_64 Linux musl
distribution remain the supported boundary. Source acceptance, finalized-candidate
acceptance and public delivery are recorded separately in the current campaign.
