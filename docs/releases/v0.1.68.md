# v0.1.68: joined parallel owned tasks

Selected successor to public v0.1.64. Selection is not publication; exact candidate
and public availability are recorded in [status](../status.md).

This increment adds native `(parallel LEFT-CALL RIGHT-CALL)` for two exact empty-effect
graph tasks. A parent moves separate owned inputs to fresh child invocation identities
and receives ordinary `left` and `right` results after joining both children. Buffers,
scalar cells, nested owned products and choices retain their backing allocations.
Children can use ordinary generic libraries and exact static implementation witnesses.
Their arguments are prepared left-to-right before either child body begins.

Process-wide bounded workers use immediate capacity acquisition and caller fallback.
Nested execution does not wait for an ancestor's worker or resident task slot.
Instruction, modeled allocation and collection quotas remain invocation-wide. Failure
requests sibling cancellation, joins started work and reclaims transferred owners.
No task grants, resources, loans, secrets or dynamic child callables cross the boundary.
This first boundary has ordinary results, with channels and owned child results left
for separate extensions. Worker counts and real-child overlap are evidence of the
implemented mechanism, not a speedup, fairness or hostile-code containment claim.

The release also consolidates unpublished same-task owned parameters/results and
exact task-method witnesses from 0.1.65/0.1.66, plus 0.1.67's explicit runtime mailbox
custody used by the session writer. A session callback cannot continue after its
reserved writer closes. Function extraction now preserves task kind separately from
an empty effect row, including invocation through task-valued descriptors/callbacks.

Admission and recovery fixes accompany the language change. Artifact readers bind
compiled externals and overlapping owner inventories to the same canonical meaning.
Data writers enforce the counts accepted by readers before publication; typed data
codecs distinguish byte limits from collection counts. Retained installations complete
directory synchronization before activation or successful retry. Public extraction
plans retain empty-effect task kind, and malformed Unicode review tokens return a
diagnostic. Authored record initializers retain their original evaluation order while
record layout stays canonical.

Development guidance now treats campaigns as historical evidence, with current work
and unfinished acceptance in one status page. Changed checks select complete scoped
checks for documentation/site and checker-only edits. Fresh full acceptance remains
required for product changes; smaller context and check scope are not measured API
cost savings.

Graph 21 retains supported historical meaning readers. Rebuild predecessor derived
artifacts for compiler 19, bytecode 15 and artifact 26. Authored request 25, compact
discovery 29, function projection 11, CLI observations 35 and semantic validator 24
expose current contracts. Discover support through the executable's public
capabilities; product version components remain opaque identifiers.

Request generations 18–24 recover their original commitment identities. Review tokens
made with the erroneous newer-codec fallback require a fresh plan; their mistaken
commitment bytes are not retained as historical identities.

Installation does not change accepted application definitions, exact dependencies,
operational data or running services. No existing release bytes or tags are rewritten.
The [native guide](../guides/native-parallel.md) and
[normative contract](../spec/structured-parallel.md) define the available composition.
