# v0.1.88: operation-local callable transfer inputs

Recursive generic-type checking now retains one immutable input projection per
exact demanded incoming call. Distinct witness paths reuse those input bytes without
rereading the full expression or implementation mapping. They still retain independent
source scopes, exact selections, ordered paths and weighted type-flow edges.

Complete source discovery and callable-cycle selection remain mandatory. Sharing is
local to one checking operation; no source, revision or publication can inherit a
previous operation's admission. Undemanded calls remain lazy. Every retained operand
and type vector is reserved under the existing limits, cache hits retain cancellation
and work checks, and failed loading cannot expose a partial projection.

The [decision](../decisions/operation-local-callable-inputs.md) describes the boundary.
The regression fixture forces many distinct witness paths through one cross-package
mapping and independently counts source reads on both predecessor and successor.
Constructor growth at every witness position, exact work refusal, late cancellation,
subsequent healthy admission and final local-handle reclamation remain checked.
[Measurements](../performance.md#operation-local-callable-transfer-inputs) also retain
the single-use bookkeeping cost; this is not a claim of general faster compilation
or execution, reduced RSS or lower API cost.

No language syntax, semantic graph, source/package/artifact encoding, CLI observation,
shared-runtime observation or application data changes. No migration or new authority
is introduced. Product numbering remains opaque. Mainline/source acceptance does not
substitute for finalized-archive acceptance or immutable public release verification;
actual availability is [status-owned](../status.md).
