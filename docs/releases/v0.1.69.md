# v0.1.69: owned results from joined parallel tasks

Successor to published v0.1.68. Source acceptance,
mainline integration and publication are separate; [status](../status.md) owns
their exact current state.

An existing `parallel` expression can return closed owned buffers, scalar cells,
products and choices from its children. When either child returns an owner, the
joined result is an ordinary language `OwnedProduct` with `left` and `right`
fields. Existing complete `unpack-owned` exposes the results for further borrowing,
mutation and consumption in the parent. Two ordinary child results still produce
the existing structural record.

Child results cross a separately sealed custody boundary before child-local
cleanup. Both children join before the parent adopts their results, with exact
program, task, result type and invocation identities checked. Nested owned payload
allocations are retained. Failure, cancellation or refused result storage disposes
of every pending result without implicit retry or rollback. Invocation-wide quotas,
deadline causes and bounded caller fallback retain their existing meaning.

Direct children remain monomorphic graph tasks with empty effect rows. They can
use generic libraries and explicit implementation witnesses internally. Loans,
capabilities, secrets, dynamic callables and open types cannot cross the boundary.
This adds no channels, detached task handles, asynchronous borrowing, worker pool
or performance guarantee.

The independent symbolic memory oracle now resolves imported Owned generic
signatures in their defining package and substitutes actual types before checking
ownership flow. Separate exported/imported packages exercise this boundary rather
than merging supplier and consumer declarations into one package.

Literal edits through implementation and method calls retain the surrounding
body's binding identities. The editor traverses these calls under its existing
complete intent comparison instead of unnecessarily replacing the whole body.

Graph 21 and authored request 25 retain their representation. Semantic validator
25 updates current acceptance. Compiler unit 20, bytecode 16 and artifact 27 bind
the explicit parallel result type; predecessor derived artifacts must be rebuilt
from accepted meaning. Existing exact dependencies, application data and running
services are not migrated. All product-version components are opaque identifiers.

The native parallel result tests belong to the existing final-archive public
harness inventory. Development-host checks alone do not establish acceptance of
the final distributed executable.
