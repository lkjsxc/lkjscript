## Recoverable owned results

Fixed named `OwnedChoice` types represent an ordinary success value or a still-owned
rejected payload. `choose-owned` constructs exactly one case; `match-owned` consumes
the complete parent and binds its selected payload in a case-local scope. Every
case is checked, with no fallback, missing arm or shared binding identity. Payloads
may be concrete owned carriers, scoped Owned parameters, nested products/choices,
or closed ordinary first-order data; at least one case must carry owned data.
Ordinary Option/Result and nominal containers remain unrestricted and cannot hide
these owners.

The feature composes through canonical native authoring/editing, exact offline
packages, explicit static implementation witnesses, recursive synchronous forwarding
and whole-owner reborrowing. A closed choice may itself be an implementation Self.
The maintained public witness combines a generic outcome library, independent scalar
and byte-buffer implementation packages, and a source-free command consumer. A task
may use choices locally while its capability resources retain separate exact use
contracts. This does not add mixed memory/resource task signatures or asynchronous
ownership transfer.

The bootstrap carrier reuses sealed composite storage, carries one selected payload
and performs bounded iterative cleanup for mixed products/choices. Token clones do
not duplicate ownership. Cancellation and failed allocation admission release owned
payloads through ordinary cleanup, not through an implicit rejected-result case.
Independent effects are not rolled back, and a returned owner alone does not prove
that retry is safe.

Semantic ownership branch-state copies and joins now consume finite proof work,
including otherwise-unused live slots. Owned case analysis streams capability-flow
states instead of retaining one complete state per arm. Existing quotas are not
raised to accommodate this accounting. These changes do not claim universal
zero-copy execution, lower RSS or superior throughput.
