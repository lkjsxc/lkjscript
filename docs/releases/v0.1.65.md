# 0.1.65 development: same-task owned calls

This is a source-development identifier, not a published binary or a replacement
for the accepted 0.1.64 candidate. All three product-number components retain their
equally opaque identifier role. Exact contracts and executable discovery determine
availability; no component implies stability or compatibility.

Named graph task helpers can now consume and return owned memory within one
invocation. Buffers, cells, products, choices and first-order Owned parameters
compose with ordinary arguments and a final exact capability-resource suffix.
Task hosts may forward explicit implementation witnesses; concrete owned-contract
methods remain pure and monomorphic. Pure synchronous helpers still provide
read borrowing, but task memory parameters must consume, even when unused.

The change closes the same-call boundary needed before a future structured
in-process handoff. It creates no child tasks, channels, cross-invocation owner
rebinding, implicit grants, shared scheduler or rollback of completed effects.
Raw owner entry/results and ordinary data-codec escape remain rejected.

The [contract](../spec/owned-task-transfers.md) defines custody and failure behavior;
[verification](../spec/verification.md#same-invocation-task-owned-transfer) defines
independent source/runtime, exact-resource and source-free public obligations.
The [campaign](../campaigns/20261002-task-owned-transfer.md) records actual failed,
focused and full acceptance separately. Current source availability and public
binary delivery are distinguished in [status](../status.md).

Semantic validator 22 changes safe proof-reuse identity. Graph, owner/type, native
request, compiler instruction and artifact wire versions remain unchanged by this
increment. Historical content is not silently rewritten, but an older validator
or host is not claimed to execute this new meaning. No running service or
application data is migrated. Release selection and final-archive acceptance, when
this development is selected for publication, remain separate explicit operations.
