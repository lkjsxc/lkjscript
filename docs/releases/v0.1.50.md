# v0.1.50 — Cancellation-safe resident queue ownership

This successor retains the native editing and durable web starter described in
[v0.1.49](v0.1.49.md), and corrects shared resident queue lifetime handling.
[Current status](../status.md) owns actual availability: notes and a version change
alone are not source acceptance, a finalized candidate or public distribution.

## Cancel waiting work without leaving a phantom task

A resident invocation waiting for a worker now owns its captured resources and
queue accounting together. Dropping that future releases captures before reporting
the queue empty, releases its admission capacity, and wakes a waiting shutdown.
The cancelled operation does not run, consume an execution identity, or count as
an executed completion. Repeated cancellation does not accumulate phantom waiters.

The handoff to a running worker establishes active ownership before releasing
queued ownership. A shutdown observer must not see an idle gap between those states.
Existing running work still requires cooperative cancellation and joined cleanup;
cancellation and a missing HTTP response do not establish rollback of live effects.

A deterministic regression on the predecessor observed zero running operations
but one remaining queued task after both shutdown grace periods. A separate
notification witness detects an intentionally early queue-to-active handoff.
Tests also cover captured-resource destruction, worker closure, exhausted task
identities, waiting-shutdown notification, repeated cancellation, and a real
running worker beside an aborted asynchronous queued task.

These are shared runtime lifecycle corrections, not a new web-specific primitive.
The kernel counterexample does not by itself demonstrate every HTTP disconnect path
or data corruption. The predecessor runtime source was identical in v0.1.48 and
the frozen v0.1.49 candidate; published older assets are not rewritten.

## Compatibility and delivery

There is no graph, artifact, package, deployment, or application-data format change.
Existing programs, grants, configured limits, native UI libraries and stores keep
their meanings. Corrected cleanup requires running the new executable; merely
installing or selecting it does not modify an already running process.

The v0.1.49 candidate passed its then-maintained acceptance, but its promotion was
cancelled before publication after the additional regression reproduced a defect.
Its annotated tag, successful candidate evidence and cancelled promotion history
remain unchanged. This version is an additive successor, not a retagged candidate.
The [campaign](../campaigns/202609262000.md) records the precise source, failures,
verification scope, integration and delivery state.
