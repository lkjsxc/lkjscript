# v0.1.90: exact incremental units and direct immutable-list construction

Ordinary native component/port creation no longer puts a Port ID in the compiler
unit set. Impact follows before and candidate ownership independently and selects
only enclosing declarations and targets. New children have no before path, deleted
children retain their former path, and moved children affect both parents.

This fixes Issue #9 without weakening the compiler cache's corruption guard or
port type checking. The semantic and compiler sets share one owning-unit projection
rather than repeating it. Source regressions compare exact identities and complete
incremental manifests/artifacts with clean builds, including port addition,
implementation changes, moves, deletion and component removal. Cycle and work-bound
refusal remain explicit.

The public regression uses copied executables and ordinary reviewed native edits.
One/two-port components and Command targets must update their derived caches and
check as exact-current, rather than accept meaning and silently recover with a
clean build. Command results remain correct after source removal. A wrong port
contract must leave project contents unchanged and permit a subsequent valid edit.

A writerless FIFO at the derived compiler cache's CURRENT entry no longer blocks
before file-type admission. Ordinary checking can reach its existing clean-cache
recovery; valid semantic publication can report the exact corrupt-cache failure
without losing its accepted result. Idempotent retries retain the original receipt
and leave cache repair to a later check. Bounded copied-product tests also require
unchanged authority, deterministic rebuilt artifacts and a subsequent incremental
edit. This does not make ordinary filesystem I/O asynchronous or guarantee a hard
whole-operation deadline.

This selection also publishes the previously source-accepted direct bulk-List
builder. It constructs the final immutable tree without repeatedly copying
unpublished prefix paths. Each raw value moves into its final element handle;
existing immutable append, indexing, iteration and retained siblings are preserved.
Reservations precede modeled growth, and failure/cancellation releases pending and
attached ownership. No new public transient-mutation interface is introduced.

The maintained native fold library exports ordinary generic `fold-four<Item, State>`
and `fold-eight<Item, State>` through independent package composition. Scalar and
nested-history consumers check ordered complete results, retained earlier prefixes,
initial-state preservation, full input admission, callback failure and recovery,
both attached and after source removal. These are source libraries/examples, not
new compiler intrinsics or automatic replacements for the standard fold. Matched
measurements retain small-input costs and unfavorable samples; lower construction
counts do not imply a universal runtime or application speedup.

Final-candidate acceptance and its native-public workload advance together to
generation 6. The exact five fold and three incremental-compiler behavior witnesses
are mandatory, with all other present/future tests in their respective namespaces.
The incremental family also contains the new FIFO recovery and immutable-replay
regressions. The full detached Map matrix and existing source, target, pinned-userland,
installation, original-reader and joined-cleanup obligations remain. Missing,
substituted, ignored, failed, duplicated or unexecuted selected cases reject. Older
and mixed contract/workload generations do not establish these new obligations.

No graph, type, interface, bytecode, artifact or application-data encoding transition
is selected by these changes. Product identifiers are opaque rather than maturity
or compatibility promises. Existing immutable releases and operational data remain
unchanged; these notes alone do not establish a new publication or application update.

## Native owned FIFO composition

The selected standard also adds six pure generic FIFO operations implemented
in lkjscript itself over existing owned sequences: empty, length, push, pop,
front and discard. Both pop outcomes preserve the remaining owner for reuse.
Front returns a source-tied borrowed element; nested and forwarded loans retain
the queue's custody until the scope ends. No queue-specific host intrinsic,
bytecode, encoding transition, capability or scheduler is introduced.

Ten fixed graph tests advance the current standard total from 96 to 106.
The transported native trace is admitted before its separate concrete cell,
two-byte buffer and owned-packet implementations. Independent full-result
regressions cover all 781 short operation words in each representation, long
mixed-stack traces, empty reuse, signed scalar extremes, malformed input,
rejected loan violations and finite-fuel cleanup. Detached runs remove their
owned source projects and transports before repeating the same behavior.
The existing native-owned final-byte family selects these public regressions;
its exact source and workload must still undergo finalized-byte acceptance.

An element moves from the incoming stack to the outgoing stack at most once
before removal. This does not imply constant end-to-end execution work or
bounded refill latency, and spare sequence capacity can remain retained.
This is standard-library adoption, not production adoption of the bounded
native dependency planner. See the [native FIFO guide](../guides/native-owned-fifo.md)
and [consumer](../../examples/owned-fifo/README.md). Existing exact suppliers
and running applications are not upgraded implicitly.
