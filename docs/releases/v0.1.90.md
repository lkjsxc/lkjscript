# v0.1.90: generalized owned storage and exact incremental compilation

Ordinary native component/port creation no longer puts a Port ID in the compiler
unit set. Impact follows before and candidate ownership independently and selects
only enclosing declarations and targets. New children have no before path, deleted
children retain their former path, and moved children affect both parents.

This fixes Issue #9 without weakening the compiler cache's corruption guard or
port type checking. The semantic and compiler sets share one owning-unit projection
rather than repeating it. Source regressions compare exact identities and complete
incremental manifests/artifacts with clean builds, including port addition,
implementation changes, moves, deletion and component removal. Cycle and work-bound
refusal remain explicit.

The public regression uses copied executables and ordinary reviewed native edits.
One/two-port components and Command targets must update their derived caches and
check as exact-current, rather than accept meaning and silently recover with a
clean build. Command results remain correct after source removal. A wrong port
contract must leave project contents unchanged and permit a subsequent valid edit.

A writerless FIFO at the derived compiler cache's CURRENT entry no longer blocks
before file-type admission. Ordinary checking can reach its existing clean-cache
recovery; valid semantic publication can report the exact corrupt-cache failure
without losing its accepted result. Idempotent retries retain the original receipt
and leave cache repair to a later check. Bounded copied-product tests also require
unchanged authority, deterministic rebuilt artifacts and a subsequent incremental
edit. This does not make ordinary filesystem I/O asynchronous or guarantee a hard
whole-operation deadline.

This selection also includes the previously source-accepted direct bulk-List
builder. It constructs the final immutable tree without repeatedly copying
unpublished prefix paths. Each raw value moves into its final element handle;
existing immutable append, indexing, iteration and retained siblings are preserved.
Reservations precede modeled growth, and failure/cancellation releases pending and
attached ownership. No new public transient-mutation interface is introduced.

The maintained native fold library exports ordinary generic `fold-four<Item, State>`
and `fold-eight<Item, State>` through independent package composition. Scalar and
nested-history consumers check ordered complete results, retained earlier prefixes,
initial-state preservation, full input admission, callback failure and recovery,
both attached and after source removal. These are source libraries/examples, not
new compiler intrinsics or automatic replacements for the standard fold. Matched
measurements retain small-input costs and unfavorable samples; lower construction
counts do not imply a universal runtime or application speedup.

Final-candidate acceptance and its native-public workload advance together to
generation 7. The exact five fold and three incremental-compiler behavior witnesses
are mandatory, with all other present/future tests in their respective namespaces.
The incremental family also contains the new FIFO recovery and immutable-replay
regressions. The five maintained owned-FIFO cases and five generalized-sequence cases
are now mandatory under their exact namespaces; disappearance of an entire family
also rejects. The full detached Map matrix and existing source, target, pinned-userland,
installation, original-reader and joined-cleanup obligations remain. Missing,
substituted, ignored, failed, duplicated or unexecuted selected cases reject. Older
and mixed contract/workload generations do not establish these new obligations.

This selection intentionally cuts graph/owner encoding to 31, package interfaces
to 19, compiler units to 31, bytecode to 26, artifacts to 38, authored requests to
35 and compact responses to 39. The owned-sequence type envelope remains 1;
complete graph admission independently gates the newly ordinary element closure.
Maintained artifacts, transports and discovery are regenerated through their
product owners. Predecessor derived formats reject; supported previous source
remains input to ordinary reauthoring. No experimental-format migration layer or
application-data migration is introduced. Product identifiers are opaque rather
than maturity or compatibility promises. Existing immutable releases and
operational data remain unchanged; these notes alone establish neither acceptance
of a finalized archive nor a new publication or application update.

## Native owned FIFO composition

The selected standard also adds six pure generic FIFO operations implemented
in lkjscript itself over existing owned sequences: empty, length, push, pop,
front and discard. Both pop outcomes preserve the remaining owner for reuse.
Front returns a source-tied borrowed element; nested and forwarded loans retain
the queue's custody until the scope ends. The FIFO implementation adds no
queue-specific host intrinsic, bytecode, capability or scheduler.

The FIFO request adds ten fixed graph tests.
The transported native trace is admitted before its separate concrete cell,
two-byte buffer and owned-packet implementations. Independent full-result
regressions cover all 781 short operation words in each representation, long
mixed-stack traces, empty reuse, signed scalar extremes, malformed input,
rejected loan violations and finite-fuel cleanup. Detached runs remove their
owned source projects and transports before repeating the same behavior.
Generation 7 requires every exact maintained FIFO behavior identity and selects
all other cases in `native_declarations::native_owned_fifo::`. Its exact source
and workload must still undergo finalized-byte acceptance.

An element moves from the incoming stack to the outgoing stack at most once
before removal. This does not imply constant end-to-end execution work or
bounded refill latency, and spare sequence capacity can remain retained.
See the [native FIFO guide](../guides/native-owned-fifo.md)
and [consumer](../../examples/owned-fifo/README.md). Existing exact suppliers
and running applications are not upgraded implicitly.

## Ordinary data in owned sequence storage

`(owned-sequence T)` now admits ordinary first-order data as well as owned
elements. Container storage stays affine even when empty or containing only I64
or Bool values. Complete element admission rejects hidden resources, secrets,
callables and unsafe phantom substitutions before creating an empty owner.
Transfer and sharing require independent complete proofs; ownership grants neither.

`sequence-get` reads an ordinary element by index and returns its immutable value
without a source loan. Retained results survive replacement, removal, destruction
or task transfer of the sequence; nested immutable backing may remain shared.
`sequence-replace` evaluates index, replacement value and source in that order,
checks bounds and reserves its result before swapping, then returns an owned
product containing the sequence and displaced value. Owned replacements consume
exact owning locals. Negative and out-of-range indices trap, and failure or
cancellation joins cleanup without exposing a successful partial result.

The standard adds seven `data-sequence-*` wrappers using `T: Transferable`, plus
owned `sequence-replace<T: Owned>`. Ten additional fixed graph tests cover
ordinary scalars and aggregates, stable retained reads, empty reuse, displacement
and owned payload custody. Copied-product regressions export a generic library
before its consumers, compare a finite independent model, reject invalid types
and active-loan mutation, and repeat complete results after source removal.
Generation 7 requires their five exact behavior identities and all present/future
tests in `native_declarations::native_data_sequences::`.

Generic structural types reuse exact substitutions already proved during bounded
preparation. The immutable lookup retains full binding contexts and the prepared
program identity; each runtime hit still checks the current type shape and
cancellation. This removes repeated whole-type-table searches from generic owned
operations without a growing runtime cache or a weaker admission boundary.

The maintained native dependency planner adopts I64 sequences for remaining
counts and levels, Bool sequences for visited flags, and an append-only readiness
sequence with a scalar head. Each component is queued at most once, and the final
sparse output map is materialized after traversal. Existing complete results,
refusal behavior, graph capacities and the independent checker remain required.
This advances maintained native tooling; the production compiler integration is
a separate boundary. Mutable storage alone establishes no speed, retained-memory
or API-cost improvement. See the [data-sequence guide](../guides/native-data-sequences.md)
and [planner](../../examples/dependency-plan/README.md).
