# v0.1.77 — Parameterized owned contracts

Owned contracts can declare ordered owned type parameters in addition to Self.
Explicit implementation witnesses bind every argument, and method signatures may
compose those parameters in owned products, choices and sequences. A collection
contract can consume an element and collection together, or return both from a
typed removal result. Generic libraries validate before concrete implementations
exist and retain exact witness identity across package boundaries.

The native worklist example implements one interface using flat sequences and
32-element chunks, with independent cell and byte-buffer elements. Generic
algorithms build, transfer, drain and reuse these owners through contract methods.
A native provisional dependency-graph tool validates complete input and computes
reachability using either representation, returning independently specified typed
results. It is a tooling witness; it does not replace the production compiler.

Contract applications retain scope, ordered arguments, use modes and exact effects
through authoring, inspection, transport, compilation and execution. Structural
substitution has bounded work and independent admission. An implementation witness
confers neither a capability grant nor transfer authority. Existing lexical loans,
affine cleanup and task boundaries apply to every substituted owned type.

Graph 26, package interface 14 and authored codec 30 carry the extended contracts.
Compiler 26, bytecode 21, artifact 33 and the current semantic validator require
rebuilding derived bundles. No migration layer or operational application-data
change accompanies this experimental format cut. Unreachable predecessor compiler
unit encoders are removed from production; historical adversarial evidence remains
available to independent tests.

The native_owned_worklist_ public cases participate in the mandatory finalized-byte
release harness. See [status](../status.md) for exact accepted source, validation
receipts and publication availability. These notes do not certify a pending build.
