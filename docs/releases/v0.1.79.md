# v0.1.79 — Explicit generic owned implementations

Owned implementations can declare ordered type parameters and map their methods
to explicitly applied generic functions. One storage implementation can serve
independently authored owned element types. Each witness retains its exact
implementation declaration and every type argument, including phantom arguments.

The native three-package example exports flat and chunk32 Worklist and IndexRead
schemes before creating cells, buffers and a nested owned product downstream.
Consumers select source-tied borrowed results, drain and reuse the original
owners, transfer elements between representations, and run joined generic tasks.
No element-specific storage adapter or implicit implementation search is needed.

Admission follows complete callable and witness applications across package
boundaries. A supplied implementation can call back into a consumer, so a package
dependency DAG alone is insufficient. Parameter-flow analysis rejects structurally
expanding application cycles while retaining ordinary recursion, permutations and
closed resets. Bounded analysis exhaustion remains a separate resource failure.

Signature admission preserves exact types, ownership modes, callable kind, closed
effects and borrowed-result provenance through simultaneous substitutions. The
independent evaluator and artifact loader check the complete application, including
unused mappings and untaken syntax. Runtime specialization binds both callable
and witness arguments without introducing a new ownership mechanism.

This release selects graph/owner 28, package interface 16, compiler unit 28,
bytecode 23 and artifact 35. Experimental derived bundles require rebuilding;
no migration layer is provided. Maintained accepted graph identities and original
historical fixtures remain preserved. Schemes with implementation prerequisites,
associated types, method-local generics and implicit resolution remain future work.
