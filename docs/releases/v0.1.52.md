# v0.1.52 — Typed form selection and coherent recovery reads

This successor combines ordinary native form-library improvements with a correction
to repository catalog recovery. Source availability, candidate acceptance and public
publication are distinct; consult [current status](https://github.com/lkjsxc/lkjscript/blob/main/docs/status.md) and the
[verification and delivery record](https://github.com/lkjsxc/lkjscript/blob/main/docs/campaigns/202609280350.md).

## Select one form field without hiding ambiguity

The ordinary `forms` library provides `lookup(fields, name)` with three typed results:
`missing`, `present(Text)` and `repeated`. Empty text is a present value. Names match
exactly after decoding, without normalization or a second decoding pass. Even two
identical values remain repeated rather than silently choosing a winner.

The authenticated native editor and newly created `web-editor` starters use this
operation directly. Form values no longer need an intermediate HTTP-header/byte
representation. The editor still requires exactly its three expected fields and
retains authentication, Host/Origin checks, input bounds, conflict handling and
transaction completion. Duplicate aliases, unexpected names and malformed forms
remain rejected.

This is ordinary lkjscript code, not a new intrinsic or parser convention. An existing
compatible executable can explicitly author and consume the updated library.
Installing a newer executable does not silently update previously accepted exact
suppliers, existing application definitions or operational data.

## Preserve one repository observation after recovery

Healthy catalog reads retain their shared publication lock and permit concurrent
readers. When a failed observation requires an exclusive recheck or reconstruction,
keep that exclusive ownership through the caller's catalog/HEAD observation.

The former exclusive-to-shared lock conversion was not guaranteed atomic. Another
writer could publish between the captured catalog and the later HEAD read, causing
a valid newer HEAD to be checked against an older catalog. Removing that conversion
closes this observation gap without weakening object validation or repeating recovery
without a finite bound. Other readers can wait on this exceptional path;
normal shared-read behavior is unchanged.

## Compatibility and boundaries

Graph, package, artifact and operational-data encodings are unchanged. This release
does not introduce `inspect history`, rollback, automatic upgrades, a network package
registry, a new persistence format or a browser/Wasm backend.

Focused tests distinguish a deterministically modeled legal lock handoff from an
observed production race frequency. They check healthy reader sharing, recovery
exclusion, coherent old/new observations and release after errors. The complete
[form evidence](https://github.com/lkjsxc/lkjscript/blob/main/docs/campaigns/202609280200.md) and
[recovery evidence](https://github.com/lkjsxc/lkjscript/blob/main/docs/campaigns/202609280350.md) retain failures as well as passes.
