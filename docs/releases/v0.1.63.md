# 0.1.63 — owned-product metadata reads

This identifier is opaque. Its components do not encode stability, compatibility
or change size. These notes describe source development, not a published binary.

## Useful change

Ordinary policy helpers can inspect closed metadata in a structural owned product
without consuming or reconstructing it:

```text
(field (local packet) (name tag))
```

The source is an exact live local, owned or borrowed. The operation briefly
borrows the whole product and returns an ordinary immutable value. Generic
helpers and cross-package reborrows preserve the parent's ownership, so the
caller can subsequently move or completely unpack it. The result can outlive
the parent under ordinary-value rules.

An owned payload is not a readable ordinary field. Missing fields, consumed
locals, non-local owned temporaries, partial moves, escaping references and
mutable borrows are not admitted. This does not implement owned choice/result
containers or asynchronous ownership transfer.

## Compatibility and implementation

Accepted graph and native request layouts do not change. Semantic validator 20
and owned-product feature revision 2 admit the new operation context.
Compiler unit 17, bytecode 13 and artifact 24 replace prior derived execution
contracts. Rebuild old artifacts from their accepted source. Existing public
releases and application data are not rewritten or automatically upgraded.

The VM and reference evaluator independently resolve and admit the selected
ordinary field. Storage admission precedes any inline sum/option spine copy.
This is not a general allocation-free or whole-program zero-copy claim.
