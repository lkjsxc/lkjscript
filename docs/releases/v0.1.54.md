# v0.1.54 — Scoped resource borrowing

Development notes. Availability and source-specific evidence belong to the
[borrowing campaign](../campaigns/202609281548.md). These notes do not establish
candidate acceptance or public publication.

## Added

A private, same-package, nongeneric task may take one final direct capability
resource parameter with `use=borrow` and an exact requirement binding. It may
observe the resource through permitted non-consuming operations or reborrow it
into another admitted helper. The caller retains ownership after normal return
and may then borrow again or consume its original resource.

The ordinary native declaration workflow authors these signatures. Canonical
inspection, package transport, artifact admission, bytecode execution and the
independent reference interpreter preserve the exact use mode and authority.
Borrowed views cannot be consumed, forwarded to a consuming helper, returned,
captured, placed in a container, or wrapped as an owned variant.

The maintained lkjournal worker now calls an ordinary private `lease-payload`
borrowing helper before its existing owning helper performs heartbeat and
completion/failure operations. Its types, dependency selections, deployment
grants and operational-data formats remain unchanged.

## Runtime and verification

A borrow attenuates the opaque handle without allocating another resource slot.
Consuming local loads and adapters independently reject non-owning handles.
Normal return, tail calls, nested reborrows, prefix failure, cancellation and
capability-call exhaustion retain the existing task cleanup boundary. Cleanup
does not replay an effect or implicitly complete an external queue job.

Borrow means non-consuming capability access, not purity or general read-only
memory. Reading the payload can still copy ordinary data; no zero-copy, RSS,
throughput or general lifetime-system claim is made.

## Compatibility and limits

No graph, package, artifact or operational-data encoding is added. The affine
validator feature advances so old validation evidence is not reused for the
new semantics. Re-plan unchanged requests after a runtime upgrade; do not reuse
incompatible review tokens. Older runtimes do not acquire borrowing support and
cannot be assumed to admit applications using the new signatures.

Direct calls remain acyclic, private and same-package. General resource results,
generic resource parameters, asynchronous borrowing, cross-package or
cross-instance owned transfer, region allocation and resource-capturing closures
remain outside this increment. Automatic function extraction retains its existing
consume-only resource boundary.

See the [language contract](../spec/language.md#affine-capability-resources) and
[authoring contract](../spec/semantic-cli.md) for the exact boundary.
