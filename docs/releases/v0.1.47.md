# Editable native web starter

## Start from one executable

`lkjscript new my-app --template web` creates an ordinary native browser
application, its editable UI modules, shared tests and a loopback deployment.
Application setup no longer requires downloading the UI source or manually
staging and binding its package identities. Continue with `check`, `build`
and `serve`; the ready event reports the actual local address.

The page has a labeled name field and light/dark submit buttons. The application
composes typed UI values in lkjscript. The ordinary UI library owns the fixed
HTML/CSS renderer; no application JavaScript is emitted or executed. Hosting
requires no Node.js, compiler checkout, Cargo or external database.

UI code is vendored as local editable declarations at creation, not a new kernel
intrinsic or a silently updated built-in supplier. Separate exact package imports
remain available. Installing a different runtime does not rewrite an existing
application or upgrade its local UI.

## Native editing and atomic creation

The starter reuses the existing public native declaration decoder, typed change
preparation, complete validation and publication machinery. Intermediate recipe
revisions remain in a private owned stage; one complete initial project becomes
visible at the destination. Malformed syntax, wrong types and conflicting
declarations reject instead of exposing partial application meaning.

Public `change draft`, `change plan` and `change apply` support edits to the
application and local UI. The tested title edit retains its declaration identity.
Wrong-typed proposals do not advance the accepted head. The original source
proposal is not a synchronized second authority: the accepted graph remains
authoritative.

## Tested behavior and boundaries

Focused source verification exercises 107 graph tests: 19 shared UI tests,
13 application tests and 75 built-in standard tests. A copied-binary workload
checks native editing, rejected changes, query behavior, text escaping and
standalone HTTP use after removing the authoring project. Real Chromium operation
with page JavaScript disabled covers Unicode input, markup-shaped text, keyboard
submission, theme selection, refresh and a 360px layout without horizontal overflow.

The starter is stateless. GET form values appear in URLs; do not enter secrets.
There is no implied authentication, account system, POST mutation or persistent
save. The separate durable-editor example demonstrates explicit authentication,
Origin admission and conditional transactions.

The generated deployment listens on loopback and grants only request-stream
access. It does not grant arbitrary filesystem, outbound network, secret or
application-data access. Plaintext loopback and resource limits are not a public
multi-tenant security boundary. The Rust runtime remains supported; this is not
a self-hosted compiler or browser/Wasm backend.

## Compatibility and distribution

The new template is additive. Existing templates, exact dependency selections,
stored application data and running deployments are not rewritten. Older
executables lacking `web` reject that template name; use `capabilities new` to
discover the selected executable's actual support.

Distribution remains static x86_64 Linux musl. Standalone bundles require a
compatible lkjscript executable and their descriptor layout, not the authoring
graph. Source acceptance, finalized candidate acceptance, immutable publication
and anonymous installed verification are separate delivery claims. Their actual
state is recorded in `docs/release.md` and `docs/campaigns/202609251450.md`.
