# v0.1.73: owned generic applications with explicit authority

Generic graph tasks compose Owned parameters and exact implementation witnesses
with caller-supplied effect and requirement arguments. A reusable library can
consume an owner, invoke a callback under its declared effect row, use a supplied
capability requirement and return the owner. Generic relays preserve every operand
through exact package transport and standalone artifacts.

Implementation selection, ownership, effect allowances and deployment grants
remain independent. The same witness-specialized template can serve different
applications without sharing invocation authority. Methods remain closed and
monomorphic; this change does not introduce effectful parallel children, escaping
borrows or owned callable captures.

The canonical reference evaluator also counts ancestor frames when admitting
non-tail witness calls inside nested parallel children, matching the production
call-depth limit and preserving joined cleanup on refusal.

The maintained three-package owned-effects example uses both OwnedI64Cell and
ByteBuffer and returns independently expected complete results. Its clock calls
exercise distinct authority bindings without making results depend on wall time.
Public authoring, reviewed edits, canonical drafting, package composition and
source-free execution remain the ordinary development path.

Graph 23 preserves supported predecessor meaning. Validator 28, authored request
27, compact change 31 and function-definition projection 13 own the new application
contract. Compiler 23, bytecode 18 and artifact 30 require rebuilding derived bundles
and caches. Package interface 13 and type-object 10 retain their layouts. Existing
application data and running services are not migrated or replaced by installation.

Product version components remain opaque identifiers. See the
[semantic contract](../spec/owned-effects.md) and [current status](../status.md)
for the exact implementation, acceptance and publication boundary.
