# v0.1.86 — Demand-driven idle worker custody

Independently owned structured executors in one process can reuse an idle worker
from another open executor without shutting that executor down or starting a new
thread. The worker's mailbox, join handle and unreleased physical reservation move
together. An owner's own idle worker remains the first choice.

Active work and unreceived results never move. No available capacity still means
first execution on the caller, including nested groups. Submission refusal retains
one intact job; a missing receipt or disconnected worker keeps its current cleanup
owner. Cancellation, exact program selection, payload custody, grants and quotas
remain per invocation, not properties inherited from the previous worker owner.
A host-side failure while destroying an unreturned result no longer strands an
active receipt: its owner joins the retained worker and reports cleanup failure
instead of waiting forever or claiming successful shutdown.

Dispatch closure serializes with handoff. Each owner drains its own accepted work
and joins the workers it still owns; stopping a former owner neither cancels nor
waits for a handed-off worker executing another owner's job. The physical auxiliary
ceiling is unchanged. Idle bookkeeping contains bounded weak references rather than
a permanent owner or program cache.

Shared-runtime observation 3 and CLI observation 43 add `workers_received` and
`workers_handed_off`. Physical starts retain their existing meaning; started plus
received balances joined plus handed off plus remaining, before counter saturation.
A successful shutdown has no active dispatches or remaining owned workers.

This changes scheduling and its observations, not the meaning graph, package
interfaces, bytecode, artifact encoding or application data. It introduces no public
channel, active-task migration, cross-process sharing, CPU fairness guarantee or
bound on resident-root CPU work. Public capability and publication are distinct;
[status](../status.md) records actual source and finalized-byte acceptance.
