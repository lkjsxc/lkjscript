# v0.1.56 — Recursive exact-resource helpers

Private same-package task helpers can use direct or mutual synchronous recursion
with one final exact `borrow` or `consume` resource parameter. Ordinary type
parameters, data callbacks and results continue to compose with that contract.

Each task body is checked independently under its declared use modes. Recursive
edges apply the same checked call boundary as nonrecursive calls. Borrowing keeps
the caller's owner; consuming moves it and does not restore it on failure.
Strict prepared calls still require the exact package, argument count and final
local use. Resource-bearing function values remain forbidden.

The native example includes a 4,097-step tail countdown, mutual borrowing with
caller reuse after return, and recursive consuming helpers with ordinary results.
Detached execution observes durable completion separately from the returned value.
Decoder failure preserves an already committed lease without inventing completion
or retry; another ready job remains executable.

Recursion admission is not a termination proof or a general lifetime system.
Existing execution work, cancellation, live-depth and resource limits remain.
Resource returns, indirect or cross-package transfer, effect/requirement-polymorphic
resource signatures, asynchronous borrows and affine containers are not added.
Automatic function extraction retains its narrower eligibility. No memory-copy
or performance improvement is claimed.

Affine validator feature 5 separates the new acceptance contract from earlier
evidence. See the [guide](../guides/native-resources.md), [campaign](../campaigns/202609282124.md)
and [current availability](../status.md) for examples, verification and delivery.
