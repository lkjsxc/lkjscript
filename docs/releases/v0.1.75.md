# v0.1.75: scoped reads of owned children

Generic readers can inspect owned fields and choice payloads without consuming
their container. The accepted graph records each view's exact source, child type,
binding and lexical extent. The original owner remains available after the scope
ends. Native authoring, canonical drafts, explicit implementation witnesses,
package transport and detached artifacts carry the same checked contract.

`borrow-owned-field` selects one direct owned product field, including a symbolic
`T: Owned`. `match-borrowed-owned` exhaustively inspects a choice: owned payloads
become read views, while ordinary payloads follow the existing admitted copy rules.
Views can be inspected recursively and passed to pure borrowed helpers or exact
borrowed methods. They cannot be consumed, returned, captured, stored, packed or
transferred to another task. Bodies may perform independently authorized effects
and return unrelated owned values.

Whole-source read loans retain ancestor custody until scope exit. Both evaluators
release child views before parent guards on success and failure, and retain
lexical cleanup across terminal calls even when a helper has only borrowed inputs.
Composite storage locks are released before executing a scope body. No mutable
borrowing, escaping references, borrowed task parameters or new execution grant
is introduced. Function extraction containing a new scope rejects before publication.

The [three-package example](../../examples/owned-borrows/README.md) uses a generic
reader, distinct scalar and buffer implementations, nested products and mixed
choices. Its public workflows retain exact drafts, reviewed edits, independently
expected complete outputs and source-free execution. See the
[native guide](../guides/native-owned-borrows.md), [semantic contract](../spec/owned-borrows.md)
and [verification obligations](../spec/verification.md#scoped-owned-child-read-obligations).

## Compatibility

Graph 24 adds the two expression forms and their explicit borrowed binding role.
Authored codec 28 and compact change contract 32 carry the new native intent.
Owner summary 10 and semantic validator 29 invalidate prior derived proofs;
unchanged witness envelopes and authentic predecessor graph records retain their
existing historical readers. Compiler unit 24, bytecode 19 and artifact 31 require
rebuilding prior derived bundles from admitted meaning. Registry 20 and CLI
observation 38 and function-definition projection 14 advertise and inspect the
new operations. Function signatures and package interface layouts are unchanged.

Installation does not rewrite application data or rebuild existing deployments.
Source acceptance and public availability are recorded in [status](../status.md).

work. Original tested examples and release evidence retain their exact identities.
