# v0.1.85 — Shared exact dependency interface records

Source admission now materializes each needed exact dependency interface record
map once and shares it across importing snapshots. Snapshot clones also retain
those immutable maps instead of copying their variable-sized records. The pool
is local to one admission and holds no application state, authority or successful
validation decisions.

Every load still independently admits interfaces and canonical source, checks
private bodies, compares interfaces with their bodies, verifies direct visibility
and reconstructs the composed callable closure. Equal display names or contract
shapes do not merge package revisions. Corrupt inputs do not become acceptable
because a previous load succeeded. The independent source oracle retains its own
record reconstruction.

Record materialization, incoming bindings and map bookkeeping remain bounded by
the existing aggregate admission policy. Exact-fit and one-below checks retain
resource refusal. Flattened type maps are still private and still incur their
own per-snapshot copy costs; tiny interfaces can incur extra bookkeeping.

The maintained [four-package diamond](../guides/native-shared-dependencies.md)
combines the recursive generic supplier, two distinct same-Self readers and one
borrowed cell. It preserves exact results, canonical re-entry and detached use
after deleting the authoring projects and transports. The required public harness
includes the new case against finalized candidate bytes.

This successor also includes v0.1.84's whole immutable prepared-witness sharing.
No semantic graph, interface, type-object, bytecode or artifact encoding changes,
application data migration or production deployment. Product components remain
opaque identifiers. [Status](../status.md) owns actual acceptance and availability.
