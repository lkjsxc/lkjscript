# v0.1.76 — Dynamic owned sequences

OwnedSequence<T> holds a runtime-sized collection of owned values. Empty sequences
remain affine. Native sequence-empty, sequence-length, sequence-push and
sequence-pop expressions compose with lexical borrow-owned-item inspection.
Pop returns the sequence in both its empty and item outcomes, retaining reusable
capacity; the item outcome also transfers the last element.

Generic native libraries construct, inspect and drain collections through exact
element implementation witnesses. Independent ByteBuffer and OwnedI64Cell carriers
exercise the same algorithms, including alternative implementations for one Self
type. Existing structured parallel transfer admits sequences when their complete
element type is transferable. No borrowed task parameter or escaping view is added.

Products, choices and sequences share sealed composite custody. Growth and result
envelopes reserve storage before mutation; indexed reads retain ancestor loans and
release internal locks before user evaluation. Failure cleanup releases every owned
child without replaying effects or claiming rollback. Finite type depth still
bounds allocation-free destruction while sequence length varies at runtime.

function-definition projection 15 advertise the new meaning and authoring surface.
Compiler 25, bytecode 20, artifact 32 and semantic validator 30 require rebuilding
prior derived bundles. Owned sequence types use the disjoint LKJSEQ01 envelope.
There is no operational application-data migration or running-service replacement.
