# Runtime demands at large-program scale

Chromium is a yardstick, not a port or a source dependency. The rows are lkjscript decisions, not claims that its current runtime matches Chromium.
Baseline: checked source at `6632d1ca`; compiler-owned image admission is available, affine child transfer is not yet a language operation.

| Order / demand | What holds today | Honest form here | Smallest retained specimen |
| --- | --- | --- | --- |
| 1. Privilege-separated processes and parallel work | Needs capability/IR: authenticated ELF and slot ABI exist; `Process` is broad host authority | Affine admitted image, explicit moved slots, attached lifetime, deadline and exit/trap values; no implicit grants | Listener/root parent and unprivileged parsers; four-worker ordered pure map; death/restart/kill campaign |
| 1. Typed messages and descriptor transfer | Needs capability/IR and compiler type identity; bytes are expressible | Checked message identity plus generated codec; affine capabilities move with a message; byte framing must state its remaining mismatch gap | Sender/receiver type mismatch, stale identity, malformed frame, reuse-after-move refusals |
| 1. Shared payloads | Needs capability/IR; current views belong to one address space | Seal immutable region before sharing; typed readonly views; never share writable mappings or allocator state | One MiB round trip by copy versus frozen mapping, write-after-publish refusal |
| 1. Threads, synchronization, scheduling | Needs IR: no checked cross-thread type or memory model exists | Processes-only parallelism now; serialized actor owners, bounded channels and readiness/timers. One-address-space threads require separately proved transfer/share predicates and allocator/stack rules | Ordered pool, contended map owner, bounded producer/consumer shutdown; seeded protocol schedules, not a claimed thread race detector |
| 2. Code arriving after start | Needs capability; authenticated build-time image admission exists | An admitting image carries checker/backend, admits IR under an explicit authority ceiling and returns a sealed callable child; traps terminate that invocation | Runtime-supplied pure IR succeeds; authority growth/mutants refuse; located trap survives at host |
| 3. Long-lived foreign libraries/drivers/codecs | In-image FFI contradicts current boundary; confined one-shot foreign child exists | Attached confined foreign worker with explicit roots/device handles and shared payloads; per-request deadline; library restart policy | `git cat-file --batch` worker versus per-request spawn, death/deadline/restart |
| 4. Mutable graphs and nonlexical lifetimes | Expressible as owners/indices; library on existing IR | One owner arena, typed generational handles, lexical lookup borrows; actor owns mutation; stale references are values | Million-node parent/child/sibling/observer graph, random subtree edits and stale-generation checks |
| 5. Runtime dispatch over open type sets | Closed enum dispatch expressible; open in-image callables need IR | Closed enums within an image; independently admitted image/interface identities for open plugins; no fabricated vtable pointers | Two independently built implementations behind one checked request contract |
| 6. Many idle I/O tasks and timers | Existing capabilities and library | Readiness and deadline queue, bounded dispatch, fixed absolute deadlines; no thread per idle peer | Existing HTTP/SSE idle-peer and slow-reader suites |
| 7. Window, input, graphics and sound | Needs capabilities/backend/target work | Explicit device/protocol service handles, typed command streams; foreign driver remains outside checked image | Window/input event loop, submitted frame and audio buffer with scoped device grants |
| 8. Text and cryptography | UTF-8/text, SHA-256/HMAC and entropy expressible; Unicode layout/TLS still missing | Ordinary audited libraries plus explicit entropy/trust-root effects; do not invent assurance for missing algorithms | Unicode traversal/normalization corpus; authenticated stream with certificate refusal |
| 8. Allocation controlled by program | Existing owned containers, fallible kernel growth and located exhaustion; custom allocator control missing | Ownership-preserving arena/pool libraries first; explicit allocation-domain capability only on measured need | Arena reuse/fragmentation and one maintained heap-refusal case |
| 9. Failure isolation and evidence | Located traps, private result channel and durable journal exist | Child fault becomes parent value; bounded library supervision; publish only committed results; no in-image trap recovery claim | Kill every publication phase, retain acknowledged prefix and located worker failure |
| 10. More than one target | Needs backend/runtime: Linux x86-64 only | Target-independent checked contracts with target-specific sealed capability implementations and refusal when unavailable | Same checked cases on a second real target, including failure and authority parity |

The order makes process isolation the prerequisite for both parallelism and failure containment; graphs are independent library work. It does not silently declare same-address-space parallel compilation solved.
A process pool costs separate heaps, IPC and checked unit serialization; compiler adoption is offered through a pending case, never asserted from a toy map benchmark.
The old prose about three pending scoped-concurrency cases is stale: only `borrowed_closure_escape` remains in conformance. No absent test is counted as proof.

Architecture sources (documentation only; no Chromium source checkout): [process separation and failure](https://www.chromium.org/developers/design-documents/multi-process-architecture/), [Mojo messages, platform handles and shared buffers](https://chromium.googlesource.com/chromium/src/mojo/+/refs/heads/main/core/), [threads, sequences and task pools](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/threading_and_tasks.md).
