## Matched complete-command cost and decision

The retained predecessor and new optimized verifier inspect the same repository.
After one warm-up per executable, seven fresh-process pairs alternate execution
order. Filesystem caches are not flushed. Each invocation returns the same clean
policy report and exit status. These are complete command wall times, not a kernel
microbenchmark, peak-memory measurement or universal capacity guarantee.

| Observation | Predecessor Rust decisions | Native decisions |
| --- | ---: | ---: |
| Median wall time | 7.286852 ms | 190.284160 ms |
| Minimum / maximum | 6.396748 / 10.243332 ms | 179.411916 / 215.324756 ms |
| Contributor executable bytes | 36,032,712 | 36,803,136 |

The migration is **slower**, by 182.997308 ms at the measured medians (26.11 times
the small predecessor latency), and adds 770,424 executable bytes. The ordinary
750,750-byte bundle carries the complete exact standard closure. Accept this cost
for one required development gate and the shared embedding boundary; do not claim
a speedup or mechanically repeat the migration for every small predicate. Policy
work is not added to normal application execution. Rust still owns observation and
orchestration, and this change does not reduce total Rust source line count.
