## Selected semantic increment

Allow an ordinary type-generic private task helper to borrow or consume one final,
direct capability-resource argument bound to the same exact concrete requirement.
Use T in actual ordinary arguments/results and nested generic calls; an unused
phantom parameter alone is not evidence. Keep effect/requirement-polymorphic
resource signatures, cross-package authority transfer, resource-valued results,
escaping borrows, resource-capturing callables and asynchronous borrowing outside
this increment. Existing ordinary generic and affine admission duties remain.

This removes an unnecessary composition boundary without inventing a new heap,
collector, resource format or type language. It is not general Rust-style lifetime
support, region transfer, zero-copy payload processing or measured throughput.
A literal public native consumer and independent resource/failure oracles must
establish the supported boundary before mainline acceptance.
