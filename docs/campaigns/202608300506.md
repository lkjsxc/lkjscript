## 3. Load-bearing current state

The typed semantic graph is the sole editable program authority. `GraphRepository` owns accepted
publication; an exact `RepositoryView` pins reads to one repository, package, and accepted revision.
Canonical owner records plus namespace and forward/reverse relation witnesses own current query
facts. Output, continuations, generated guides, indexes, caches, and measurements are derived or
evidentiary.

Current query contract `lkjscript-query-3` exposes only:

```text
query owners [--kind KIND] [--limit N] [--bytes N] [--continuation TOKEN]
query find CLASS NAME [--parent OWNER]
query relations OWNER|package --direction incoming|outgoing
  [--kind KIND] [--limit N] [--bytes N] [--continuation TOKEN]
```

These operations already provide compact deterministic records, revision/selector-bound `qcont_`
tokens, bounded physical-work accounting, canonical witness validation, zero-write behavior, and
complete-page equality with a full canonical oracle. A retained 10,000-owner/9,999-relation fixture
shows logical locality for one-hop reads. The gap is that an agent must coordinate repeated one-hop
queries itself to obtain a finite neighborhood; status and roadmap explicitly leave bounded context
traversal absent.

The removed predecessor `query context` used repeated seeds, scalar work/fanout/depth budgets, JSON
request forms, `--continue`, and a disposable `SemanticQueryIndex`, and returned only first-discovery
owner summaries. Do not revive or adapt it. The new operation may reuse the word `context` only; it
must use current typed identities, compact protocol, exact revision views, canonical witnesses,
separate resource dimensions, and current continuation integrity. Predecessor requests and token
bytes reject.

`applications/lkjournal` is the maintained nontrivial topology: its checked-in authority has 1,313
root owners and a stable `service` module discoverable by exact public query. The built-in standard
package is another maintained topology. A copied candidate can therefore prove useful traversal
without deployment, database, network, source text, or a contributor-only product path.

## 5. Success conditions

- **CTX-1 — Canonical public contract.** Discovery exposes exactly one new grammar:
  `query context OWNER --direction incoming|outgoing|both --depth N [--limit N] [--bytes N]

  generated documentation, and no alias, JSON form, repeated seeds, package root, relation filter,
  mutable cursor, or hidden default direction/depth.
- **CTX-2 — Exact semantics.** The root is one live local owner. Root depth is zero. Expansion visits
  selected incoming/outgoing canonical relations for local owners with depth below the requested
  maximum, assigns every reached local owner its minimum distance, never expands package or foreign
  endpoints, and includes every unique relation selected while expanding. Cycles, self-edges,
  diamonds, and equal-length paths are deterministic.
- **CTX-3 — Bounded stateless result.** Depth is 1 through 8. One request admits at most 4,096 unique

  separately derived map/store/decode admissions. Exhaustion fails atomically with a typed resource
  diagnostic; it never returns a misleading partial neighborhood. Output paging remains bounded by
  the existing item/byte envelope and uses no durable or process-local query state.
- **CTX-4 — Canonical projection and continuation.** Context pages emit existing `owner` projections

## 6. Selected design

### Public selector and traversal

`OWNER` is the existing typed owner identity and must belong to the selected local package at the
observed revision. `--direction` is mandatory and finite. `--depth` is a canonical integer in the
fixed range above. Existing `--limit`, `--bytes`, and `--continuation` retain their public units and
bounds; the item limit counts emitted owner and relation records, not visited witnesses.

Traverse breadth-first by semantic distance. For each frontier owner, enumerate the selected witness
range or ranges in canonical key order. Validate the decoded edge, selected endpoint, relation kind,
and canonical owner/package binding before use. Add a local owner endpoint to the frontier only when
its newly discovered minimum depth does not exceed the request. Package and foreign-package owner
endpoints are output boundaries only. De-duplicate owners and relations by typed canonical identity.
Do not silently cap per-owner fanout; charge and fail at the fixed whole-request admissions.

Materialize the bounded logical neighborhood before emitting success so exploration exhaustion or
corruption cannot masquerade as truncation. Pagination truncates only the complete canonical output
stream. Every page may recompute the same bounded neighborhood from the pinned view; no query file,
index, session, server cursor, or token-carried frontier is permitted. Report actual per-request map,
store, decode, witness-visit, expanded-owner, selected-owner, selected-relation, and rendered-byte
work in separate fields. Do not infer tokens, cost, latency guarantees, or global graph scale.

Reuse the current owner and relation record vocabulary rather than inventing `context-owner` or
`context-edge`. Add only fields needed to make context unambiguous: owner `depth`, summary totals for
owners/relations/expanded owners, and exact context admissions/work. The root appears once at depth
zero even when isolated. Relations may include package or foreign endpoints even though those
endpoints do not receive local owner records.

### Continuation and cutover

The selector digest must canonically encode the new operation, root, direction, and depth. The
continuation's resume key identifies the owner or relation section and exclusive canonical key; it
must fit the fixed token bound and carry no accumulated result. Changing root, direction, depth,
operation, repository, package, revision, or ordering rejects. Changing only page item/byte limits
is allowed. Mutated, padded, oversized, truncated, noncanonical, stale, foreign, predecessor, or
logically impossible tokens reject without repository writes.

This is a direct contract cutover. Existing owners/find/relations semantics stay current under the
new query/CLI versions, but query-3 tokens and removed `context`, `impact`, `request`, `--seed`,
`--work`, `--fanout`, `--continue`, and JSON shapes are not accepted. Do not add an adapter from the
old query index or retain a dual decoder.

### Narrow empirical questions for Codex

Codex must derive the current physical map/store/decode admissions from the fixed logical maxima and
current page/object maxima, then prove exact fit and one-over failure. It must also discover the
current authoritative verifier command/filter names and exact copied-binary fixture identities.
These are local facts; they may not change the public grammar, logical maxima, oracle independence,
or stopping rule.

Implementation layout, helper names, collection types, test placement, and coherent commit count are
implementation latitude. Full semantic body projection, generic impact, fuzzy search, historical
revision query, multiple roots, relation-kind filters, package-root context, and a persistent index
are out of scope.
