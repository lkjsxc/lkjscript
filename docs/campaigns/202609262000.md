## Counterexample and implementation

`ResidentKernel::invoke_timed` incremented queued accounting before awaiting a worker,
but decremented it only when that await returned. Dropping the pending future restored
its semaphore permit while leaving a phantom queued count. The literal regression
manually polls a real invocation future to its pending state, drops it, and observes
shutdown without permitting the operation to run. On unchanged predecessor logic,
`.artifacts/202609262000/queue-before.log` records exit 101: queued=1, active=0,
remaining_tasks=1, no operation executed, no cancellation requested, and
102476699 ns elapsed with two configured 50 ms grace periods.
This is an observed configured-grace delay, not a general latency benchmark.

Pending work now owns the operation and a queue guard in declaration order.
Cancellation destroys captured resources before releasing queue accounting and waking
idle waiters. Admission capacity remains separately guarded. Successful admission
establishes active ownership before removing queued ownership, avoiding the previous
false-idle handoff. Failure to allocate an execution identity also releases pending
ownership. No application-level retry, counter reset, shutdown timeout reduction or
hidden queue is introduced.

The first corrected runtime suite passes all ten tests in
`.artifacts/202609262000/queue-after.log`. A deliberate early-handoff mutation then
causes the independent notification witness to observe active=0 instead of 1;
`.artifacts/202609262000/handoff-mutant.log` records the genuine exit 101. The worker
is released and joined before that assertion fails. The mutation was removed, not
weakened into an accepted expectation. The final suite adds an actual blocking
worker beside a Tokio task aborted while queued.

The original runtime file is byte-identical between the v0.1.48 and v0.1.49 tags.
This is not a defect introduced specifically by the native starter. The exact
kernel witnesses do not establish all HTTP disconnect paths, data corruption,
hostile-code isolation, or rollback of already started effects. Normalized
resident targets and ports share the corrected kernel. Existing task/grant/stream
limits and application data formats remain unchanged.
