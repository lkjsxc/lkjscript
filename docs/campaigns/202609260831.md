`7009061def5a3cf2d846c1882f5104c90bedc675`, not pushed. Its fresh source owner is
`.artifacts/lkjscript-dev/check/1790380928226667166-933052-0`, launched from an

is used. The original check is a prototype observation, not permission to deliver a
known-defective product. Its eventual terminal must not be relabeled as corrected
source acceptance.

A literal copied-executable relative-path witness runs with an empty environment
and PATH, creates a command project in a path containing spaces, passes 76 native
tests with differential equality, builds twice and observes exact reuse, then
runs the returned relative deployment and gets `hello`. The first creation omitted
an explicit logical name and correctly rejected a name containing spaces; using
the discovered `--name` option fixes that fixture, not the product.

Review then reproduced a genuine problem: an operator descriptor with mode 0600
was copied into a new descriptor with mode 0640 under the host's umask. A controlled
child-only umask 000 oracle reproduced mode 0666 and unsafe exact reuse. The
unchanged driver is `.artifacts/202609260831/private-descriptor.mjs`; its corrected
baseline output `privacy-original.json` has four failed and four passed assertions.
It independently checks POSIX modes and actual public-command effects. Its first
attempt mistakenly supplied --project to standalone run and was rejected; that
harness failure is retained in `privacy-before.json` and is not the counterexample.
Fixtures contain no actual secrets and affect only newly owned disposable paths.

The correction adds a private mode to the existing create-new output owner rather
than copying its publication algorithm. It creates the private stage at 0600 before
writing, never a chmod-after-publication window. Only deployment descriptors use
that path; ordinary artifacts retain existing permissions. Exact descriptor reuse
also checks current effective ownership and absence of all group/other bits before
reading bytes. Broad or foreign-owned existing files reject before artifact
publication, with no permission, ownership or byte changes. Explicit operator
repair or sharing is outside build. The receipt reports `access=owner-only`.

A new unit regression and copied-executable workflow cover permissive umask,
group/other read/write/execute bits, original-file preservation, preflight ordering,
explicit repair and unchanged raw-output policy. The public test changes umask only
inside a child shell, not the parallel test process. Corrective compilation,
focused reruns, the unchanged independent oracle and fresh source acceptance are
still required; the existing functional passes alone do not prove this correction.
