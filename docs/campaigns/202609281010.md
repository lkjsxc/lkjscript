## Contract and implementation

Development v0.1.53 adds `inspect history [--limit N]`. The default is 20 entries,
maximum 100; one cumulative admission bounds catalog lookups and objects to 200
and payload to 8 MiB. The reader captures HEAD and the append-only store snapshot
under one repository lock, then releases that lock before traversal. It preserves
v0.1.52's coherent recovery observation: healthy opening is shared, recovery keeps
exclusive ownership until HEAD has been observed.

Canonical revision/receipt decoders and repository, graph-contract, parent,
result, transaction and semantic-diff bindings are checked. Missing or inconsistent
visited objects reject the complete response. The last returned record can name
an explicitly unread parent; that is neither an admitted cursor nor proof of the
suffix. Two-parent history is reserved rather than silently choosing a parent.

Output separates recorded intent, owner/dependency counts and selected/executed/
passed tests. `current-validation=not-run` is explicit. No old executable graph is
required or run; no operational data, deployment selection, rollback, graph schema,
artifact or package encoding changes. The exact public command and bounds are
discoverable; generated references remain owned by the existing native guide tool.
