## 4. Target contract

### 4.1 Authority and physical store

One deployment-selected local root owns one exact current operational revision. It has its own
format/store identities, namespaces, schema state, immutable records, and atomic current-head
binding. It never reuses graph, package, artifact, compiler-cache, or semantic-revision identity.
Service and worker may share the root through separately validated grants without gaining program
authoring authority.

Physical catalogs and navigation indexes are derived. Missing derived state may rebuild from
verified immutable data; missing or inconsistent accepted data, reachable objects, schema, or head
is corruption and fails closed.

Implement a repository-owned local directory format with bounded canonical decoding, private
staging, create-new files/directories, file and directory synchronization, one cross-process writer
lock, immutable accepted objects/pages/packs, a rebuildable catalog, and one atomic durable head.
Readers pin immutable revisions. Retain all reachable history in this campaign; no compaction, GC,
destructive repair, or accepted-file rewriting.

Every retained interruption checkpoint before head visibility reopens the old state; every point
after durable visibility reopens the new state. Reject corrupt payloads/digests/links/catalogs,
invalid offsets/lengths, duplicate keys, foreign domains, symlinks, non-regular files, path escapes,
trailing input, and exhaustion. Catalog-only damage may rebuild; canonical damage may not be guessed
away.

Proven graph-store primitives may be extracted or reused only with explicit domain separation and no
shared authority. Do not build production on SQLite, PostgreSQL, RocksDB, another embedded database,
an SQL parser, or a permanent provider abstraction.

### 4.2 Provider-independent logical interface

Replace the SQL standard surface with one exact `DataStore` interface and canonical standard types.
Names may change only for a verified naming conflict; semantics are fixed:

- `DataKeyPart` has exactly `Bool`, `I64`, `Text`, and `Bytes`. Keys are nonempty bounded sequences.
  Compare lexicographically by sequence; tag order is Bool, I64, Text, Bytes; value order is
  `false < true`, signed numeric order, validated UTF-8 byte order, and unsigned byte order; a
  strict prefix precedes its extension.
- A static graph-owned space name plus key selects one record. Space, part count, key bytes, value
  bytes, transaction mutation/bytes, scan item/bytes/work, and live resources have independent
  executable-discovered limits.
- Pure standard functions equivalent to `data-encode<T>` and `data-decode-or<T>` provide canonical
  exact typed values. Encoding binds nominal/runtime layout identity and rejects foreign types,
  corruption, noncanonical/trailing bytes, and exhaustion. JSON, Rust layout, serde shape, and SQL
  rows are not storage authority.
- `schema-read` returns missing or one exact schema identity/digest. Transaction-only `schema-set`
  compares missing/exact prior schema. Graph migrations use ordinary reads/writes and publish the
  next marker last; exact retry is a no-op and divergence has no visibility.
- `get` returns missing or value plus an opaque entry revision. Revision identity prevents ABA:
  delete/recreate never validates an old expectation.
- `scan` reads one exact snapshot in canonical order over static space and key prefix, forward or
  reverse, under item/byte/work limits. Its opaque continuation binds store, revision, selector,
  direction, limits, and exclusive resume key; no mutable server cursor exists.
- Transaction-only `put` and `delete` require `Missing` or an exact entry revision. Failed
  expectation returns false and stages nothing. Maintained code performs the primary conditional
  write before dependent index writes; later capability failure rolls back everything.
- `transaction` pins an exact base, reads its staged writes, and commits at most one new head. Commit
  locks, rechecks the base, makes immutable data durable, then changes visibility once. A changed
  base is a retryable conflict with no visibility. Possible post-visibility interruption remains a
  distinct reconciliation class, not a blind retry.

Secondary indexes are ordinary application keyspaces updated atomically with their primary record.
No joins, arbitrary predicates, dynamic schema language, ambient filesystem access, network
database, hidden optimizer, or SQL compatibility is included.

### 4.3 Public lifecycle and deployment

Add one discoverable top-level `data` operation using the current registry, path policy, bounded
records, diagnostics, and generated-document owner:

- `initialize`: validate one first-party grant; atomically create only an absent root; matching valid
  state reports unchanged; foreign/corrupt state rejects.
- `verify`: reconstruct and validate the complete accepted closure without mutation.
- `backup`: pin one head and write a create-new canonical logical backup containing schema and sorted
  key/value/revision facts plus manifest/digests, independent of page/pack layout.
- `restore`: accept only a strict backup and absent destination; create equivalent logical state
  under a new physical identity, verify it, and publish the root once.

No in-place overwrite/repair, SQL import, interactive shell, ad hoc query language, or alias.
Recovery is backup, restore to a new root, then explicit descriptor switch.

Add exact first-party deployment adapters equivalent to `data` and `durable_queue_data`, with
confined root, strict namespace, sharing domain, authority revision, and independent limits. They
have no connection secret, host/port/TLS, or PostgreSQL timeout. Preparation validates format,
identity, namespace, operation closure, paths, and limits before readiness; failure emits no
readiness and releases partial resources.

### 4.4 Maintained consumers

- **BBS:** store each post once in a primary space and maintain `(created-at, id)` index keys
  atomically. Listing scans the index and resolves primaries in one read transaction. Create expects
  missing, update expects exact revision, delete removes primary/index atomically. Remove SQL schema,
  statements, `SqlValue`/`SqlType`, JSON row aggregation, SQL row helpers, and migration checksum.
- **`lkjournal`:** inventory current tables/operations, then map actor, session, resource,
  immutable-snapshot, object-metadata, and lookup facts to explicit graph-owned spaces/indexes while
  preserving routes/domain behavior. Remove every SQL statement, row codec, checksum, and
  PostgreSQL-specific graph function. Use public reviewed change. Add only minimal typed
  retire/remove or requirement-rebind authored operations needed for the cutover; no private graph
  builder, frozen replacement artifact, or second authoring format.
- **Durable queue:** implement the existing contract in a separate internal namespace of the same
  engine: idempotent enqueue, ready order, exact lease/attempt, heartbeat, stale completion
  rejection, retry, cancellation, inspect, restart, and bounds. Do not claim exactly-once delivery
  or cross-capability atomicity.
- **Objects:** keep bytes in object storage; only metadata/reconciliation facts move.

Service and worker descriptors share the first-party root. Remove `postgres`,
`durable_queue_postgres`, database URL secrets, PostgreSQL preflight, and normal database
prerequisites. Old adapter kinds/fields/secrets, exact standard references, and predecessor
artifacts reject or disappear.
