## Implemented contract

Repeated `serve --deployment` arguments select one fixed in-process group.
HTTP and interactive services share exact immutable `NormalizedProgram` objects
and the Tokio scheduler, while each instance has its own descriptor, configuration,
secret catalog, grants, adapters, resident kernel, queues and cancellation.
Every artifact path is strictly loaded, including code-cache hits. Distinct complete
artifact versions do not alias, and no process-global cache retains stopped code.

All static admission precedes any live preparation. The group is limited to 64
instances and the sums of declared concurrent/queued task capacities are bounded
by 4096/65536. All listeners bind before one group-ready event. Startup cancellation
requests cooperative stop and joins its blocking owner. Signals or a member's
infrastructure failure request group stop; every started service is joined before
the host returns. Handled request errors and overload remain per instance.

The CLI publishes argument ordinals, redacted instance observations, exact code
digests and structural accounting, not a complete memory profile. Library tests
can independently stop one instance and prove last-owner program reclamation.
There is no CLI dynamic load/reload/individual stop, cross-instance owned message,
fine-grained inter-version dependency pooling or hostile-tenant sandbox.

See [the specification](../spec/shared-runtime.md) for the compatibility key,
readiness/termination semantics, external-resource sharing and observation limits.
No graph, package, artifact or operational-data encoding changes; no new dependency,
Python, JavaScript, service migration or production application restart.

## Admission/stop race found during final review

The pre-existing resident kernel checked `accepting`, then acquired/accounted its
queue owner without synchronizing that interval with shutdown. Stopping could
observe zero queued/active tasks and finish adapter cleanup while an already
accepted invocation still held its capture. The earlier full-profile success did
not test this interleaving and does not dismiss the newly demonstrated defect.

A test-only pause in the real acceptance prefix reproduces the failure before
changing production behavior. `admission-race-original-run.log` retains the actual
failing unit run: zero passed, one failed, with `shutdown reported idle while an
accepted invocation still owned its capture`. Both invocation and shutdown owners
are resumed/joined before that assertion. The preliminary compilation-only log is
retained separately; its background output transport did not establish test execution.

The correction puts acceptance and queue registration under one short per-instance
mutex, and closes admission under the same mutex. It releases that mutex before
waking semaphore waiters, awaiting work, running application code or cleaning up
adapters. The test hook is compiled only for tests. Queue limits, operation grants,
resource semantics, existing deadlines and concurrency of application execution
are unchanged. The corrected focused run passed all 16 runtime tests, including
the same previously failing regression, with zero failures or ignored cases in
0.50 seconds after compilation. Original output and exit status are retained as
`admission-race-corrected-runtime.log` and `admission-race-corrected-runtime.exit`.
This focused result is not the combined-source acceptance; that is recorded
separately after the corrected inputs have been frozen and checked.
