## Implemented contract

Repeated `serve --deployment` arguments select one fixed in-process group.
HTTP and interactive services share exact immutable `NormalizedProgram` objects
and the Tokio scheduler, while each instance has its own descriptor, configuration,
secret catalog, grants, adapters, resident kernel, queues and cancellation.
Every artifact path is strictly loaded, including code-cache hits. Distinct complete
artifact versions do not alias, and no process-global cache retains stopped code.

All static admission precedes any live preparation. The group is limited to 64
instances and the sums of declared concurrent/queued task capacities are bounded
by 4096/65536. All listeners bind before one group-ready event. Startup cancellation
requests cooperative stop and joins its blocking owner. Signals or a member's
infrastructure failure request group stop; every started service is joined before
the host returns. Handled request errors and overload remain per instance.

The CLI publishes argument ordinals, redacted instance observations, exact code
digests and structural accounting, not a complete memory profile. Library tests
can independently stop one instance and prove last-owner program reclamation.
There is no CLI dynamic load/reload/individual stop, cross-instance owned message,
fine-grained inter-version dependency pooling or hostile-tenant sandbox.

See [the specification](../spec/shared-runtime.md) for the compatibility key,
readiness/termination semantics, external-resource sharing and observation limits.
No graph, package, artifact or operational-data encoding changes; no new dependency,
Python, JavaScript, service migration or production application restart.

## Delivery boundary and next decision

This is a development v0.1.53 change, not a new public release. Public v0.1.52,
its original producer/assets, the previous failed v0.1.53 candidate and all tags
remain unchanged. A v0.1.53 publication needs a new source-specific candidate,
verbatim notes, all source/selected-target gates and ordinary immutable promotion;
the history-only failed candidate cannot stand in for the changed implementation.

No speed/RSS reduction, CPU fairness, process-crash survival, instantaneous native
cancellation or new advanced type system is claimed. The resource observations
cover shared encoded objects and selected per-instance counts, not complete live
private-memory accounting. Pre-cancelled admission and running-service signal
termination are tested; not every possible blocking adapter phase is independently
fault-injected. Explicitly shared external paths still share external resources.

Next language evidence should be an ordinary generic producer/transformer/consumer
across an exact package boundary, with one valid owner or cleanup owner through
move, scoped borrow, queue-full, cancellation and receiver failure. Keep a copied
standalone-binary witness and negative admission cases. Only then use measurements
to choose region allocation, local tracing, frozen sharing or component-level
pooling; do not conflate this host's Rust Arc implementation with the language's
permanent ownership model.
