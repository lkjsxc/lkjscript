## 2. Why this outcome

The language now combines exact packages, rank-one function values, explicit immutable environments,
tail execution and practical persistent lists. It can support libraries of configurable transforms
rather than host-coded application recipes. However, `kernel/infer.rs::require_capture_safe` rejects
`TypeForm::TypeParameter` unconditionally, and `TypeParameterRecord` has no constraint meaning.
A generic factory cannot retain its caller's ordinary configuration even when each intended concrete
instance is safe. The workaround is concrete factory duplication or exposing configuration in each
consumer's accumulator/signature. Capturing a callable whose signature mentions T is already allowed;
it does not solve storing an actual T.

Select one built-in structural type constraint and its complete public path. The strongest broader
alternative is parametric nominal data declarations: valuable, but it expands declaration, layout and
codec design before resolving this already identifiable barrier to higher-order reuse. A release
would distribute existing gains but not remove it. This campaign enables reusable configured
projectors, default-value functions and callback libraries over existing data forms. New witnesses
establish capability, not existing adoption. General traits, generic nominal types and richer effects
remain contingent opportunities, not additional work.

Preserve explicit rank-one instantiation, current recursive-call restrictions, function/effect and
package visibility rules, pure binding order, tail transfer, persistent lists and data encodings.
Do not add implicit capture/constraint inference, lambdas, task closures or generic tasks, resource
polymorphism, generic extraction, equality/serialization constraints, user-defined traits,
specialization/JIT, new collection intrinsics, application features, releases or deployments.

## 3. Fixed semantic and public contract

### Constraint authority and entailment

Add graph-owned type-parameter constraint meaning. The closed set for this campaign is either empty
or `{capture-safe}`; encode it canonically with explicit stable tags. Unknown or duplicate constraints
reject. An empty set means unconstrained, not implicitly safe. Attach it to the existing stable
`TypeParameterRecord` identity and exact declaration, never a name, annotation, inferred body fact,
request side table or runtime value. Constraints are interface meaning even for an unused parameter.

Use the existing pure/closed-external rank-one declaration model. Pure graph declarations may use the
new constraint. Closed external signatures remain checked against the exact intrinsic inventory;
constraints cannot decorate an external into a new implementation or relax that match. Existing
external constraints remain empty unless its unchanged closed contract actually declares otherwise.
Task declarations and generic nominal declarations do not become admissible.

Define `capture-safe(type, declaration-scope, exact-closure)` by the existing stored-type rule:
scalars including StaticText are safe; structural/nominal records, all variant payloads, lists, map
keys/values, options and result branches require every stored child to be safe. Inspect absent cases
and empty-container element types. Secret, stream and capability/live-resource storage is unsafe.
Traverse already admitted nominal cycles with bounded visitation; do not introduce recursive types.
A type parameter is provably safe only when its exact in-scope declaration supplies this constraint.
An out-of-scope or foreign parameter ID never imports a proof merely because an owner record exists.

A pure Function type remains a capture-safety leaf: future parameter/result types are not retained
values. Thus `Function(U)->U` is safe without requiring U itself to be safe. Actual callable values
still require the existing pure-target, origin and safe-environment admission. This is not permission
to hide a task port or resource inside a callable. Capture-safe implies neither semantic equality,
serialization, durable/session retention nor capability authority.

At every direct-call and named-function-value instantiation, prove each callee constraint for its
explicit type argument in the caller's scope before accepting the complete candidate. A caller's
constrained U may discharge a callee's constrained T; unconstrained U may not. Structural composition
such as `List<U>` works precisely when its stored leaves satisfy the rule. Check constraints even
for unused parameters, dead branches, empty lists and functions whose bodies do not bind anything.
Keep exact arity, scope, substitution, ordinary type well-formedness and effect checks independent.
A constrained body may bind T or its safe aggregates; an unconstrained body still rejects. No
constraint dictionaries, implicit specialization, subtyping or higher-rank quantification is added.

### Authoring, review and inspection

changes; canonical/JSON forms carry the same closed constraint set. No raw graph edits or private

Do not print runtime secrets or invent an unbounded explanation traversal. Rename keeps meaning;

### Small graph-owned proving surface

`function-constant<Value: capture-safe, Argument>(value: Value) -> Function(Argument)->Value`.
Implement it with existing `bind` over a private ordinary generic graph helper returning its first
argument. Do not constrain Argument or require the noncapturing helper's Value to be constrained.
No constant-function intrinsic is permitted.

Retain a separately authored non-built-in generic factory:
`configure<Env: capture-safe, Input, Output>(env: Env, step: Function(Env,Input)->Output) -> Function(Input)->Output`.

`[1,2,4]` yields `[8,11,17]`; a simultaneously retained `{scale:-2,bias:4}` instance yields `[2,0,-4]`

through standard map. This is a reusable callback/configuration family, not a new application.
A factory instantiated with `List<Secret>` must reject even when the list is empty; a malformed
runtime callable with a hidden forbidden environment must reject at its real admission boundary.
