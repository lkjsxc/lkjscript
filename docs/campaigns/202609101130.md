## 1. Decision and finish line

An ordinary user must be able to download the supported release and author reusable parameterized
records and variants, compose them with generic graph functions and retained pure callbacks, move
code-complete libraries between projects, and use admissible concrete instances with typed data
and structured sessions. The source already implements this outcome. This campaign completes its
distribution boundary rather than claiming that release engineering invented the language feature.

The predecessor explicitly selected source-only completion and a next-cycle release review when
NOM-1–NOM-7, maintained-consumer migration, normal integration and exact local musl admission passed.
Its terminal record reports precisely that state. Honor this achieved trigger instead of moving it
behind recursive generic types, a new application or an idealized final language. [S1–S3]

The strongest alternatives are broader recursive generic data, richer effect/resource composition,
and a coherent optional-metering execution policy. Each could have substantial long-term value,
but each introduces a different semantic, ownership or failure contract. None is needed to deliver
the completed nominal abstraction. A compiler/backend campaign also lacks a selected measured
bottleneck here. Publishing now has higher immediate leverage: it makes the completed reusable
foundation available to independent programs without the source checkout, and creates a reliable
external baseline for discovering the next composition limit. [S2,S4]

Do not inflate the scope into a new release platform. Existing transferred offline-package and
pure-tail owners already execute nominal workloads, and the current transferred fault matrix
already contains nominal omissions. The work is to run, verify and finish that path for the new
source, repairing only demonstrated defects necessary for truthful delivery. A documentation-only
campaign, a tag without download proof, and another local target pass without publication are not
the selected outcome. [S5–S8]

Completion requires one normally integrated release source, its required fresh acceptance, a
successful exact-source hosted dry run, immutable publication through the established workflow,
