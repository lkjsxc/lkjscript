## 3. Authority and selected architecture

### Immutable meaning and exact resolution

Each dependency binds package ID, semantic revision, logical package revision, and its committed
interface. The root accepted graph selects the complete logical program. Imported graphs are
immutable snapshots, never extra editable repositories or hidden HEADs. Package names and paths
are presentation/transport only. Staging, inspection, compilation, cache recovery, export, and
execution must not advance any semantic HEAD.

Resolve the union of exact transitive dependencies before acceptance or execution. A package ID
has exactly one logical/semantic revision throughout that union. Deduplicate shared dependencies;
reject missing edges, cycles, self-dependency, conflicting revisions, foreign references, and
interface/body inconsistency. Transported externals must satisfy existing exact intrinsic
signature/effect admission; import cannot register host code or grant capabilities. Different
package IDs with equal names remain distinct. Closure
availability is not visibility: references still obey existing direct-dependency and public-interface
rules. An installed transitive package does not become an ambient import.

### Code-complete transport, not trusted object code

Replace the interface-only public transport file with one strict, versioned, deterministic,
uncompressed container. Reuse existing logical `PackageRevision` and `PackageTransport` ownership;
do not invent another program model. The container binds one root transport and every exact
transitive selection and carries the canonical objects needed to reconstruct each selected current
graph, including private bodies, types, current retirement metadata, and public interfaces. Carry
only the required current closure, not entire repository history. Ancestor identities need not
bring their historical bodies. No host paths, grants, operational data, compiler caches, or imported
bytecode are authoring material. Internal privacy is not source confidentiality.

Canonicalize the container independently of original pack partitioning and directory order, with
unique ordered object keys and an exact closure inventory; identical bound inputs export identical
bytes. Reject missing, extra, duplicate, malformed, noncanonical, or trailing material. Reconstruct
and fully validate graph meaning and interfaces; bundled witnesses are not self-authenticating
proof. A valid hash on an ill-typed private body must still fail admission. Integrity establishes
content agreement, not publisher identity or original acceptance provenance.

Compile admitted dependencies through a read-only immutable package view, in deterministic
bottom-up order, using the existing compiler and linker. Do not materialize writable shadow
projects to satisfy APIs. The reference interpreter independently evaluates canonical dependency
owners, not compiled units or production resolver decisions. Check each selected package's existing
graph tests once; command target selection remains root-scoped. Standalone service artifacts retain
the full executable closure and require no dependency directories at runtime.

The embedded standard remains a convenient exact source supplier for recipes, not a privileged
identity in admission or execution. An embedded compiled asset may remain only a derived accelerator
whose exact graph/contract/input equivalence to clean compilation is proved. Imported transports
cannot supply independently trusted compiled units. Missing or invalid derived caches rebuild;
missing/corrupt admitted canonical source fails with an actionable restage diagnostic, not a
fallback to a checkout, ambient directory, or a different embedded revision.

### Staging, review, and failure boundaries

Reuse the `PACKAGE-TRANSPORTS` operational owner. Stage into private owned storage, validate the whole
container, durably install immutable material, then expose one atomic closure-ready selection.
Readers see either the previous ready closure or the complete new closure, never partially installed
members. Readiness binds the validation contract and exact immutable inputs. No global package
registry, mutable authoring session, or semantic sidecar is needed.

Restaging identical material is idempotent. Staging another revision only makes a candidate
available; it cannot replace an accepted dependency. Physical reselection for the same logical
revision cannot change meaning. Plan reports old/new exact bindings, transitive closure changes,
interface effects, affected owners/tests, and its commitment through existing bounded review output.
Apply rechecks base, closure availability, validation identity, and all logical bindings under the
publication lock before the sole accepted visibility point. Stale/altered plans, an incompatible
replacement, missing source, and exhaustion publish nothing.

Before staging visibility, failure leaves prior readiness and all semantic HEADs unchanged; owned
stages are removed. An interruption may leave unreachable immutable objects, never a ready partial
closure. After visibility but before acknowledgement, retry/inspection must identify the complete
staged result. Semantic publication likewise remains old-or-new; post-publication derived failure
must report acceptance separately. Tests must observe these distinctions, not infer them from exit
status. Preserve existing diagnostic classes/codes where applicable; new failures must identify
the exact package/revision or exhausted bound and the corrective restage/replan action.

### Admission limits and implementation latitude

For the new transport admission, hard ceilings are 268,435,456 container bytes, 1,000,000 distinct
objects, 10,000 packages including its root, and 100,000 dependency edges. Retain existing narrower
per-object, value-depth, authoring, output, and execution limits. Charge at most 16,000,000 aggregate
owner/type/expression/relation validation visits and 4,294,967,296 cumulative validation-read bytes
per admission, without resetting counters per package. These are conservative safety ceilings,
not claimed capacity or throughput. No public override or compression is in scope. Check arithmetic
and lengths before allocation; use visited sets and bounded iterative closure traversal.

Codex owns factoring, indexes, cache placement within existing owners, concrete encoding tags,
and command integration. It may replace an internal mechanism only with recorded disconfirming
local evidence and unchanged outcomes. One bounded preflight exports/sizes standard, lkjournal,
and the acceptance diamond and verifies compatibility with these ceilings; exceeding them requires
a blocked report, not silent limit inflation. There is no open-ended performance experiment or
alternate product objective.
