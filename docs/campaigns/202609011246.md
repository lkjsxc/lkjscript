## 4. Current bottleneck

At the orientation revision:

- Graph Contract 5 has no first-class generic capability-resource type. Accepted meaning cannot
  represent a durable-queue lease as unique program authority.
- `ParameterRecord` owns name and type but no canonical unrestricted/borrow/consume mode.
- Standard `DurableQueue` has eight operations. `claim` returns a zero-or-one `List` of a structural
  record containing copyable `attempt_id`, `attempt_number`, `job_id`, lease time, and payload.
- `heartbeat`, `complete`, and `fail` accept raw job/attempt/worker text. Runtime storage validates the
  tuple, but accepted graph meaning cannot reject duplicate terminal use, use after an ambiguous
  terminal call, or a reconstructed token before publication.
- Normalized execution already has task-scoped opaque handles bound to exact requirement authority,
  but only byte streams use the resource table; queue adaptation ignores it and emits ordinary values.
- Queue storage already owns nonreused attempts, finite leases, stale rejection, atomic operational
  revisions, backup/restore, and bounded failures. The defect is the program authority above it, not
  the queue algorithm or data format.
- `applications/lkjournal/` is a maintained consumer whose service/worker proof already covers claim,
  completion, stale attempts, restart, failed startup, backup/restore, and cleanup.

The bottleneck is split lease authority: graph meaning grants queue use, while copyable strings remain
the transition right. Runtime catches stale tuples only after an invalid program was accepted, leaving
maintained application protocol meaning outside the graph.

### 5.2 Affine flow

The validator derives exact requirement provenance and evaluates uses in language order.

- Borrow observes without ending ownership. Ordered borrows may precede one consume.
- Consume moves the resource from its binding. Any later use of that owner rejects before publication.
- Dropping is allowed. Task cleanup removes only the local handle; it never completes, fails, cancels,
  or otherwise mutates the durable queue.
- A nominal variant may contain one direct resource payload; matching consumes the outer value and
  transfers the payload to the selected branch.
- Resource-bearing records, lists, maps, streams, function/generic values, constants, tests, and
  function signatures reject. Do not add partial moves, affine containers, polymorphism, or capture.
- A branch join preserves a binding only when every reachable branch preserves the same owner and
  provenance.
- A resource operation must use the exact requirement that acquired the handle. Foreign requirement,
  scope, kind, closed slot, duplicate alias, and predecessor token shapes reject.
- Every semantic rejection identifies the owner/expression and leaves semantic `HEAD`, derived cache,
  generated output, and operational data unchanged.

Validation, compiler, artifact, and runtime movement must agree. Host copying must not become a
second authority; hostile derived input still receives runtime single-consume enforcement.

### 5.3 Final queue interface

Replace the lease record and raw token signatures in one cutover. The final interface has nine
semantic operations, with one public spelling each:

- unchanged `initialize`, `enqueue`, `cancel`, and `inspect`;
- `claim(worker-id, now, lease-duration) -> QueueLeaseState`;
- `lease-info(lease borrow) -> QueueLeaseInfo`;
- `heartbeat(lease consume, now, lease-duration) -> QueueLeaseState`;
- `complete(lease consume, now, result) -> Bool`; and
- `fail(lease consume, now, retry, retry-at, error-class) -> Bool`.

`QueueLeaseState` is a standard nominal variant with absent and live cases; live directly carries
`CapabilityResource<DurableQueue>`. It replaces the zero-or-one list and is reused by heartbeat.
`QueueLeaseInfo` contains unrestricted job identity, attempt number, lease-until time, and payload.
It omits attempt and worker identity; those remain private runtime transition authority.

`lease-info` reports acquisition metadata, not current liveness. Heartbeat consumes the old handle
and returns fresh-or-absent. Complete/fail consume on every reached outcome. Once a consume argument
is evaluated, the old binding is unavailable even on stale, cancellation, or possible visibility.

Reserve handle capacity/identity before claim or heartbeat effects. Local exhaustion precedes queue
mutation; empty/stale/failure releases the reservation; successful transitions cannot lose authority
to avoidable post-effect allocation. Possible visibility consumes the local right and preserves no
exactly-once claim.

Keep queue ordering, retry/attempt policy, physical store contract, operational revisions,
backup/restore, and no-exactly-once limitation unchanged. Internal `JobLease` may retain raw fields,
but only the resource scope and queue engine may use them as transition authority.
