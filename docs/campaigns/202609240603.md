A concrete native-development obstruction is present: Bytes has length, concatenation,
text conversion and equality, but no indexed observation. The maintained policy therefore
receives a List<I64> per raw file prefix. This host expansion prevents ordinary native
code from examining opaque Bytes received from HTTP/object storage without text decoding.

Add the general closed pure `core.bytes.get(Bytes,I64)->I64` primitive and expose
`bytes-get` in the maintained standard package. Indices are zero-based byte offsets;
results are unsigned octets represented as I64. Negative or out-of-bounds indices trap,
including both I64 extremes; no UTF-8 decoding, replacement, clamping or wrapping occurs.
Keep graph, artifact and data encodings unchanged. Older runtimes must reject the new
external contract rather than misexecute it; unchanged old exact closures remain valid.

Use ordinary native authoring to add the standard declaration and fixed graph tests.
Migrate the existing policy's accepted program to Bytes, retiring production integer-list
expansion. Retain its independent byte oracle, all prefix/read/link/order semantics and
required gate. Keep unchanged guide and application dependencies exact rather than
upgrading them merely to match the newest builtin. Prove fresh public authoring,
canonical re-entry, detached execution, wrong signatures and bounds. Measure matched
complete policy costs without erasing slower cases. Run dependency-complete acceptance
after inputs stabilize, then integrate through normal mainline operations.

No new filesystem/process authority, policy-specific intrinsic, compiler self-hosting
claim or frozen-release modification is selected. Publication remains a distinct boundary.
