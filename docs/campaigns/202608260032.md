## Deviations and limitations

- The active HEAD exactly matched the audited baseline, so no later implementation or conflicting
  campaign required reconciliation.
- The fixed compact envelope requires a 1,536-byte public output minimum; the campaign explicitly
  allowed the smallest justified minimum.
- Core, process cutover, generated documentation, and proving tests were one coherent implementation
  commit because the new descriptor, repository adapters, registry, and public boundary compile and
  verify as one dependency closure. Current/normative documentation and retained evidence form the
  following coherent documentation commit; the final handoff owns the resulting final HEAD because
  a commit cannot canonically contain its own SHA.
- The first fresh full profile exposed five warnings-denied Clippy findings in the new code. The
  correction uses typed persistent-map and repository relation range selectors rather than lint
  suppression; the exact Clippy command and narrow range/query tests pass before the final rerun.
- `/usr/bin/time` was unavailable. The scale record uses Bash process CPU time and Linux
  `VmHWM`; filesystem cache state remained uncontrolled.
- Service acceptance could not start because this environment provides no `docker`, `podman`,
  `nerdctl`, or `docker-image-inspect` command. The harness classifies that gate as
  unavailable rather than passed; all independent evidence remains required and the final handoff
  reports the final receipt verbatim.
- The 10,000-owner fixture uses the normalized in-process builder as permitted. Public correctness,
  copied-binary independence, interruption, and no-write behavior are proven separately.
- Query remains current-revision-only. Context, impact, fuzzy/historical search, saved queries, and
  compiler/runtime/package/service/worker cutovers remain out of scope.
