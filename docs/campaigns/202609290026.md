## Selected continuation

Keep one affine protocol rather than introducing a second public-library
ownership mechanism. Remove visibility/package vetoes from resource-flow admission
while preserving exact signature use, final-argument placement, concrete authority,
interface, generic type parameters, parent and closed-effect checks. Normal
namespace/interface visibility admission remains authoritative.

Imported public signatures and local canonical declarations use the same field
contract. The independent snapshot flow oracle reads interface fields separately.
An imported concrete requirement may be retained by a public forwarder; a same-name
local requirement cannot substitute for it. Strict linking obtains foreign task
requirement metadata from its owning dependency, and complete loading rechecks
that exact executable closure.

Entry ports explicitly declare imported obligations in their top-level closed
task row. Canonical and strict-loaded HTTP route closure and runtime component
preparation agree about those declarations. Implementation bodies, nested callbacks
and unused supplier requirements do not implicitly grant authority. Deployment
still binds actual exact grants. Name-based descriptors cannot address two distinct
same-name obligations; missing or duplicate grants fail before effects.

Affine feature 6 and qualified-task feature 2 produce validator identity
`validator_contract_2bf742fb0f1d14e45f17e9e20777400c9014c222e1cfab9e21419b58288b68fd`.
Graph/codec/bytecode formats are unchanged. Rust still owns the compiler and host;
the authored library/consumer execute through ordinary lkjscript alone.
