## 2. Strategic choice and preserved contract

Offline code-complete packages, bounded pure tail execution, checked-value propagation, explicit
pure environments, and persistent graph-owned mapping now form a useful compositional core.
Publishing that coherent core makes these capabilities available to independent consumers without
a contributor checkout. This is a milestone selection, not a release obligation for every version
change or implementation campaign.

The strongest foundational alternative is explicit generic capture constraints: bare stored,
unconstrained type parameters remain outside the capture-safe subset. That extension is valuable,
but would add another semantic migration before the existing mutually enabling foundations reach
distributed users. Close this demonstrable public-path gap first. Richer capture and other language
work remain contingent follow-ons, not implementation obligations here.

A useful scenario exports a library with a private configured helper, removes its producer, imports
its exact closure into an independently authored consumer, and maps runtime input through a bound
callable. Public authoring, definition inspection, validation, build, execution, and failures must
work without Cargo or private generators. Wrong callback types, stale reviewed changes, missing or
conflicting package closure, and execution exhaustion must retain their existing rejection and
recovery behavior. A release with a missing capability receipt must never pass on HTTP success alone.

Preserve current graph/type/effect/capture rules, evaluation and failure order, resource limits,
package visibility, supported encodings, and maintained semantic identities. The graph remains the
only editable program meaning; release evidence cannot edit it. Operational data and deployment
remain separate. No new language form, capture permission, execution tier, target, installer,
registry, application feature, deployment, or operational-data migration is selected. Correct a
minimal directly exposed regression only when necessary to satisfy the existing contract; a
fundamental semantic redesign is outside this mandate.
