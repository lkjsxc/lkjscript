## 0. Executive mandate

Transform lkjscript from a recently cut-over canonical meaning-graph platform into a genuinely self-hosting application-development environment for agents.

The intended first-use artifact is one `lkjscript` executable.

An agent given that executable and an empty directory must be able to discover the system, create a project without a repository checkout or external artifact, author a nontrivial application through the CLI, inspect and refactor its meaning graph, add tests, validate it, build it, run it, diagnose failures, and recover it.

The canonical accepted program authority remains one typed, revisioned meaning graph.

Do not reintroduce maintained textual source.

Do not turn transaction JSON into source code by another name.

Do not expose storage records as authoring.

Do not preserve the current command hierarchy merely because the graph cutover is recent.

Meaning-graph development must become materially better than text-first development on semantic selection, stable identity, change precision, refactoring, impact analysis, merge, locality, context economy, and deterministic publication.

The current system is correct in several important respects but remains locally optimized around the first graph cutover.

This campaign must revisit the architecture as a whole.

The highest-priority defects are:

1. no binary-only blank-directory project creation;
2. whole-graph reconstruction and cloning on ordinary changes;
3. repeated full validation and publication work;
4. roots and APIs whose easiest implementation is linear in total modules;
5. name-bearing references that make rename scan unrelated modules;
6. a ceremony-heavy public mutation workflow;
7. excessive and partly redundant vocabulary;
8. public hard ceilings that reflect the current representation rather than language meaning;
9. insufficient language and authoring abstractions;
10. redundant verification work and avoidable model-context cost;
11. missing compaction, retention, and large-graph physical design;
12. a current roadmap that still mentions TLS work despite the user's explicit decision that lkjscript does not plan to support TLS.

Long-term performance is a primary product property.

Optimize architecture before constants.

Use independent full oracles to make aggressive incremental optimization trustworthy.

No TLS implementation belongs in this campaign.

Cold broad index construction reconstructs the current graph.

Cold orientation loads the root and all module references.

The current logical root owns an ordered set of module references in one root object.

A local module change therefore changes a root representation whose cost grows with total modules.

The current canonical store uses one content-addressed immutable module object per module version.

That is acceptable at current scale but is not automatically the best million-module physical design.

- 100,000 declarations per module;
- 2,000,000 retained identities or tombstones in a container;

- 4,096 dependencies;
- 65,536 targets;

- 10,000,000 transaction work;
- 100,000 affected owners;
- 64 MiB packed module objects;
- 128 MiB packed global objects;
- 4 MiB CLI responses;
- 16 MiB transaction request files.


A plausible high-level structured change may contain:

```json
{
  "base": "current revision or exact session-bound revision",
  "changes": [
    {
      "create": "module",
      "as": "$app",
      "name": "app"
    },
    {
      "create": "function",
      "as": "$main",
      "module": "$app",
      "name": "main",
      "parameters": [],
      "result": {"type": "text"},
      "body": {"text": "hello"}
    },
    {
      "create": "test",
      "module": "$app",
      "name": "main_returns_hello",
      "actual": {"call": "$main", "arguments": []},
      "expected": {"text": "hello"}
    }
  ],
  "mode": "commit"
}
```

The final schema should be more exact than this sketch.

It should not mirror Rust enum layouts mechanically.

It should allow typed request-local symbols.

It should provide exact selectors for existing owners.

It should expose preconditions.

It should return the normalized change digest.

It should return allocated stable identities.

It should preserve deterministic ordering.

It should never make the JSON itself accepted program authority.

A plausible stdio flow, only if measured and selected, is:

```text
client -> handshake
server -> binary/schema/capability identities
client -> open exact project
server -> repository and revision
client -> context request
server -> bounded context plus handles
client -> prepare change
server -> normalized change and predicted result
client -> commit prepared handle
server -> accepted revision and compact receipt
```

The session must not invent implicit mutable state.

Every request and response remains exactly attributable to a revision and repository.
