## Design and proof obligations

Development version v0.1.58 / deployment discovery contract 6 adds
`pkg_<32 lowercase hex>/req_<32 lowercase hex>` to the existing string field.
Unique legacy names remain accepted. Names are resolved against the complete
selected component, never against the unmatched remainder. Exact and named
selectors of the same requirement reject as duplicates. Unknown, unused,
malformed, missing and ambiguous selections reject before secret lookup or
live preparation. Static admission, stream relationship checks and preparation
must use exact references; redacted observation must not collapse equal names.

The descriptor's JSON shape, artifact/package/graph/data formats, per-grant
operations/limits/sharing domains, and resource-provenance rules are unchanged.
No operator descriptor or running application is implicitly rewritten.

Required evidence includes public package/draft identity discovery, detached
execution with copied native binaries, same-name obligations writing to distinct
durable roots, reversed descriptor order, exact duplicate/foreign rejection,
absent test-only secret sentinels, unchanged rejected stores, and the existing
public package ownership/HTTP cases. Complete fresh acceptance remains distinct
from focused feedback and from testing final distribution bytes.
