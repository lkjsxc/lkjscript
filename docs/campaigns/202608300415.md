## 4. Target contract and design decisions

### 4.1 Public grammar

Add exactly one normalized query action:

```text
query neighborhood OWNER --direction incoming|outgoing|both \
  [--depth N] [--kind KIND] [--limit N] [--bytes N] [--continuation TOKEN]
```

Mandates:

- `OWNER` is one exact live owner in the selected root package.
- `--direction` is required. `incoming`, `outgoing`, and `both` are the only values.
- `--depth` defaults to `1` and accepts canonical integers `1` through `4`.
- `--kind` optionally selects one exact current relation kind.
- `--limit`, `--bytes`, and `--continuation` retain the normalized query page meanings and bounds;
  do not create synonyms.
- `context` remains a rejected predecessor action. Do not add an alias, fallback, environment
  switch, hidden compatibility mode, or second request format.
- Discovery, generated operations, response fields, diagnostics, and examples must be owned by the
  executable registry and its generators.

### 4.2 Neighborhood semantics

Use deterministic breadth-first traversal over committed relation witnesses at one pinned accepted
revision.

- Include the root owner at minimum distance `0`.
- Expand only same-package owner endpoints whose current minimum distance is less than the requested
  depth.
- For `outgoing`, follow edges whose source is the expanded owner; for `incoming`, follow edges whose
  target is the expanded owner; for `both`, use the deduplicated union.
- Apply the optional relation-kind filter before adding an edge or neighbor.
- Package endpoints and foreign-package owner endpoints are emitted as boundary relation endpoints
  but are never recursively expanded by this operation.
- Assign each included same-package owner its shortest selected-path distance. Cycles and diamonds
  must not duplicate an owner or edge.
- Emit only edges encountered while expanding owners below the depth boundary. Do not inspect or
  imply unscanned edges beyond that boundary.
- Reuse the current normalized owner projection and relation projection. Add only the selector,
  distance, page, closure-summary, and work fields required by this operation. Do not duplicate the
  full `inspect owner` representation or expose storage bytes.
- Canonical logical order is all owners by `(minimum distance, encoded owner key)`, followed by all
  edges by the current canonical encoded relation key. The root is therefore first.
- A complete selector result is capped at the existing maximum normalized-query logical item
  admission across unique owners plus unique relations. Detect one-item overflow and fail with a
  stable resource diagnostic; never silently truncate the selected closure or issue a continuation
  for an incomplete closure.
- Page limits and output-byte limits may divide the canonical complete result. A page boundary must
  not change membership, distances, or order.

This operation is read-only. It must not advance `HEAD`, write canonical objects, create or mutate a
query index, persist a cursor/session/frontier, populate a cache, rewrite a witness, or modify a
maintained artifact.

### 4.3 Stateless continuation and contract cutover

A continuation must bind at least repository, package, exact revision, neighborhood operation,
root, direction, depth, optional relation kind, ordering contract, and exclusive logical resume key.

Each page may recompute the bounded neighborhood from the immutable revision and resume over the
canonical logical key. Do not serialize an unbounded frontier or visited set into the token and do
not create server-side state.

The normalized query grammar, selector domain, operation tag domain, and continuation behavior
change. Advance the one canonical normalized-query contract identity exactly once, including its
owned magic/domain constants where required. Reject predecessor query-contract tokens directly; do
not retain a dual decoder. Do not advance unrelated semantic, graph, artifact, deployment, package,
runtime, adapter, or release-format contracts.

### 4.4 Failure behavior

Provide stable, actionable classified failures for at least:

- missing or non-live root owner;
- malformed or foreign owner identity;
- missing/invalid direction, depth, relation kind, limit, or byte bound;
- malformed, oversized, noncanonical, integrity-invalid, foreign, stale, selector-mismatched, or
  predecessor-contract continuation;
- neighborhood item/read/output admission exhaustion;
- one projection that cannot fit the requested byte page;
- canonical/witness disagreement or missing required data; and
- cancellation where the current query boundary supports it.

Every failure must leave accepted semantic authority, generated maintained assets, and external
state unchanged. Do not return a success summary for an incomplete closure.
