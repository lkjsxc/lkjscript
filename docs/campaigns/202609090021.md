## 2. Strategic choice and useful result

Named rank-1 function values, graph-owned `list-fold-left`, code-complete offline packages, pure tail
execution, and checked values now provide a credible foundation for reusable functional libraries.
What is missing is runtime environment binding. Today a configured reducer must thread configuration
through its state/callers or use a separately authored wrapper; it cannot simply retain configuration
and satisfy the existing reducer function type. This is an interface/composition limitation, not a
claim that the underlying calculation is impossible.

Add explicit prefix binding rather than a second anonymous-body representation. Ordinary named graph
functions remain the body authority. Also add graph-owned standard
`function-compose<A,B,C>(outer: Function(B)->C, inner: Function(A)->B) -> Function(A)->C`, implemented
with a private generic graph helper and `bind`, never a Rust intrinsic. This permits reusable reducer,
predicate, projection, and callback factories while reusing existing function types and invocation.

The principal witness is a runtime-configured reducer:
`step(scale,bias,state,item) = state + scale*item + bias`.
A factory returns a bound `(state,item)->state` after its own frame has disappeared. Folding
`[1,2,4]` from zero with `(scale,bias)=(3,5)` returns **36**; a separately retained closure with
`(-2,1)` returns **-11**. Composition must capture other function values, not only scalar literals.

This outranks another collection-copy optimization now because it removes a missing abstraction
rather than further improving an already expressible fold. Collection copying remains a credible
measured follow-on, not an acceptance obligation. Explicit generic capture constraints or richer
lexical authoring may follow only when their own limitations justify them.

Preserve arithmetic, evaluation order, exact identities, existing noncapturing calls, package
visibility, task/port authority, and service behavior. Non-goals: anonymous lambda bodies, automatic
free-variable capture, mutable environments, argument holes/reordering, task closures, broader
affine lifetimes, generic constraint inference, JIT/AOT, collection redesign, application features,
new targets, public releases, and deployment.

## 3. Fixed language and execution contract

### Meaning, typing, and order

Add one canonical expression operation `Bind { callee, arguments }`: `callee` is an expression ID;
`arguments` are ordered expression IDs for a prefix of its parameters. No embedded body, environment
object, code address, or captured runtime value enters accepted meaning. Extend ordinary child,
scope, relation, projection, and change ownership, not a side table editable as another program.

For a pure function value of type `Function(P0,...,Pn-1)->R`, binding k arguments requires
`0 <= k <= n` and exact types `P0..Pk-1`; the result is
`Function(Pk,...,Pn-1)->R`. No coercion, inferred generic application, overload, or new function-type
family is introduced. Empty binding preserves the function without an environment allocation;
complete binding returns a zero-argument function, not the result of executing it. Existing named
values supply explicit rank-1 type arguments; resolve them in the current substitution before the
value escapes. Preserve generic scope, ordered-instantiation, and polymorphic-recursion rejection.

Evaluate the callee first, then supplied arguments exactly once left-to-right. Do not execute the
target during binding. Invocation evaluates its callee and remaining arguments in the existing order,
then calls the exact target with stored prefix followed by those arguments. Rebinding concatenates
prefixes in that order; it does not create a dispatch-wrapper chain. Creation captures immutable
values, not references into locals, a substitution map, or the creator's frame. Returned closures
remain usable after that activation ends and may be shared and repeatedly invoked.

Binding's effects are precisely those of evaluating its callee and capture expressions. Task code
may capture ordinary results obtained through its already declared capabilities; that does not make
the resulting callable effectful. Binding a task target is forbidden, including empty binding and
inside port preparation. Preserve the existing separately authorized task-port binding mechanism.
Never let its context exception leak into a public pure function value.

### Deliberately bounded capture subset

Capture-safe stored types are ordinary scalar data, including `StaticText`, and records, variants,
lists, maps, options, and results whose stored members are recursively capture-safe, plus pure
function values whose environments satisfy this same rule. Inspect every nominal field/case,
including absent affine cases. A function type is a callable leaf for this predicate: its argument
and result types are not stored captures. Exact callable purity and environment validity remain
mandatory at construction/admission.

Reject secrets, streams, live resources/transactions/leases, capability resources, and any aggregate
containing them. `affine-free` alone is not a capture-safety certificate. A stored type parameter
whose capture safety is unknown rejects at declaration validation; do not invent implicit generic
constraints or defer this semantic error to execution. Type parameters inside a function signature
are permitted because the captured value is the checked pure callable, not a future argument.
Thus generic `function-compose` is supported, while an unconstrained generic factory capturing a
bare `T` is explicitly outside this slice. Closed explicit instantiations and generic helpers with
capture-safe concrete prefixes remain supported. Publish this restriction and test it; it is not
permanent language policy.

Closures are runtime-only, non-serializable, and have no semantic equality. They may occur in ordinary
transient data where function values are admitted, but cannot enter durable literals, external value
encodings, operational stores/queues/backups, or retained session state. A constant may evaluate pure
binding code under existing constant rules; it must not serialize the evaluated environment.
Function-returning internal calls are supported; existing command/result encoding restrictions remain.
Aggregate equality must not bypass callable non-equality. This adds neither map authoring nor new codecs.

### Checked representation, lifetime, and limits

Use one public-pure-callable path: exact prepared-program target identity, fully resolved type
arguments, and an immutable flat bound prefix; named function values have an empty prefix. Environment
storage is derived execution state. Sharing is allowed; mutation, process-global closure registries,
caller-supplied certificates, and serialized environments are not. Preserve package provenance:
an exported factory may return a closure over its private helper, but consumers cannot directly
resolve that helper in violation of visibility. Linked code/source closure must include it.

Both evaluators need their own construction/admission and invocation logic. The canonical reference
must derive binding, target resolution, substitutions, capture checks, and calls from accepted owners,
not compiler instructions or production certification/flattening helpers. Neutral carriers may be
shared, not the decisions whose agreement is being tested.

Construction may perform one bounded, iterative capture-retention admission. Count environment edges
in the existing depth-256 admission rule; apply existing cumulative item/allocation admission rules
to captures and admission work, including new environment metadata. Capture slots are collection
items. Retain the existing limits: 1,000,000 collection items, 268,435,456 allocated-accounting bytes,
10,000,000 VM instructions, 4,096 live frames, 1,000,000 operands, and 100,000 capability calls, with
independent reference work units. Retain narrower adapter/decoder limits. Canonical prefix size also
cannot exceed actual remaining arity or the existing 100,000-child bound. Do not raise limits to pass.

Check cancellation at every visited capture node, before installing an environment, and on invocation/
tail transfer. Charge before growth, retain failed progress, and dispose rejected or deeply nested
raw environments stack-safely. Capture admission is a construction cost, not permission to readmit
retained environments at every local read, argument transfer, or invocation. Preserve the checked-
value no-recurring-descendant-guard invariant. Immutable sharing should survive invocation; do not
reconstruct an environment or copy a captured list payload merely to call it. Existing ordinary
algorithmic/copy/accounting costs are not claimed eliminated.

Extend the existing per-tier observations with capture-admission node visits, keeping them distinct
from input/raw-result admission and actual instruction counts. Include equivalent hidden eligibility
work in the cost oracle. Raw ingress to this pure-callable path must validate origin, target purity, exact
substitutions, prefix length/types, suffix signature, capture contents, and limits before installation.
A declared function type or an affine-free flag cannot bypass this boundary.

An eligible pure tail `invoke` of a bound function transfers directly to its ultimate graph target
with the complete arguments. Binding and evaluating captures are not tail calls. Preserve cumulative
accounting, original return continuation, transaction/affine ancestors, and non-tail frame limits.
Constants, tasks, and closed externals keep their existing outgoing-tail eligibility rules.

Wrong typing/capture is a semantic rejection before publication; malformed loaded code is corruption;
runtime origin/admission violations, exhaustion, cancellation, and target traps retain their owning
failure classes and actionable bounded diagnostics. A failed bind installs no closure and executes
no target; later capture expressions do not run. Already completed effects of earlier expressions
retain their actual visibility. Only a real enclosing transaction can roll back its staged work.
Failure never advances semantic HEAD, returns success evidence, or leaks owned execution state.
