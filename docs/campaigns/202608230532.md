transaction, accepted HEAD, and receipt object. Reuse of a key with a different base or transaction
is a typed conflict.

parent receipt. It also point-reads the physical root before accepting it. Historical
reconciliation performs one exact persistent-map lookup, loads and cross-checks the original

## Initial architecture decisions

1. The first source cutover boundary is a typed executable contract registry under
   `src/platform/contract/`. Parser dispatch, capabilities, schemas, generated references,
   diagnostics, exit mappings, limits, magic values, and digest domains must share that owner.
   Public request schemas use narrow `schemars` derives with explicit stable names and independent
   executable decoder tests.
2. Graph 5 will use normalized stable-ID owner records, package-plus-owner exact references,
   content-addressed structural type objects, stable expression records, and one deterministic
   relation extractor. It will not wrap `MeaningModule`.
3. The physical prototype compared the retained 10,000-module object population as loose files,
   one sorted immutable footer-index pack, and target-sized packs plus a rebuildable catalog. The
   implemented result uses target-sized immutable packs plus a compact rebuildable catalog; the
   path-heavy evidence catalog is not production code.
4. The normalization prototype selects exact package-plus-owner references and derived witnesses:
   stable rename and move change only the selected record and the mechanically affected witness
   paths, not exact use records.
5. No backward reader, edition flag, public alias, TLS work, JIT, network registry, or destructive
   garbage collection is authorized by this campaign.
