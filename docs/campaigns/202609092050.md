## 2. Selected outcome, leverage, and invariants

The capability delta is distribution, not invented language semantics: a user of the public binary,
without a contributor checkout, can reuse separately authored generic libraries that retain safe
runtime configuration, return private graph-backed callbacks, compose through exact offline packages,
and transform substantial runtime lists under existing defaults. Today the source contains these
mechanisms, but the supported public snapshot and its transferred admission do not deliver that
whole boundary. Existing route-pattern, service, worker, session, and data behavior must survive.

This is a good stopping point because exact package closures, tail-space control, checked values,
explicit environments, persistent lists, and constrained generic environments now compose into a
useful library-development model. The concrete broken publication path makes release work a product
limiting-boundary repair, not administrative tidying or release-by-commit-count.

The strongest next language alternative is parametric nominal data: reusable graph-owned data
abstractions would complement the new factory abstractions. Broader affine protocols are another
credible dependency for richer applications. Neither belongs in this release: each expands its own
semantic and migration boundary, while an already completed compositional core still needs honest
public availability. JIT and application development have no selected measured or semantic necessity
here. After closure, reassess one representative public workload for reusable nominal data or richer
state/resource composition; that is a contingent horizon, not additional acceptance.

Keep these invariants throughout implementation and adaptation:

1. One accepted typed semantic graph revision remains the sole editable program-meaning authority.
   Authoring, inspection, packages, compilation, artifacts, and execution use its existing path.
   Release metadata and verification receipts cannot grant semantic permissions or edit meaning.
2. Preserve the completed capture-safe contract: explicit constraint authority and scope; complete
   candidate validation; direct and named instantiation checks; exact type, effect, package, origin,
   and resource provenance; raw runtime admission; and independent canonical reference derivation.
   Empty unsafe containers and unused constrained parameters do not bypass checks. Capture-safe
   does not imply equality, serialization, durable/session retention, or authority to retain a handle.
3. Preserve deterministic evaluation and failure order, callback ordering, resource accounting,
   cancellation, alias preservation, cleanup, and actual transaction visibility. No live-effect
   replay, per-consumer hardcoding, monomorphic substitute, or hidden host implementation may stand
   in for a graph-owned generic library.
4. Keep maintained standard and lkjournal meaning, owner continuity, unchanged type/data bytes, and
   existing operational authorities. No new semantic generation or application-data migration is
   needed merely to publish this source. Do not revive predecessor production readers.
5. Public identities remain immutable. Preserve the existing target policy, release owner,
   no-checkout write-isolated publication job, trusted handoffs, and independent download admission.
   No second target, registry, installer, deployment, live-data migration, or application feature is
   selected. No new language primitive is needed for release orchestration.

Private factoring, helper shapes, local algorithms, coherent commit boundaries, and directly necessary
repairs are Codex's decisions. Use substantial implementation changes when necessary to satisfy this
contract, not to pursue independent redesign. A new safety contradiction or genuinely different
objective requires a precise incomplete record; routine engineering judgment does not.
