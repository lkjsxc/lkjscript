## Changes

The public process wrappers share an eagerly registered termination owner. Both
signals are installed before deployment preparation or `ready`. Registration
failure remains explicit, before live adapters, secrets or listeners are opened.
Foreground diagnostic compatibility is retained; `resident_signal` is added to the
authoritative registry and its derived references.

HTTP transport drain and resident shutdown are joined concurrently. A signal asks
the transport to stop accepting while resident drain/cancellation can release its
active requests. Early transport completion also triggers resident cleanup. No
new detached cleanup task, grace-period increase or effect replay is introduced.
Previously the transport awaited all requests before the operation that could
cancel those requests was even started.

Structured-session stop is a private monotonic owner. It retains a request even
with zero subscribers and tests the retained value for each new wait. An upgrade
or initial writer can no longer require a second stop request merely because it
subscribed late. Parent ownership, phase validation and reader/writer joining are
unchanged. The five direct unit cases cover absent and late subscribers, pending
clones, cancelled waits and repeated requests after completed waits.

The public suite uses an ordinary native fixture, copied product executables,
empty PATH, removed authoring graphs, loopback ephemeral listeners and signals
sent only to owned unreaped child PIDs. It covers SIGINT and SIGTERM immediately
after readiness for HTTP, worker and interactive runners, admitted infinite HTTP
work, and an actual upgraded peer left connected during shutdown. Successful
cases require one stopped event, successful exit and zero remaining tasks,
permits and session scopes. Connected sessions must complete, not merely fail
and disappear. A separate native web-editor case retains committed revisions and
stale-write rejection through two SIGTERM stops and a final SIGINT control.

## Compatibility and delivery boundary

No graph, package, artifact, deployment or durable-data format changes. No quota,
stack, concurrency, session phase, authorization, origin, secret or conditional-save
rule is relaxed. Synchronous preparation is not made preemptible. Forced process
termination and crashes cannot promise cleanup; stopping does not imply rollback,
retry, automatic replacement, migration or live backup.
