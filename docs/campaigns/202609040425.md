## 4. Target contract

### 4.1 Authority and identity

Add one stable semantic owner kind for an inbound HTTP route. Each route has a durable ID, is owned
by one exact root-package HTTP target, and stores one method, path, and exact port reference. A
supported method/path/port update preserves route identity.

An HTTP target owns one component and one nonempty finite route set. It has no universal, default,
fallback, or hidden port. Every current non-HTTP runner retains its exact single-port contract. A
route port belongs to the target component, is function-backed, and has the exact current HTTP
function type. The component requirement closure remains authoritative for its handlers.

The graph owns route membership, keys, relations, and application behavior. Artifacts carry a

### 4.2 Public authoring and inspection

non-HTTP runners and forbid it for `http`; generated discovery must state the conditional rule.

Add exactly:

complete topology from `minimal`. Setting changes one existing route without replacing its ID.

### 4.3 Matching, bounds, and failure

A method is a nonempty valid HTTP token of at most 32 ASCII bytes. Equality is byte-exact and
case-sensitive. A path begins with `/`, is at most 16 KiB, and contains no query or fragment. Match
the adapter's existing validated path bytes exactly: no percent-decoding, Unicode normalization,
case folding, slash collapse, or dot-segment resolution.

One target admits 1 through 4,096 routes and at most 4 MiB of aggregate method-plus-path bytes.
Check arithmetic before allocation or publication. Canonical order is unsigned method bytes then
unsigned path bytes. Authored operation order changes neither semantic identity, artifacts,
inspection, nor behavior. Duplicate pairs reject even when they name the same port.

Transport validation precedes one exact lookup. Query text and decoded parameters do not select a
route. There is no implicit method, trailing-slash, percent-spelling, or path-case match. A matched
`HEAD` route invokes its own handler and retains current body suppression; unmatched `HEAD` is not
mapped to `GET`.

An unmatched valid pair yields semantic status 404, no application headers, and an empty body. It
invokes no graph function or capability, creates no resident task, and closes or drains the body
through bounded transport ownership. Existing malformed/excess, overload, cancellation,
disconnect, handler/response failure, and shutdown classifications remain. A selected handler runs
at most once; visible effects are never replayed.

Graph validation, packages, compilation, strict artifact loading, preparation, and both dispatch
paths reject zero routes, excess, duplicate/invalid keys, foreign owners, ownership drift, wrong
component/shape, a route on non-HTTP, an HTTP universal port, or a missing non-HTTP port.
