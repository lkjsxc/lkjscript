## Outcome and strategic choice

Make ordinary **task function tail calls use constant additional control space**, preserving exact effects, authority, transaction continuations and invocation-owned resources. Use that mechanism to deliver a graph-owned `task-iterate` combinator whose callback decides whether to continue with a new state or finish with a result. Replace the maintained task fold's divide-and-conquer workaround with direct sequential tail iteration.

Before: pure tail calls can replace their activation, but task functions always retain it. The new effect-polymorphic task library can traverse a known list using range splitting, yet a natural data-dependent task state machine accumulates frames. The current 4,096-frame policy is an operational bound, not a sensible bound on the number of sequential iterations.

After: an author can write self-recursive, mutually recursive or bound-callback task loops, including across admitted package boundaries, without accumulating a frame for each terminal transition. A reusable library callback can return either the next ordinary state or a final value, based on configuration, data or application logic; it needs no preconstructed list or host-defined application loop. Calls with real pending return work retain that continuation. Control-space guarantees do not imply constant payload memory, unlimited execution, resource refunds or a scheduler.

Why now: the preceding campaign supplied explicit rank-one effects, authority-free task descriptors and task fold/map. Its implementation deliberately left task tail execution out and introduced logarithmic range recursion to work around that absence. Removing this restriction makes those mechanisms compose more naturally and retires a concrete workaround. The mechanism remains useful without the witness, game experiments, or relay experiments.

The strongest rejected alternative is broader affine resource abstraction: public/cross-package borrow and result protocols would remove real restrictions, but require a larger lifetime and failure transition and are not prerequisites for ordinary effectful state iteration. Further CI optimization is not selected: the public-pair change already removed duplicate aggregate work, and its first hosted public observation is still due. Recursive nominal data is already delivered. Neither deserves reimplementation.

Reverse this choice only if the actual checkout already provides the complete outcome, or a concrete counterexample shows that the specified control transfer changes authority or observable resource/transaction behavior. Reconcile already implemented work and finish its missing proof; do not redo it. A local algorithm correction is permitted with a recorded reason and refreshed affected proof. A fundamental counterexample blocks dependent changes, not unrelated safe progress.

Scope includes both evaluators, derived tail admission, standard-library graph cutover, public discovery and package composition, tests and existing receipt readers, generated assets, specifications and integration. It excludes new effect syntax, resource-polymorphic signatures, resource-returning functions, anonymous capture, dynamic continuations, async scheduling, expanding ordinary-type recursion, new platforms, fuel-default changes, and a new verification/orchestration system.

## Design contract

### Tail positions and the production transfer

All ordinary pure and task graph function bodies are tail contexts. Preserve existing propagation through selected `if` branches, the body of a `let` after its ordered initializers, the last expression of a sequence, and the selected arm of a variant match. Arguments, conditions, initializers, earlier sequence members, constructors, projections and scrutinees retain their pending work. A transaction body has a commit/rollback continuation; its call cannot discard that continuation. A helper called from inside an ancestor's transaction can still have its own terminal transitions.

Support direct calls and `invoke` to exact graph functions, including self/mutual recursion, explicit rank-one type/effect applications, fully and partially bound descriptors, and admitted package boundaries. Ordinary type-recursion validity remains unchanged. The callee expression is evaluated first and its remaining arguments once left-to-right; direct-call arguments also evaluate once left-to-right. Resolve and admit the complete target application and captured prefix before any outgoing frame is discarded. Do not reread/replay effects or reevaluate arguments on fallback.

Use the existing derived normalized tail dispatch. Continue to derive it from strictly validated code and canonical callable kind; never serialize an author-controlled tail bit or add a special loop opcode. Generalize graph-call eligibility without conflating a graph task with an external or a port expression. Retain linear reverse-edge terminal analysis; charge its metadata/work and check cancellation under the existing preparation policy. Follow effect-specialized prepared clones and calls so a base function's proof cannot certify the wrong closed application.

At a successful graph tail transfer, preserve the caller's original return continuation and operand base, replace the outgoing activation with the callee's locals and exact substitutions, and install the callee's own declared allowance. No discarded locals, lexical maps, old substitutions, allowance stack entries, native recursion frames or tracing history may accumulate per transfer. Checked internal values can retain existing sharing; do not rescan a captured tree on every iteration.

Task-to-pure transfer removes task permission for that pure activation. Pure-to-task remains invalid, including a task with an empty requirement set. Calls to closed externals keep their normal execution/admission path; their tail position must not turn an external into a graph activation. Constants, tests and port-expression entry wrappers retain their entry contracts; called graph functions receive the new guarantee internally. Task-only execution does not become accepted by pure `run`.

Required space claim: for a fixed finite prepared program and fixed non-tail nesting/cleanup depth, an arbitrarily longer admitted chain of terminal graph calls has constant additional live call/control frames, local slots and substitution/allowance state. Bound application payloads separately. Do not claim guaranteed termination, constant total allocated bytes, or a speedup for IO.

### Authority is checked before the outgoing context disappears

Preserve the existing separation between a declared row, an authority-free callable descriptor and actual canonical component grants. Check each task target against the **outgoing activation's** closed allowance and the actual canonical grant mapping, before replacement. Operation admission thereafter uses the callee's row. Do not widen a narrow helper from the surviving ancestor/root, from a matching alias alone, or from all grants present in the component.

The production `dispatch_call` already orders task admission before `call_code` discards the frame. Preserve that property for both direct and indirect transfer, including resource transfer and exact prepared origin checks. Remove redundant pure-only gatekeeping at `TailInvoke`; do not bypass normal call validation.

The reference evaluator needs an explicit internal handoff: resolve the target, type/effect applications, arguments and task-row/grant admission while the outgoing canonical scope is active. Return a construction-controlled admitted tail target, or equivalent bounded internal transition object, to the trampoline. Enter that exact callee without reauthorizing it against the now-visible ancestor, and install its own independently derived allowance. Bind the handoff to target/application/preparation and checked arguments. It is neither a callable value nor an externally loadable proof, carries no new grant, and lasts for one transition. Normal calls still use normal admission. Do not use a boolean bypass that raw entry or unrelated calls can invoke.

The reference implementation must continue deriving tail position and signatures from canonical owners rather than consuming production tail annotations, indexes or admission proof. Share semantic contracts, not the algorithm that is supposed to independently verify them.

### Transactions, resources, failure and accounting

Keep the invocation's resource table, task identity, capability quotas, call counters, transaction map and generation identities intact across transfers. A tail call neither starts a new task nor resets any quota. Cumulative allocations and work remain cumulative without refunds; removing an unexecuted return/jump means it is not counted as executed work. Check cancellation independently of profiling, including immediately before replacing an activation. Admission/allocation failure produces no successful transition or result.

The current invocation-owned resource model permits unused affine rights to be dropped. Dropping their local descriptor performs no external operation and does not remove the resource table entry or free resource admission capacity. Therefore a valid task's unused affine local is **not by itself a reason to reject or disable tail transfer**. Preserve the actual underlying lifetime and accounting; never acknowledge, fail, close, release or duplicate a lease merely because its frame disappears. The pure activation's no-affine-authority invariant remains independently enforced.

For an already admitted final `consume` direct-call parameter, finish unrestricted arguments first, commit the same exact transfer once, validate live scope/interface/requirement provenance and install the right in the callee. A later failure does not restore the caller's right. This does not relax current private/same-package/acyclic resource-signature rules or allow resource callbacks, captures, containers or results. A task that has consumed its last local resource may also transfer normally.

Do not discard an owned transaction or any genuine post-call cleanup continuation. Valid calls beneath such a continuation remain ordinary calls; they are not new source errors. A falsely certified terminal call with residual operands, mismatched ownership or omitted cleanup is corruption and must be rejected at its owning boundary. An ancestor transaction retains its exact owner and sees all nested loop operations; commit happens once at the original lexical exit, rollback follows existing reverse-order failure handling, and forbidden nested transactions still reject.

Callback traps, cancellation, work/allocation exhaustion, grant exhaustion and malformed results stop later steps. Earlier nontransactional effects retain possible visibility; enclosing transactional staged effects roll back according to the existing owner. Never turn runtime failure into the loop's normal `done` value or silently retry a callback. A user-returned `Result` remains ordinary typed data. Invocation completion/shutdown releases invocation-owned resources at the established point; an intermediate observation may legitimately show live table entries, so do not fabricate zero-resource evidence at each transfer.

If startup discovers an actual frame-owned observable destructor absent from the inspected model, retain its continuation and document the counterexample before widening that case. Prove or repair that owner; do not quietly change cleanup timing or impose a permanent blanket resource-signature exclusion.

### A general graph library, with complete public authoring

Add a public standard nominal family and graph function, using the current authoring conventions and stable newly allocated identities:

```text
iteration-step<State,Output> = continue(State) | done(Output)
task-iterate<State,Output; E>(
    initial: State,
    step: TaskFunction(State) -> iteration-step<State,Output> ! E
) -> Output ! E
```

This is semantic notation, not new CLI syntax. Discover and use the executable's exact compact records. `iteration-step` is an ordinary parameterized variant, with separate ordered type parameters and stable case identities. `task-iterate` invokes `step(initial)` once, matches its result, returns the payload of `done`, or tail-calls itself with the `continue` payload and the same step. An immediately completed iteration therefore invokes its callback once. There is no built-in maximum-iterations parameter, implicit exception conversion, scheduler, automatic yielding, or precomputed collection. All current operational admission/cancellation policies still apply.

Do not add capture-safe bounds to `State` or `Output` just to implement the combinator. They are ordinary arguments/results subject to existing type and containment rules; the descriptor has its already admitted environment. If a client chooses a callable-containing transient state, retain its existing non-durability/non-equality rules. The variant gets ordinary nominal behavior only where its concrete members allow it; do not invent special serialization or effect semantics for its case names.

Preserve public standard `task-fold-left` and `task-map` identities, signatures, exact callback order and failure semantics. Replace the range-splitting fold body with a private sequential index/state tail loop that uses the original list without slicing or copying its prefix. Empty fold/map still invokes no callback. `task-map` remains graph-owned fold plus persistent append. Do not force the fold through a closure capturing unconstrained item/state types and thereby narrow its public accepted types. Remove superseded private range-only production topology through the maintained graph writer; preserve all unrelated owner identities.

The standard graph and its exact exported transport/artifact remain the owners of built-in meaning. Locate their actual accepted writer through `GraphRepository` and the maintained fixtures; `contributor.rs` is not a generator.
