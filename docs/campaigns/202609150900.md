## 2. Decision, useful workload and limits

**Before:** existing requirement-parametric libraries are capable but authored as flat expression
assembly. The retained producer has 145 nonempty lines, 41 expression definitions and 20 expression
argument edges; the consumer has 273, 88 and 63. Those are reported source counts, consistent with
the inspected literal files. They demonstrate repeated assembly work, not authoring-time,
model-token or billing measurements.

**After:** the same libraries can be authored and edited through the distributed executable using
nested expressions, explicit applications and lexical locals. Unchanged declarations and parameters
retain identity during body replacement. Equivalent supported flat/block requests normalize to
the same intent, commitments and reviewed candidate. The language graph remains the sole semantic
authority; a saved request is a proposal, not a synchronized source file.

The principal workload is an ordinary typed persistent-cell library. It reads/decodes a key in
a caller-owned store, invokes a caller-supplied transformation, encodes and conditionally writes
inside its lexical transaction, and provides a pure factory returning a bound updater. A consumer
uses I64 and Text, configuration-reading callbacks, different store requirements and a supplier
update. Preserve the actual algorithm, whole-requirement substitution and explicit T/E/R
constraints. Also express the existing transported DurableQueue helper's acquire/match/borrow/consume
body to discriminate scope and affine composition. These are designed witnesses, not existing
adoption claims. The language repository gains an authoring mechanism and maintained proof, not a
new application product.

The thesis is to remove incidental input assembly at the existing `AuthoredExpression` boundary.
The incumbent provides identity, inspectability, complete validation, review and repair. Structural
notation keeps those outcomes while removing per-occurrence labels and indexed expression edges.
Its cost is one bounded input adapter, source mapping, discovery and focused parity/negative tests.
It must not become a second compiler, independently editable authority or host application-policy API.

The strongest materially different alternative is **observable transaction completion**. Existing
proof shows a true primary conditional-write result while an auxiliary false condition causes no
transaction publication. An ordinary library cannot safely infer durable success from the primary
flag. That is a real future capability gap. Structural authoring remains selected because it
reduces recurring work across these libraries and was already selected at unchanged main. Keep
`UpdateAttempt<T>` honest: candidate data and the primary condition's result are not a commit
certificate. Do not introduce implicit retry or change transaction behavior here.

General affine transfer and floating-point/numeric support remain possible future capabilities.
Neither is a prerequisite for the selected authoring outcome. No change to resource signatures,
numeric types, execution engines, daemon architecture or platform matrix belongs in this campaign.

Mandatory scope is all **22 current public expression forms**, public creation/body replacement,
diagnostics, compatibility and combined delivery. Declarations, signatures, types, effects,
requirements and dependency selection keep their current explicit forms. Flat requests remain
supported for exact low-level authoring. Two input notations resolving into one authority are
intentional; no forced retirement of the flat notation is selected.

Coverage of all forms does not mean that lexical names alone reproduce every identity-addressed
flat graph without alteration. A flat body can reference an earlier same-named binder after it
has been shadowed; bare structural names select the nearest binder. Such exact editing remains
available in flat requests. Do not add a binder-addressing escape or silently rename semantic
binding Names merely to overclaim universal flat/block identity parity. New ordinary programs can
choose distinct names where both values are needed.

The revisable next-few-campaign hypothesis is: make current libraries practical to author and
distribute; then evaluate a concrete committed-update API against observable transaction outcomes;
consider structural declarations or editable projections only after observing the remaining prelude
and edit burden. Resource transfer needs a caller policy that actually requires ownership across
a library boundary. These are hypotheses, not an authorized feature queue.

Reconsider the implementation if early parity or admission work disproves a premise. Repair a
narrow actual mismatch while preserving the outcome. A semantic/storage redesign must be named
and justified with a transition, not hidden as parser work. If a serious independent blocker
prevents credible completion, preserve useful isolated work and release accepted requirement
libraries alone; report structural authoring as incomplete. Do not renew its release deferral.

## 3. Resolved public and architectural contract

### 3.1 Input boundary and grammar

Add the following **new syntax to implement** to the existing
`change plan --input-file` / `change apply --input-file` path:

```text
expression.block as=$body
  (call $add (local $parameter) (i64 3))
expression.end
```

The header has exactly `as` and exports one ordinary request-local expression root. The body
contains exactly one parenthesized expression, over one or more physical lines. The closing marker
is an otherwise empty standalone `expression.end` line, allowing surrounding whitespace.
Reject stray/missing markers, nested block headers, duplicate roots, extra fields, a second body
expression and trailing tokens. A marker/comment spelling inside a quoted string is literal data.
An incomplete expression at the marker rejects; it is not reinterpreted as outer records.

Outside blocks, preserve current compact-record framing, escaping and error behavior. Route
multiline handling through change-input framing. `control/compact.rs::parse_records` also validates
responses; do not inadvertently admit blocks in compact responses or unrelated consumers.

Inside blocks use ASCII whitespace and parentheses; `;` starts a comment through the physical
line end outside strings. Literal text requires double quotes and the existing compact escape
rules, including Unicode validation. Unescaped physical newlines/control characters in strings
reject. Identifiers use existing portable `Name` rules, not a new quoted-identifier language.
Typed selector/type/row atoms reuse current lexical spellings and decoding rules. No arithmetic
operators, precedence, bare literal shorthand, inferred applications or implicit function lookup
are introduced.

The selected forms are below. Capitalized metavariables describe grammar, not literal tokens.
`EXPR` is a nested expression; `TYPE` and `ROW` are existing type/effect references.
Member/declaration/requirement positions retain current typed aliases and exact selector rules.

| Meaning | Structural syntax |
|---|---|
| Unit | `(unit)` |
| Boolean | `(bool true)`, `(bool false)` |
| Integer | `(i64 42)`, with the existing I64 range and parsing contract |
| Text / static text | `(text "value")`, `(static-text "value")` |
| Local value | `(local NAME)`, `(local $parameter)`, or `(local (exact LOCAL_SELECTOR))` |
| Constant | `(constant DECLARATION)` |
| Conditional | `(if CONDITION WHEN_TRUE WHEN_FALSE)` |
| Sequence | `(sequence EXPR...)` |
| Direct call | `(call FUNCTION APPLICATIONS EXPR...)` |
| Named function value | `(function-value FUNCTION APPLICATIONS)` |
| Dynamic invocation | `(invoke CALLEE EXPR...)` |
| Prefix binding | `(bind CALLEE EXPR...)` |
| Sequential let | `(let (binding NAME (type TYPE) INITIALIZER)... (in BODY))`; each `(type TYPE)` is optional |
| Nominal record | `(record DECLARATION TYPE_APPLICATION (field FIELD EXPR)...)` |
| Structural record | `(record structural (field NAME EXPR)...)` |
| Variant | `(variant CASE TYPE_APPLICATION)`, optionally with exactly one payload expression before the final close |
| Projection | `(field EXPR FIELD)` for a nominal selector; `(field EXPR (name NAME))` for a structural field |
| List | `(list TYPE EXPR...)` |
| Map | `(map KEY_TYPE VALUE_TYPE (entry KEY_EXPR VALUE_EXPR)...)` |
| Match | `(match SCRUTINEE (arm CASE BODY)...)`; payload arm: `(arm CASE (payload NAME TYPE) BODY)` |
| Capability call | `(capability-call REQUIREMENT OPERATION EXPR...)` |
| Transaction | `(transaction REQUIREMENT (binding NAME) BODY)` |

`APPLICATIONS` is zero or one each of `(types TYPE...)`, `(effects ROW...)`,
`(requirements REQUIREMENT...)`, in that order before value arguments. Omission means an empty
vector, not inference; explicit empty clauses are equivalent to omission. Duplicate, unknown,
out-of-order and misplaced clauses reject. `TYPE_APPLICATION` is only an optional
`(types TYPE...)`. Preserve the distinction between a concrete requirement and `parameter:$R`.
Existing type/effect/requirement rules decide arity, constraints, visibility and validity.

The current flat decoder already admits maps despite a stale compact-slice exclusion in
`docs/spec/language.md`. Include maps and correct that sentence at its owner. Other current
semantic constraints, including empty sequences, field uniqueness, exhaustiveness and affine
eligibility, continue to be decided by the existing semantic owners.

For example, with the existing declaration/reference prelude, a proposed factory body is:

```text
expression.block as=$factory-body
  (bind
    (function-value $update
      (types @FactoryT)
      (effects @FactoryE)
      (requirements parameter:$factory-R))
    (local $factory-space)
    (local $factory-default)
    (local $factory-transform))
expression.end
```

This is a selected syntax example, not an executed program. The current
`create.function ... body=$factory-body` attaches the root. Retain the actual complete prelude
and independent algorithm in the acceptance fixtures.

### 3.2 Ownership, delayed references and lexical scope

A block root has the same exactly-once expression-use rule as an ordinary flat root. It may be
consumed by an outer change or a flat parent expression wherever that role is valid. Reject unused
or multiply consumed roots. A block cannot splice a separately defined flat expression into its
interior. Its nested expressions and lexical bindings are private, including against guessed
request labels. Reject outer `expression.argument`, `type.argument`, binding/field/arm or other
edge records that try to extend a block root or reach its private children. Edges owned by a genuine
surrounding flat parent remain valid.

Keep whole-request delayed resolution: a block may refer to a function, parameter, type, effect
or requirement alias declared later in the request, exactly as the existing flat adapter permits.
All public references, including unused bindings, retain their current complete validation.
Resolve through `ReferenceLookup` and typed intent; do not create an alternate package/name resolver.

Bare `(local NAME)` resolves only in the current block's lexical environment. It never falls
back to a public label or a guessed exact ID. `(local $parameter)` uses the existing explicit
typed reference route. `(local (exact LOCAL_SELECTOR))` is the explicit exact-reference route.
`LOCAL_SELECTOR` is a currently accepted exact local identity spelling (`param_...` or
`bind_...`), subject to existing kind and scope validation. Names resembling those spellings
remain ordinary lexical names when used without the explicit wrapper. The `(name NAME)`
wrapper similarly disambiguates structural projections.

**Permit sequential and nested shadowing.** Resolve a let initializer in the preceding environment,
then introduce that binding for subsequent initializers and the body. A same-spelled outer/earlier
binding is visible during the new initializer; the new binder cannot refer to itself. Unbound
self/forward references reject. On scope exit restore the enclosing binding. Each binder has a
distinct identity. Match payloads exist only in their own arm body; transaction bindings only in
their transaction body. No cross-block lexical capture or implicit closure is introduced.

This deliberately corrects the preceding mandate's same-let duplicate-name prohibition.
`kernel/namespace.rs` excludes lexical binding Names from the package namespace; current graph
validation checks identity and scope, not same-let Name uniqueness. Do not convert an earlier
assistant's proposed notation restriction into a language law.

Every syntactic expression occurrence receives a distinct owned expression, even when two
occurrences read the same local. Only let binding supplies evaluated-once value reuse. Preserve
left-to-right field/map-entry/argument/sequence order, callee-before-arguments order, selected-branch
evaluation, lexical transaction meaning, task/pure distinction, explicit substitutions and affine
provenance. Do not sort record fields or map entries during parsing, share expression nodes, perform
implicit common-subexpression evaluation, infer grants, attenuate whole requirements or retry effects.

### 3.3 Canonical parity and private symbols

For flat/block requests representing the same normalized authored tree, preserve identical
canonical authored-intent bytes, request commitments and prepared candidate on the same base.
The comparison includes operation order, preconditions, typed reference inventory, semantic Names,
optional annotations, explicit applications, budgets and publication options. Formatting, comments
and request-local label spellings are not semantic inputs. Changed literals, real Names, argument
order, selectors or applications must retain their proper commitment differences.

The concrete implementation constraint is inspected:
`decode_expression` emits `AuthoredExpression.symbol = Some(...)`; the codec serializes that
optional tag, then symbol kind and traversal ordinal. `None` children break parity. Symbol
collection traverses authored structure; canonical bytes seed allocated identities. Generate
`Some` symbols for every nested occurrence and a unique symbol for each lexical binder, preserving
the current traversal/domain order. Keep semantic binder Names and absent/present annotations:
these are encoded and cannot be normalized away for convenience. Transaction binder
`declared_type` remains `None`.

Private symbols must be valid under existing symbol validation, deterministic and collision-free
throughout the request. Their spelling must not become public addressing syntax. A special prefix
alone is insufficient: public users can already spell legal prefixes. Keep original user-authored
labels/references distinct from generated identities until resolution is complete; user text never
resolves against a generated-label inventory. Export only the root to the public expression
namespace. A separate internal node/reference representation is recommended. A string-based
approach must carry origin/visibility and prove equivalent isolation. Do not reserve formerly valid
public spellings or synthesize a flat text buffer whose private names become addressable.

Retain the canonical codec when these conditions hold. Do not erase its optional-symbol distinction,
change allocation order or force comparisons to pass by weakening the independent oracle. Flat-plan
and structural-apply interchange under the same current executable is required when all normalized
inputs match. This is not a promise that predecessor executable review tokens remain current.
