## 1. Outcome and strategic decision

Make public-release acceptance distinguish **independently obtaining and admitting each delivery route** from **executing the complete application suite for the same admitted executable**.

Before: the public job anonymously obtains exact-tag and latest assets, validates their provenance, then serially extracts and runs all five behavioral owners against each route. Only afterward does it compare the two archives, checksums, manifests and executables. The same job therefore schedules ten complete behavioral-owner executions for byte-identical release content.

After: independently acquire, authenticate, strictly extract and exercise a small real command lifecycle through **both** routes; establish complete content equivalence; execute the existing five-owner suite **once, freshly, within that same pair invocation**; and bind that evidence explicitly to the second admitted route. Preserve independent pre-publication acceptance, exact-target admission and source-full verification. A shared behavioral observation must never masquerade as a second fresh execution.

This is a bounded change to the existing release verification owner, not a general CI cache, new scheduler, substitute type checker, or new campaign framework. The language executable's authoring, semantics, graph/artifact/data formats and runtime behavior do not change.

## 3. Design contract

### 3.1 Claims and trust boundaries

For each route R in {exact, latest}, retain independently established:

- A(R): the route was actually downloaded anonymously; selected tag/source, immutable release, asset identities/digests and release/asset attestations were accepted by the existing workflow owners.
- V(R): that route's own checksum/archive passed the strict first-party verifier and produced an independently created extraction with admitted manifest, executable, modes and static-linkage facts.
- S(R): that extraction's executable actually completed the small route lifecycle below, with its own fresh project and successful cleanup.

Let E mean byte equality of **both archive files, both checksum files, both canonical manifests and both executables**, together with matching admitted modes and relevant execution policy. Let B mean one freshly completed, fully reread five-owner behavioral aggregate for the exact extraction in this pair invocation. New public acceptance requires:

`A(exact) AND A(latest) AND V(exact) AND V(latest) AND S(exact) AND S(latest) AND E AND B AND clean`

The contributor command owns V/S/E/B and clean. It must not claim to have proved anonymous HTTP acquisition, GitHub authenticity, or publication merely because it received two local directories. A complete public-delivery claim additionally needs A from the existing hosted steps and successful overall job completion.

Sharing is confined to one running pair operation in one controlled environment, with a fixed candidate, verifier, target policy and workload inventory. It is **not** cross-run cache reuse, reuse of pre-publication results, reuse from a previous attempt, or equality of version strings. Cross-route sharing has a distinct evidence disposition. Retain exact-source full, six-owner target admission, fresh pre-publication five-owner acceptance and all substantive behavioral cases.

This preserves the named semantic obligations and strengthens explicit route/fault accounting; it does not claim identical statistical detection probability for intermittent faults after removing a second sample. Preserve existing procfs/descendant race regressions and add the focused cancellation/recovery coverage below. Never justify weakening cleanup by saying the repeated run was redundant.

### 3.2 One implementation owner and a concrete contributor interface

Extend the existing `release transferred` owner. The following interface is **new work**, not an existing command:

```text
lkjscript-dev release transferred pair-run
  --exact-assets ABSOLUTE_DIRECTORY
  --latest-assets ABSOLUTE_DIRECTORY
  --tag TAG --commit SOURCE_COMMIT --publication release|dry-run
  --evidence-root ABSENT_ABSOLUTE_DIRECTORY
  --verifier-identity ABSOLUTE_FILE
  --expected-verifier-sha256 SHA256 --expected-verifier-bytes BYTES

lkjscript-dev release transferred pair-verify
  [the same identity, input and evidence-root arguments]
```

`pair-run` owns execution. `pair-verify` rereads existing evidence and executes no applications. Keep existing `run`/`verify` for pre-publication, diagnostics and old single-boundary evidence. Do not repurpose their schema-1 records into shared proofs. Keep the single `ORACLES` production inventory and each owner's receipt reader; do not add a parallel role list to production.

Each input directory contains the existing target-owned archive name and `SHA256SUMS`, not user-selected arbitrary filenames. Require separate canonical absolute directories and independent regular input files; reject symlinks, path aliases, shared-file aliasing and pre-existing output roots. Bind byte lengths/digests and relevant modes. Route roots need not contain source, Cargo, checkout paths or inherited application state.

`--publication release` requires both manifests' release mode and selected exact tag/source. `--publication dry-run` is a deliberately labelled **local pair rehearsal**, not an anonymous-public or public-delivery pass. It permits end-to-end rehearsal without publishing a new version. Dry-run and release evidence are not interchangeable, and the release workflow must hard-code release mode. The existing verifier handoff's source/tag/hash validation is not relaxed or reinterpreted to pass a rehearsal.

Use an internal module under the existing transferred owner if size warrants it. Refactor narrow Rust helpers for strict extraction and typed summaries rather than copying archive validation or encoding semantic acceptance in shell. Production contributor logic stays in Rust. No Python, external acceptance database, reusable success-token service, or generic evidence planner.

### 3.3 Execution sequence and frozen inputs

1. Validate the externally expected verifier handoff, input paths and identities. Create a private absent evidence root, record incomplete state before candidate execution, and install the existing owned cancellation/supervision lifetime.
2. Independently run the existing strict archive/manifest/static admission for exact and latest. Use separate create-new extractions and retain each route's own typed facts. Reuse validation code, not one route's successful observation as the other route's observation.
3. Establish E by bounded streaming comparison after both strict admissions. Digests are identities, not a reason to skip comparing admitted bytes here. A same-tag different asset is a mismatch, not a fallback-success case. Two identical malformed archives must fail before sharing is considered.
4. Run each route's small lifecycle directly through its own extracted executable, not a third common copied executable. Validate actual capabilities against that route's manifest. Use separate private scratch/project roots and the existing supervisor; retain actual commands, outputs, durations and cleanup.
5. Execute the existing five-owner suite freshly against the exact extraction, with its current per-child scratch/data/HTTP/TLS isolation and its complete typed receipt validation. For release-mode pairs, that child aggregate retains `exact-download`; for dry-run pair rehearsals, use the existing `pre-publication` child boundary, with the pair explicitly labelled local rehearsal. Never pass a dry-run manifest to the existing release-only `exact-download` boundary. Reference the actual aggregate from the pair evidence; never write a fabricated latest five-child aggregate.
6. Reobserve **both** routes' inputs/extractions and the verifier before and after each expensive child, and before terminal acceptance. Bind all identity/equality facts again at completion. Preserve bounded work, output, timeouts and cleanup classifications. Do not use a whole-archive allocation where streaming suffices.
7. Atomically publish a complete pair receipt only after all required facts and cleanup pass. Read it back through its strict reader before returning success. Any changed input, child failure, unavailability, incomplete receipt, cancellation, timeout, output exhaustion or incomplete cleanup remains non-passing. Retry into new owned roots; preserve failed attempts.

Do not claim resistance to arbitrary hostile host mutation from pre/post hashes. This remains the existing trusted isolated-runner model with drift detection, not a filesystem sandbox. Inspect any behavior-bearing sidecars, dynamic loads, environment, working-directory or executable-location dependencies before asserting equivalence. Static ELF equality alone is insufficient if another unbound dependency can affect execution. If such a dependency exists, explicitly bind/normalize it within this owner or block sharing.
