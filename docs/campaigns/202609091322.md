## 2. Strategic choice and scope

The language now has code-complete packages, constant-control-space pure tail calls, checked value
propagation, and explicit pure environments. Its next leverage is making ordinary output-producing
composition affordable, not adding another application-specific adapter.

At this baseline, `NormalizedValue::List` is `Arc<Vec<NormalizedValue>>`.
`vm_checked.rs::Value::append` allocates and copies the complete previous vector;
`vm_intrinsics.rs::Machine::call_checked_intrinsic` charges `len + 1` collection slots for
`core.list.append`. The canonical reference has corresponding full-vector append and charging.
Building N elements by repeated append therefore copies N(N-1)/2 existing element occurrences,
before accounting for other work. This is a source-derived cost mechanism, not a measured speedup.

Explicit generic capture constraints are the strongest semantic alternative: they would let a
factory retain an otherwise unconstrained stored T. Select list construction first because the
already available higher-order language can express useful transformations but repeatedly rebuilds
their output. This result benefits independent batch, parsing, rendering, and state-transformation
consumers. A new mapping witness proves usefulness, not existing adoption. Richer capture constraints
and broader persistent collections remain contingent follow-ons, not acceptance obligations.

The outcome comprises one runtime-list cutover and one graph-owned standard `list-map`. Do not add
map/filter opcodes, a mutable builder language, task callbacks, implicit capture, generic constraints,
new collection types, map-storage optimization, fusion, native execution, an application feature,
a release, or a new campaign harness. Preserve evaluation order, ordinary list eligibility, exact
package visibility, semantic publication, and supported data/code encodings.

## 3. Fixed semantic and runtime contract

### Public composition

Add the standard pure function with this semantic signature, using existing authoring forms:

`list-map<Input, Output>(items: List<Input>, mapper: Function(Input) -> Output) -> List<Output>`.

Its implementation is ordinary graph meaning: invoke existing `list-fold-left` with an empty
output list and a private generic step that invokes the mapper and calls existing `list-append`.
Use existing `bind` to retain only the mapper in that step. Function signatures containing type
parameters are already capture-safe leaves; this does not admit capture of a bare unconstrained T.
Keep explicit rank-one instantiation and all existing List/function/effect restrictions.

Evaluate caller arguments in ordinary left-to-right order. Invoke the mapper exactly once per item
in ascending index order, never on an empty list. Append each successful result in that order.
A trap, cancellation, or exhaustion stops subsequent callbacks and yields no successful partial
list. Do not fuse nested maps in a way that changes callback or failure order. For total callbacks
with sufficient budgets, `list-map(xs, identity) = xs` and
`list-map(xs, function-compose(f, g)) = list-map(list-map(xs, g), f)` hold by values,
not pointer identity. Task functions are not admissible mappers, even for empty input. Callables may
remain ordinary transient list elements where already supported; this creates no callable equality,
serialization, session-retention, or resource-containment permission.

A useful witness maps runtime `[1, 2, 4]` through a configured `x * 3 + 5` callable, obtaining
`[8, 11, 17]`. Retain the original and branch the result into separately appended versions; none
may change another. Also exercise heterogeneous mapping and an exported factory over a private
helper after its producer is removed. An invalid mapper signature rejects before accepted
publication; an overflowing callback fails at execution without publishing a partial result.

### One persistent runtime carrier

Replace flat-vector list storage with a bounded 32-way persistent index trie and a tail of at most
32 elements. Use shallow shared immutable element handles and path-copy only the changed spine;
appending must not recursively clone an existing element's payload. This selected representation
is an engineering decision, not new accepted meaning or permanent language policy.

Require O(1) logical length and handle sharing, O(log_32(N+1)) indexed access, O(N) ordered traversal,
and O(32 log_32(N+1)) worst-case append slot work with old roots retained. Small tail copies are
permitted; copying or visiting the complete prefix above that bounded tail is not. Do not rely on
unique ownership, reference-count luck, an unshared-only fast path, or a hidden mutable builder to
satisfy the append claim. Indexed access may be more expensive than the former contiguous lookup;
measure that trade-off. This is not a claim of constant-time append or universally faster programs.

The carrier owns structural validity, length, height and immutable sharing, never type, origin,
affinity, capture eligibility, or semantic identity. Internal tree levels do not add language value
depth. Lists remain logical flat sequences for equality where admitted, iteration, inspection,
encoding and observations. Node shape, capacities, pointers and sharing never enter a semantic digest,
artifact or operational-data encoding. No mutable or serialized tree authority is introduced.

Carry this representation through both evaluators, locals, calls, environments, aggregate values,
closed intrinsics, decoders and resident boundaries. Do not flatten/rebuild at ordinary intrinsic,
call, return, capture-invocation, length or lookup boundaries. A necessary contiguous external-buffer
conversion is explicit, bounded and measured; codecs should traverse directly when possible.
Private bounded bulk construction from raw items is legitimate, not a second public list mechanism.
Remove the old whole-vector append implementation from checked and generic/raw intrinsic dispatch.

The canonical evaluator must retain independent owner interpretation, typing, affinity, capture,
call and accounting decisions. It may share the neutral carrier; that sharing means VM/reference
agreement alone cannot prove sequence storage. Retain a small independent flat-Vec model and fixed
expected values for the decisive storage claim. No reference fallback may become production.

### Resource accounting and failure

Keep existing default limits: 10,000,000 VM instructions, 4,096 live frames, 1,000,000 operands,
268,435,456 cumulative allocated bytes, 1,000,000 cumulative collection items and 100,000 capability
calls. Preserve independent reference work units and the existing depth-256/raw-admission rules.
Keep a checked logical list-length ceiling under the existing collection bound; sharing must not
admit an arbitrarily large logical list for free.

Replace the list-specific `len + 1` allocation charge with a documented deterministic schedule for
new storage: newly reserved/copied element-handle and branch slots count as collection items;
node/header/refcount storage, capacity and new handle metadata count as allocated bytes. Charge
before allocation/growth, conservatively including unused reserved capacity. Untouched shared
subtrees are not newly allocated. The schedule cannot depend on observed reference counts and
never refunds cumulative charges. Raw ingress still charges and validates logical occurrences,
including repeated shared children; separately account newly owned metadata. Preserve all other
collection accounting. This expressly changes representation-dependent list costs, not the limits
or the obligation to account for real work.

Maintain independent cancellation checks during bounded construction/traversal and before result
installation. Checked length, index, capacity and byte arithmetic must precede growth. Failure leaves
all old aliases intact, releases temporary nodes/operands/frames, and allows a healthy subsequent
invocation. Raw foreign-program values, hidden affine children and absent affine variants still
reject through their actual admission boundaries; a shared node is no safety certificate. Preserve
stack-safe disposal of over-depth rejected values, including shared list leaves.

Pure execution never advances semantic HEAD. In task callers, an already completed external effect
retains its actual visibility; only a real enclosing transaction rolls back staged work. Do not
replay effects through the reference evaluator. No list change authorizes operational-data rewriting.
