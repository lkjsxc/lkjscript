## 2. Fixed outcome and semantics

construction-controlled affine classifications for admitted values, so ordinary local reads and
function calls never walk those values' descendants to rediscover affine eligibility, while every
raw ingress and every affine ownership boundary remains validated through the distributed product.**

### Authority and eligibility

Accepted graph meaning still owns types, nominal identities, effects, parameter use, calls, and
exact requirement bindings. Runtime classifications are disposable derivations, never authored
annotations, serialized certificates, artifact flags, or another program authority. Deployment grants
and operational data, queues, and object stores retain their distinct authorities; none selects HEAD.

Distinguish unrestricted affine-free values, direct affine capability handles, and affine nominal
variants. A nominal variant admitting a direct capability-resource payload remains affine in its
empty case. Actual payload absence does not make `QueueLeaseState.absent` unrestricted. Containers
cannot hide direct handles or affine variants, even empty ones. Affine-free does not mean durable:
secrets, streams, other runtime resources, and function values retain their separate restrictions.

For already admitted values, affine classification costs constant work per local/argument,
independent of descendant count and nominal case count. Direct, indirect, generic, cross-package,
ordinary, tail, and closed-external calls use the same guarantee. Arity, exact type substitutions,
effects, live-handle scope/generation/interface/requirement checks, and capability accounting remain
mandatory; this is not constant work for every possible call operation.

Preserve strict evaluation order, selected branches, checked arithmetic, current tail contexts,
transaction ownership, and borrow/consume rules. Only an authorized exact capability operation can
acquire a handle. Final consume transfer does not restore caller ownership after failure. Matching
consumes the affine outer owner; ordinary cloning must never duplicate it. No new affine container,
resource result, task-tail transfer, signature form, or source-level rejection is selected.
