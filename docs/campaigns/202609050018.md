## 5. Target contract

### 5.1 Authority and identity

A stable route stores exact method, exact port, and one typed selector: `exact` literal path or
`pattern` canonical literal/capture segments. Selector, segments, capture names/order, specificity,
and port binding are accepted graph meaning. Display strings, compiler matchers, prepared indexes,
capture vectors, and observations are derived; deployment cannot alter routing.

Supported selector/method/port changes preserve route ID. The route-set digest binds kind, canonical
segments, capture order, and port identity. Preserve maintained IDs where normal `set.http-route`
permits. If product remains `0.1.21`, advance source to unreleased `0.1.22`; advance only contracts
whose owned bytes or behavior change. Keep deployment/unrelated identities stable and immutable
`v0.1.21` untouched.

### 5.2 Pattern grammar, matching, and bounds

A public pattern is UTF-8 beginning `/`. Each following segment is one nonempty literal containing no
`{`/`}`, or one whole capture `{name}` using a valid graph `Name`. No empty, trailing, mixed,
optional, wildcard, or catch-all segments; a pattern has at least one capture and names are unique.

Admit at most 64 segments and 32 captures per pattern and 65,536 stored pattern segments per target.
Retain current 16 KiB path, 4,096-route, and 4 MiB aggregate ceilings; check arithmetic before
allocation/publication. Exact paths retain current syntax and may contain braces as exact bytes.

A capture matches one nonempty segment of the validated path spelling. Perform no percent/Unicode
decoding or normalization, case folding, slash collapse, dot resolution, trailing-slash equivalence,
or query selection. Captured `Text` is the exact segment spelling; the router infers no ID, integer,
UUID, alias, filesystem, or media meaning.

Methods remain exact. Different segment counts are disjoint. Equal-length patterns overlap when all
positions containing two literals have equal bytes. Overlapping `A` is strictly more specific than
`B` when every literal of `B` is the same literal in `A` and `A` replaces at least one capture with
a literal. Exact routes are maximally specific.

Allow overlap only when one route is strictly more specific; the unique most-specific route wins.
Reject identical match languages, capture-name-only variants, and incomparable overlaps at graph,
package, compiler, artifact, and readiness boundaries. Never use authored priority, insertion/source
order, owner ID, hash order, or Rust enum order.

### 5.3 Signature-indexed captures

An exact route keeps `(HttpRequest) -> HttpResponse`. A pattern with `{c1}` … `{cN}` requires its
function-backed port to resolve to `(HttpRequest, Text … Text) -> HttpResponse`, with exactly `N`
trailing unrestricted parameters named `c1` … `cN` in left-to-right order.

Independently validate route→port→function, parameter names/order/types, HTTP types, and requirement
closure across graph, package, compiler, artifact, and preparation. Invoke once with the request then
capture values in route order. Captures are ordinary non-resource `Text`. Pattern routes may share a
port only when capture-name sequences and derived contracts agree.

Do not expose an authoritative `Map<Text, Text>`, ambient router context, thread-local state, or host
callback. The full path may remain observational input, but migrated handlers consume indexed
parameters rather than reparsing it or consulting `id` query keys for selection.

### 5.4 Public authoring and inspection

Keep one route owner and existing operation names. Extend `add.http-route` and `set.http-route` so
exactly one of `path=EXACT_PATH` or `pattern=PATH_PATTERN` is present. Parse pattern transport
immediately into typed canonical segments; do not store an arbitrary template string as authority.

Plan/apply report selector, captures, overlap/specificity effects, derived handler contract,
preserved/changed owners, impact, selected tests, and commitment. Apply rederives under the
publication lock; stale, altered, malformed, ambiguous, foreign, exhausted, or signature-mismatched
work advances nothing.

Executable discovery owns fields, grammar, limits, diagnostics, and result shape. Route inspection
exposes kind, segments/captures, method, target, component, port, handler, and derived signature.
Target inspection exposes exact/pattern counts, route-set digest, and maximum specificity chain.
Context uses ordinary route/parameter/port/function/component/effect relations; add no special store,
mutable cursor, source format, or application dumper.

### 5.5 Derived execution, failure, and resources

Compilation derives one deterministic matcher per target and binds each leaf to route, target,
component, port, function, captures, parameters, HTTP types, and requirements. Artifact loading and
preparation reconstruct and reject drift independently. Matcher representation is latitude, but an
ordinary request must not allocate or scan the complete route set; retain an observable finite
match-work bound from the prepared matcher.

Transport validation precedes segmentation/selection. Existing malformed/excess failures remain.
Unmatched valid input returns fixed empty 404, invokes no function/capability, creates no task, and
drains/closes the body under existing bounds. A match constructs all captures before one invocation.
Capture failure, overload, cancellation, disconnect, body/handler/response failure, and shutdown
advance no authority and release matcher, stream, task, and permit resources.
