## 5. Target state and fixed decisions

### 5.1 Authority and public authoring

The sole semantic authority is a new public standard interface named `HttpClient` with one task
operation named `get`. The operation receives only a bounded ordered header list and returns one
structural response containing status, ordered headers, and whole body bytes. It receives no URL,
host, scheme, port, path, proxy, trust toggle, secret name, or retry count from graph code.

The exact endpoint and all transport policy are selected by one deployment grant and its concrete
`http_client` adapter. Application code may select response handling but cannot broaden destination
or trust authority. The existing inbound HTTP server adapter and its contract remain distinct.

Add one closed public recipe:

```text
lkjscript new DEST --template nostr-relay-info [--name NAME] --relay-url URL
```

`--relay-url` is required only for this recipe and rejected for the other recipes. Accept an exact
Nostr `wss` locator or its `https` NIP-11 form; normalize `wss` to `https` before deployment. Permit
`ws`/`http` only for the explicitly loopback-only development policy and normalize `ws` to `http`.
Preserve any path and reject user information, query, or fragment. This normalization does not
implement WebSocket. The created project contains ordinary typed graph meaning, one exact built-in
dependency, one `HttpClient` requirement, the existing inbound HTTP/byte-stream requirement, one
`serve` target, graph-owned tests, and a strict starter descriptor. No artifact or second editable
format is introduced.

The application exposes `GET /relay-info`, calls the configured endpoint with
`Accept: application/nostr+json`, and returns an exact bounded status-200 body when the response's
case-insensitive base media type is `application/nostr+json` (valid parameters may follow).
Transport failure, non-200 status, or another media type becomes deterministic local 502 without
remote body or provider detail. It stores nothing and makes no closed-schema claim: NIP-11 permits
omitted and unknown fields, so the slice transports the bounded document.

### 5.2 Endpoint, DNS, TLS, and SSRF policy

The adapter contract must make these decisions executable and discoverable:

- The endpoint is immutable for the grant. Only `http` and `https` are recognized. Public
  destinations require `https`; plaintext `http` is allowed only under an explicit loopback-only
  policy for deterministic local development and proof.
- Hostnames are bounded canonical ASCII DNS names. Reject credentials, fragments, queries,
  ambiguous authority, malformed ports, noncanonical escapes, and unsupported schemes before
  readiness. Do not read proxy variables or ambient resolver/configuration files beyond the system
  DNS service and operating-system networking required for the exact endpoint.
- Address policy is explicit and closed for this slice: `public_only` or `loopback_only`. Resolve at
  request time, cap the result count, reject the entire resolution if any address violates the
  selected class, and connect only to a validated resolved address without hidden re-resolution.
  Treat IPv4-mapped IPv6 consistently. Private, link-local, unspecified, multicast, and other
  non-global addresses are rejected by `public_only`; no private-LAN mode exists in this campaign.
- HTTPS verifies the endpoint hostname and certificate chain. Trust mode is exactly either the
  executable's pinned public WebPKI roots or one bounded named PEM root secret selected by the
  deployment adapter. Invalid, empty, oversized, expired, mismatched, or untrusted certificates
  fail closed. There is no insecure-skip switch, client certificate, platform-native TLS backend,
  or secret value in output/evidence.
- Use HTTP/1.1. Send one GET with no request body. Do not follow redirects, decompress content,
  persist cookies, use an ambient proxy, inject credentials, or automatically retry a request.
  Alternate validated-address connection attempts are transport establishment, not request replay,
  and must remain bounded by the same deadline.
- Reject graph-supplied `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Upgrade`,
  proxy authorization, authorization, cookie, and other transport- or credential-owned headers.
  The adapter owns `Host`, connection framing, and `Accept-Encoding: identity`.
- Give request headers, response headers, response body, DNS results, concurrent requests,
  connection time, total time, and cleanup separate positive limits with conservative recipe
  defaults and executable-discovered global maxima. Do not reuse the inbound-server limit record as
  an accidental universal scalar.
- Task cancellation, deadline expiry, inbound-client cancellation, runner shutdown, protocol error,
  and limit exhaustion close the connection and release the request resource. No partial response
  is returned as success. Repeated shutdown is idempotent and readiness is emitted only after static
  endpoint, policy, limits, and trust material are valid; readiness need not perform network I/O.

A GET may be observable by the remote operator. Classifying the operation as idempotent authorizes
no automatic replay and makes no claim that a remote implementation is side-effect-free.
