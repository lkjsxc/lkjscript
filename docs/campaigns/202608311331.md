This is an implementation-and-proof campaign, not another architecture survey.

**Final state:** `lkjscript-dev scale` is a current first-party semantic-scale harness driven through
the supported `lkjscript` executable. It no longer depends on deleted public commands, the legacy

deterministic scale-receipt contract 2, proves a fresh 100,000-owner current-authority lifecycle, and

The million-owner attempt is informative rather than a completion gate. It must finish as exactly
one of `completed`, `environment_limit`, or `not_run_with_reason`. Only `completed` permits a
million-owner capability claim.

## 3. Load-bearing current state and campaign selection

At the orientation baseline, the public binary exposes current `status`, exact owner `inspect`,
bounded `query`, reviewed `change plan` and `change apply`, `check`, and `build`. Finite public output
uses deterministic compact records.

The contributor scale harness is older than that surface. `tools/lkjscript-dev/src/scale.rs` still
owns scale receipt contract 1 and public change contract 3, serializes JSON requests, expects a JSON
envelope, invokes direct `change --commit`, and calls removed or changed operations including
`inspect project`, `query find ... --exact --limit`, `doctor --deep`, and project `backup`. Its
measurements therefore cannot be treated as current product evidence.

The repository roadmap asks for controlled 100,000- and million-owner evidence, but the first
dependency is a trustworthy current harness. The selected campaign closes that dependency before
choosing graph packing, history retention, or any data-store compaction work.

Strongest alternative: add authored owner-detail projection. It remains valuable, but the roadmap
requires a maintained edit proving that current summary plus context is insufficient. The stale
scale harness is already a concrete broken first-party consumer with a direct deletion and proof
story, so it wins this campaign.

## 4. Target state and decisions

### 4.1 One current harness

Keep one contributor command:

```text
lkjscript-dev scale <independent-modules|small-functions|wide-module|deep-chain|wide-fanout> ...
```

Preserve topology names unless the active checkout proves a current documented replacement already
exists. Remove internal compatibility with the old response and change formats.

The harness must:

- create a minimal project with the candidate executable;
- construct topologies through the current public compact change vocabulary;
- use the current plan/apply review path for every accepted update;
- read current state through supported `status`, exact `inspect`, and bounded `query` operations;
- run current `check` and `build` where required by the scenario;
- collect compiler, artifact, repository, response, wall-time, CPU, and peak-memory observations when
  the host exposes them;
- verify final logical counts through a read-only typed repository oracle that does not call the
  production result formatter;
- write raw command output only under the ignored artifact root; and
- publish one bounded structured receipt.

Do not write graph storage directly and do not use a private application builder as the measured
path.

### 4.3 Required 100,000-owner admission

Select one simple current-authored topology that reaches at least 100,000 live semantic owners and
exercises both modules and pure functions. Prefer `small-functions` distributed across enough

The required lifecycle is:

2. construct the topology in bounded reviewed batches;
3. perform one local rename through plan/apply;
4. prove status and exact owner inspection;
5. prove at least one bounded owner query and one bounded context or relation query;
6. run `check`;
7. run a clean build and an exact-current build;
8. prove the two builds agree;
9. compare public observations with the typed read-only oracle; and
10. remove the temporary project unless retention was explicitly requested.

Choose batch size from the current public limits. Record the exact value; do not raise public limits
for this campaign.

### 4.4 Million-owner capacity attempt

After the required admission passes, attempt one lightweight one-million-owner topology, normally
`independent-modules`. Limit this attempt to project creation, bounded reviewed construction,
`status`, one bounded query, one exact inspection, oracle comparison, and cleanup. Do not require a
full check or build for this informative attempt.

Before starting, record available local memory and free filesystem space. Use a campaign-owned
maximum wall time and local-space budget chosen from the actual environment. The final
classification is:

- `completed`: the one-million-owner logical state and public/oracle observations agree;
- `environment_limit`: the run stops at a measured local limit and leaves a valid bounded receipt;
- `not_run_with_reason`: the preflight shows the attempt cannot begin responsibly.

Neither non-completed classification is a million-owner admission.

with at least 100,000 live owners. The local rename advances accepted authority once; bounded reads
observe the final revision; check passes; clean and exact-current builds agree; the temporary

**SCALE-5 — Million-owner capacity classification.** The section 4.4 attempt ends with exactly one
supported classification and a complete bounded receipt. Documentation claims million-owner
admission only when the classification is `completed`.

**SCALE-6 — Authority and version closure.** Product and unrelated public contracts do not move.
Checked-in standard and `lkjournal` repositories and generated artifacts remain byte-identical. No
second fixture builder, result vocabulary, or current scale documentation owner remains.
