## 1. Outcome and architectural decision

An ordinary user must be able to install the supported Linux runtime with one copyable shell invocation, keep multiple exact runtime versions, explicitly choose the default, and recover without rebuilding the language or changing application data. Applications may pin an installed executable by its absolute versioned path. One installation runs multiple independent application bundles in separate processes.

**Before:** the executable already creates, checks, builds and runs programs outside its source checkout. Foreground artifact commands have source acceptance. The README still asks users to acquire the archive and checksums, verify, extract, and manually copy an executable; it supplies no managed version inventory, collision-safe activation, or recoverable selection protocol.

**After:** an immutable release-owned bootstrap acquires one exact archive, verifies its embedded digest, and invokes a Rust-owned local installation transaction. `runtime install`, `runtime list`, and `runtime select` expose a small, explicit installation boundary. Installed versions remain intact when the default changes. Failed installation or selection never exposes a partially copied executable. A running or explicitly pinned application does not switch runtimes when the default changes.

The thesis is **to make runtime selection explicit operational state, with immutable version slots and one atomic default pointer**. This completes access to existing language power; it is not a new program authority. Do not add a daemon, registry, automatic update service, project version file, implicit artifact-to-runtime resolver, runtime-embedding application builder, package-manager integration, extra platform, or application feature.

Why now: recursive nominal data, effect-polymorphic libraries, task iteration and foreground execution now compose into independent runnable applications. The preceding campaign deliberately made foreground execution the dependency for installation. Its accepted public witnesses provide a better installation oracle than a version-printing demo alone.

The strongest alternative is a general affine resource-library boundary. Actual `kernel/affine.rs::resource_function_parameter` still restricts direct resource calls to one final consume parameter in a private same-package nongeneric function. Simply lifting visibility would not make reusable libraries: an effect row does not select concrete capability operations, and the resource is bound to one exact requirement. Requirement abstraction and its lifetime semantics deserve a coherent later campaign. A readable authoring surface is another useful direction, but this inspection did not establish a specific new authoring failure that displaces installation. A new CI campaign is not selected without a new measured bottleneck.

Revisable trajectory:

1. Complete inherited foreground delivery and this installation/selection milestone. The decisive evidence is real anonymous installation and use of independent artifact applications.
2. Reassess ordinary public authoring against the same applications: unnecessary identity lookup, expression construction and diagnosis may justify a meaningful editing surface over the one graph authority.
3. Reconsider resource/requirement abstraction when a transported library must carry or borrow resources across its boundary; specify the general ownership rule before relaxing another special case.

This is an outlook, not permission to implement all three. Change selection only if startup shows the outcome is already delivered, a prerequisite is materially false, or a discovered correctness failure makes installation unsafe. Verify already delivered behavior and complete its missing proof instead of reinventing it. For a materially different necessary outcome, record the reason and the changed completion boundary; do not silently substitute a smaller feature.

## 3. Settled public interface and storage ownership

The following are **proposed commands to implement**, not commands verified on the inspected binary:

```text
lkjscript runtime install --archive PATH --sha256 HEX [--prefix PATH] [--activate]
lkjscript runtime list [--prefix PATH]
lkjscript runtime select TAG [--prefix PATH]
```

Use the existing strict CLI/discovery/diagnostic owners. `runtime` is project-independent. Reject `--project`, mixed project/runner modes, duplicate or unknown flags, missing values and invalid tags before installation mutations. Do not perform project discovery, load deployments, execute application code, read application secrets or acquire grants.

- Default prefix is the invoking user's absolute `$HOME/.local`. An absent/nonabsolute home requires an explicit absolute `--prefix`; never guess a system directory. An explicit prefix must be absolute and pass the path/ownership policy below. Do not use or modify `CODEX_HOME`.
- `PATH` is not edited. The result reports the actual default and pinned executable paths. Documentation includes the optional shell PATH step and makes successful installation distinguishable from whether an existing shell already searches `PREFIX/bin`.
- `TAG` is an exact canonical stable release tag `vMAJOR.MINOR.PATCH`, derived from the archive's product version and checked against its expected tag. Reject ranges, aliases, `latest`, prerelease spellings not supported by the current release owner, path fragments and environment substitutions. There is no semver compatibility inference.
- `HEX` is exactly 64 lowercase hexadecimal SHA-256 characters. It identifies the requested archive bytes; a caller-supplied digest alone is not an authenticity certificate.
- The only admitted installed target in this stage is `x86_64-unknown-linux-musl`, on supported Linux x86-64. Detect unsupported hosts and reject; do not silently fall back to a different binary.

Use this layout, with all metadata owned by the installation boundary:

```text
PREFIX/bin/lkjscript
PREFIX/lib/lkjscript/INSTALLATION.json
PREFIX/lib/lkjscript/installation.lock
PREFIX/lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/lkjscript
PREFIX/lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/LICENSE
PREFIX/lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/THIRD-PARTY-LICENSES.html
PREFIX/lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/RELEASE-MANIFEST.json
PREFIX/lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/INSTALL-RECEIPT.json
```

`PREFIX/bin/lkjscript` is the **sole selection pointer**, a relative symlink directly to `../lib/lkjscript/versions/TAG/x86_64-unknown-linux-musl/lkjscript`. Do not introduce a second `current` pointer or a second authoritative selected-version field. The root metadata identifies this installation format and its ownership; each immutable version receipt binds archive digest/length, manifest digest, product, target and retained payload digests. Those receipts are operational observations, not published provenance or graph meaning. Internal format discrimination belongs here and need not leak as a new product edition.

`runtime install` publishes the complete validated version slot and, only with `--activate`, selects it. Installation without activation does not change or create a default executable. Bootstrap passes `--activate`. Reinstalling the exact same archive identity is idempotent after revalidation. The same tag/target with differing archive, manifest or payload identity is a conflict, never an overwrite. A matching version with a corrupted installed payload is corruption, not permission to repair in place. Preserve the slot and provide the usable recovery action of installing into a new owned prefix.

`runtime select` only selects an already installed exact version after full retained manifest/payload/static-target admission. It does not download, install, search for a compatible version, run the selected binary, or touch applications. Return selected tag/path/digest, previous selection when present, and a retained manager-capable executable path for recovery. Selecting the current healthy target is idempotent.

Identify an installed recovery manager by equality with the invoking manager's executable digest, not a guessed minimum version or execution of arbitrary installed payloads. If a copied manager has not itself been installed, report its actual absolute invoking path as external/unmanaged and explicitly report that no retained manager slot was found. Do not falsely call that external path durable. Bootstrap activation returns the newly installed matching slot as its recovery path, never the temporary executable it will delete.

`runtime list` reads only installation state, orders entries by canonical tag and target, and reports exact paths, identity, declared archive publication mode and the pointer's current selection. It validates metadata and containment but must label full payload integrity as unchecked unless actually rehashed. A missing installation reports an empty unselected inventory without creating directories. Malformed state is a diagnostic, not an empty installation. Bound traversal and output explicitly with existing response principles; do not silently truncate. A large inventory may return a classified capacity error before success output rather than requiring a new cursor system in this stage.

Keep complete installed versions indefinitely in this campaign. No uninstall, garbage collection, overwrite/adopt flag, system installation, sudo, permission escalation, shell-profile editing or background updater is selected.

### 3.1 Atomicity, paths and recovery

Preflight prefix parents, reserved installation paths and default-pointer ownership before mutation. Ordinary preexisting `PREFIX`, `bin` and `lib` directories may coexist with unrelated files. A reserved product root without valid ownership metadata, a foreign symlink, a regular file at `bin/lkjscript`, a path traversing an unexpected symlink, or nonregular payload input rejects. Do not adopt a manually copied binary merely because it prints the right name. Explain the conflict and allow a different prefix. Validate existing path components with safe descriptor-relative/no-follow APIs where required; a check-then-follow sequence must not enable a path-substitution write outside the admitted root.

Use one OS-backed installation lock for mutating operations, with bounded acquisition or an immediate stable busy diagnostic. Do not busy-loop. Lock ownership dies with its process; a surviving lock file is not itself a held lock. Make competing first installs converge through the same lock/ownership protocol without deleting each other's directories.

Initialize a new product root with valid ownership metadata and its lock file in a private sibling, then publish that complete root with no replacement. A losing initializer opens and validates the winner. A killed first install must not leave an unmarked reserved root that all future attempts permanently reject. Subsequent mutations lock the established root; unfinished initialization remains an owned sibling stage, never an authoritative installation.

Snapshot the input archive to private owned staging while hashing it, then validate that exact snapshot. Do not hash one path and later reopen possibly replaced bytes for extraction. Reserve bounded storage before growth. Copy only admitted members into an absent staging directory on the destination filesystem, synchronize files and relevant directories, then publish the complete version directory once with no replacement. Keep the archive's four payload files and their bytes intact; the install receipt is a separate file.

Activation creates a private temporary relative symlink in `PREFIX/bin`, rechecks ownership under the lock, atomically renames it over only an absent or installation-owned pointer, and synchronizes the parent. The pointer must name either the old complete version or the new complete version. There is no in-place binary overwrite. Failure after version publication but before activation may leave a complete unselected version; report that exact partial operational outcome. Do not claim an all-or-nothing install-and-select transaction across these two commits.

An interrupted process may leave only its own identifiable staging material. Subsequent mutation under the lock may discard verified orphan stages belonging to this installation, or report precise cleanup needed; never delete another live stage or an installed version. Inject interruption and I/O failures around directory publication, pointer replacement and synchronization. After a post-rename synchronization failure, report the observed selection and durability uncertainty; do not pretend nothing changed. Broken stdout after a committed operation likewise does not reverse it. Preserve the primary failure and any cleanup failure.

Existing applications retain their running executable. Explicit versioned paths continue to select those bytes after activation changes. The default pointer is a convenience for future invocations, not a running-process migration protocol. A predecessor such as v0.1.32 has no `runtime` command: after selecting it, management/recovery must invoke the retained newer executable's absolute path, or rerun that newer version's immutable bootstrap. Do not rely on the newly selected old binary to understand management commands. Include this exact recovery in acceptance and documentation.

The path model protects installation ownership and concurrent ordinary operations. It does not claim protection from a hostile administrator or an attacker already controlling the same user's executable files and namespace.

## 4. Archive admission and a thin immutable bootstrap

### 4.1 One format owner, separate producer policy

The installation operation must be self-contained in the shipped Rust executable. It must not invoke Cargo, Git, Python, `lkjscript-dev`, a shell, `tar`, `gzip`, an ELF command, or a network client. Add a bounded native gzip decoder and SHA-256 dependency if needed, using the pinned manifest/lockfile, safe Rust and exact target admission.

Factor a small production-usable release-container owner out of the existing archive/model/static-ELF code. Preserve the current five-member archive: its top directory plus executable, root license, third-party notices and canonical release manifest. Preserve the one-line archive `SHA256SUMS` format. Reuse canonical member, digest and static-ELF invariants; do not copy a second subtly different parser into runtime installation. Move only format/integrity primitives and data models needed in production, leaving process supervision, building, receipts, hosted inputs, attestations and current publication policy in contributor tooling.

This boundary must distinguish **historical payload admission** from **current release-production policy**. The current `release/mod.rs::validate_manifest` pins the Rust toolchain, notice generator and downloaded tool digests. A perfectly valid retained older runtime must not become un-installable because a future manager uses a newer compiler or notice generator. The shared loader checks closed/canonical format, internally consistent product/repository/tag/source/mode identities, supported target, every member digest/length/mode, actual static ELF and bounded encoding. The release owner adds its exact current toolchain, packaging and provenance policy. Do not weaken that release policy while extracting shared logic.

Honor the current compressed/uncompressed/manifest limits (128 MiB / 256 MiB / 1 MiB) unless a measured real payload requires a deliberate changed admission. Reject traversal, absolute/foreign paths, symlinks/hardlinks, devices, unsupported extensions, duplicate or missing members, unexpected members, invalid modes, noncanonical metadata, truncated/checksum-invalid gzip or tar, decompression overrun and noncanonical trailing material. Bound decompression before allocation/write. An externally recomputed archive SHA must not make a malformed container valid.

Accept an internally valid locally supplied dry-run archive as explicitly **declared dry-run/unverified publication**, so the public local installer can be exercised before publication; never claim that a manifest's release label proves publication either. The generated public bootstrap must be for the actual published package identity. Differing dry-run/final archives under the same tag conflict in a shared prefix by design; pre-publication tests use disposable separate prefixes. Do not introduce a hidden admission bypass for tests.

Its literal fields bind repository, exact tag, target, archive filename, archive length/digest and expected executable digest. Do not generate it inside the archive or add its digest to bytes that determine its own embedded archive digest. Keep one source-controlled template/rendering owner and generated release assets out of source narrative.

The latest bootstrap URL resolves the only moving selection:

```text
https://github.com/lkjsxc/lkjscript/releases/latest/download/install.sh
```

Once that script is acquired, all archive acquisition uses its embedded exact-tag URL. The exact bootstrap uses `releases/download/TAG/install.sh`. The script accepts only `--prefix PATH`; the version comes from its immutable identity, not a second `latest` lookup or `--version` override. Reacquiring a newer bootstrap is the explicit additive update procedure.

Keep the script to POSIX shell acquisition glue: bounded temporary storage, platform/tool preflight, HTTPS-only curl including redirect protocol restrictions and disabled user curl configuration, complete-download/error checks, embedded literal archive SHA/length verification, extraction of only `lkjscript/lkjscript` to a privately created temporary regular file, executable digest verification, and invocation of that executable's public `runtime install --archive ... --sha256 ... --prefix ... --activate`. Native installation then independently admits the exact archive snapshot. Never extract the archive directly into the user's prefix with shell tar. Quote all paths, never eval user content, and clean owned temporaries on success and ordinary signals/failure.

Do not introduce a shell copy of transaction, manifest or ELF validation. Required bootstrap conveniences may include `sh`, `curl`, `sha256sum`, `tar`, `mktemp`, `chmod`, basic file utilities and `uname`; missing tools produce actionable failure, not automatic package installation. The installed native manager and subsequent application execution do not require these tools. Test both currently pinned userlands' actual shell/tool behaviors. A single copyable compound shell invocation may safely download the entire script to a private temporary file and execute it only after curl succeeds; prefer this to executing a partial download stream. Also document the download/inspect/run form. No script may edit shell profiles or silently use sudo.

Trust is precise: the initial bootstrap is executable code trusted through the selected GitHub HTTPS source (optionally an exact version), and the embedded digests bind subsequently acquired bytes to that bootstrap. A checksum in the same trusted script is not an independent signing authority. Keep authenticated release metadata/attestation checks separate from anonymous user acquisition. No new signing identity, credentials or trust registry is required.

If latest moves after bootstrap download, installation still acquires and installs that script's exact version. If its pinned asset is unavailable, fail without switching default; never fall back to another version. Bound network time/bytes and retries. Network retry is not agent status polling.
