# Evidence-gated roadmap

The semantic-development, `lkjwork`, and ordinary `lkjedit` verticals are implemented in the current
checkout. This file records reversal gates and named missing consumers. It is not a feature queue
and does not authorize ambient authority, compatibility paths, or speculative infrastructure.

## Semantic project and authoring

Full canonical snapshots plus compact revision records remain selected. Reopen storage only when a
representative maintained project exceeds 256 MiB before 1,000 revisions, optimized ordinary open
exceeds 5 seconds, deep doctor exceeds 10 minutes at 100 revisions, or path/backup count crosses a
named deployment limit. A replacement must preserve one publication owner, exact arbitrary history,
tombstones, unknown visibility, portable backup, hostile decoding, and a full reconstruction oracle.

All reads still hold the engine authority lock. Introduce immutable concurrent snapshot readers only
for a measured multi-client workflow after path substitution, snapshot lifetime, mutation
interaction, admission, shutdown, and deterministic response order are proved. A daemon, branch,
merge, or rebase is not a substitute.

Closed semantic queries, generated function proposals, exact local edits, fixed post-apply
continuations, known-digest replies, and the foreground project session are the selected authoring
surface. Expand continuation into requested subgraph deltas only if a frozen repeated-edit workflow
reduces total calls or bytes without more stale/correction failures. Add persistent query/target
indexes only after at least 20 percent complete-workflow improvement with bounded rebuild and simple
fallback. Whole-function replacement and full target validation remain independent oracles.

## Editor and rendering

The retained runtime representation is a persistent UTF-8 piece treap with immutable backing,
bounded chunks, structural sharing, byte/scalar/newline aggregates, and disposable grapheme
boundaries. Flat UTF-8 materialization remains the independent oracle. Reopen the structure only if
final equal-workload evidence still misses the interaction gate because of tree depth, compaction,
materialization, or grapheme-cache cost. A gap buffer won the isolated mutable microbenchmark but
lost because it cannot preserve immutable roots and cheap buffer undo without adding another owner.

Extended grapheme clusters are the editor cursor/deletion/Visual-character unit, tied to
`unicode-segmentation` 1.13.3. Revisit segmentation only with a version migration, differential
corpus, and exact compatibility decision. Normalization, case folding, regex, syntax
parsing/highlighting, and persistent line/search indexes remain absent.

Full logical frames remain the oracle; acknowledged row-differential terminal output is the current
projection. Keep it only while frozen workload evidence remains at least 20 percent better in bytes
or latency and PTY reconstruction matches after cache loss, resize, wide/combining text, controls,
styles, and output faults. Cell-patch semantics do not belong in application meaning.

Revision-174 evidence closes maximum paste at 84.220 ms and reduces growing 1,000 inserts from
11.056 seconds to 3.883 seconds, but the 10,000-event corpus remains 27.865 seconds and a duplicate
unoptimized layout replay took 977.90 seconds. Reopen prepared-program dispatch, application state
shape, and viewport construction before adding a bytecode/native tier. Retain a faster tier only if
the complete editor replay improves at least 30 percent with exact state/frame/action equality and
the explicit-frame interpreter remains the restart and differential oracle.

## Interaction topology

Foreground editor state plus one capacity-one host worker won. Unsaved buffers are intentionally
lost on process exit; project and file authorities survive in their own owners. Add a recovery
journal or hybrid checkpoint only after a named unsaved-work recovery requirement justifies a new
immutable authority, retention, corruption, cleanup, and unknown-publication contract. Never reuse
development history or file contents as editor undo.

One executing job is sufficient for current root search, file, and semantic-project workflows.
Increase the fixed bound only if a complete workload proves authority-busy prevents useful work and
the replacement closes ordering, queue/result memory, cancellation, stale outcomes, publications,
panic containment, and shutdown. Do not add a general async runtime or scheduler.

A resident daemon requires a demonstrated multi-client or unattended workflow that cannot use the
foreground session. Per-authority mutation remains serial. A bytecode/native tier requires execution
to dominate a complete product workflow and at least 30 percent improvement against the interpreter
differential.

## Terminal and filesystem

The retained terminal consumer uses key press/repeat, paste, resize, SGR mouse, focus, signal, EOF,
closed abstract styles, cursor shapes, and row-differential projection. Key release, clipboard,
capability negotiation, suspend/resume, and platforms other than Linux x86-64 remain absent. Add an
event only when application meaning consumes it and malformed/unsupported input, ordering, bounds,
and cleanup are closed.

The selected filesystem is Linux `openat2` confinement under one pinned root. It supports list,
regular-file read, deterministic bounded recursive literal search, no-replace create, expected-base
replace with ordinary-mode preservation, and reconciliation. Delete, rename, directory creation,
permission editing, binary editing, file watches, multiple roots, symlink following, mount traversal,
and network-filesystem claims remain absent. Add an operation class only for one product command
with exact grant, race, publication, and recovery semantics.

Hard links are not forbidden; device/inode and digest are returned as observation evidence. If a
product requires hard-link isolation, select and prove an exact trust policy before claiming it. The
current adapter has no cross-platform path normalization or case-folding contract.

## Product scope and trust

`lkjedit` is a Vim-like tiled UTF-8 terminal editor with selected-root and semantic-project tabs. It
is not a complete Vim clone, IDE framework, binary editor, GUI, language server, plugin system,
package manager, collaborative editor, shell, process supervisor, or hostile-code sandbox. Add a
typed settings/keymap authority only after a concrete user workflow proves conflict detection,
persistence, bounded discovery, and deterministic help from one owner.

Network sync, multi-user authorization, secrets, signatures/provenance, encryption, sandboxing,
remote repositories, branches/merge, database, mutable package resolution, and cross-platform
deployment are separate campaigns requiring complete threat models and products.

Provider/model token classes, cache classes, dated prices, and billing formulas remain unavailable.
Do not estimate tokens or money from request/response bytes. Retain only direct calls, bytes,
processes, elapsed/CPU time, storage, and correction observations.
