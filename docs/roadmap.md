# Evidence-gated roadmap

The semantic-development and `lkjwork` migration vertical is complete in the current checkout. This
file records only measured reversal gates and named future consumers. It is not a feature queue and
does not authorize ambient authority, dormant compatibility, or speculative infrastructure.

## Semantic repository scale

Full canonical snapshots plus compact revision records remain selected. The 100-change `lkjwork`
workload ends at 21,580,665 bytes; shallow current open is 3.224 seconds and complete deep doctor is
332.369 seconds in one warm-host unoptimized sample. Reopen journal, object-graph, Merkle, or packed
storage only if one of these gates is crossed by a representative maintained project:

- more than 256 MiB before 1,000 revisions;
- more than 5 seconds for optimized ordinary current open;
- more than 10 minutes for deep doctor at 100 revisions;
- backup/path count exceeds a named deployment service limit; or
- a complete multi-agent workflow cannot tolerate full-snapshot publication cost.

Any candidate must run the same frozen edit sequence to the same semantic result and preserve one
publication authority, exact record/diff history, tombstones, hostile decoding, unknown visibility,
portable backup, arbitrary exact-revision reads, and an independent full reconstruction oracle.
Delete the losing persistence format after a direct cutover.

Current reads conservatively hold the engine authority lock. Consider concurrent exact-revision reads
only for a measured multi-client project workflow, after snapshot lifetime, mutation interaction,
admission, shutdown, and path-substitution behavior are proved. Do not build branches, merge, rebase,
or a daemon to avoid deliberate stale-base refresh.

## Authoring and build economy

The current JSON/semantic-document proposal model, task-scoped contexts, known-digest replies, exact
receipts, and foreground session are the selected authoring surface. Reconsider only at these gates:

- retain apply-and-context-delta only if the same frozen feature needs fewer calls or corrections and
  response preflight/idempotency remain exact;
- add stable function-internal anchors only if whole-function replacement or holes dominate a real
  large-function maintenance task;
- add incomplete accepted targets only if staged work materially reduces correction depth and every
  product target remains explicitly unbuildable;
- add a derived target cache only if a restart-heavy build workload improves by at least 20 percent
  and exact keys, bounds, corruption fallback, eviction, and publication are closed;
- add a conventional source language only if evolved documents, closed JSON changes, and typed
  command forms all fail the same complete application task; and
- add provider-cost reporting only when the harness supplies exact provider/model, token classes,
  dated prices, and billing formula. Bytes remain bytes.

External immutable release inputs, additional target kinds, and product descriptor projections need
a complete cross-project consumer. Mutable coordinates, `latest`, arbitrary hooks, and ambient build
files remain forbidden.

## Product, runtime, and language gates

The one-shot and caller-owned session topologies remain sufficient. Prototype a resident supervisor,
scheduler, worker pool, concurrent mutation, or asynchronous runtime only when a measured complete
workflow cannot use them. Per-authority mutation stays serial, overload stays bounded, and the
explicit-frame interpreter remains the differential oracle.

Reopen bytecode or native execution only when interpretation dominates a complete representative
operation and total workflow time improves by at least 30 percent. Add text slicing/search,
normalization, case folding, scalar/grapheme indexing, maps, sets, generic declarations, mutable
builders, or higher-order sequence operations only for a frozen current application with exact fuel,
traps, encoding, equality, ordering, and retained accounting.

Product instance import/migration, network synchronization, multi-user authorization, secrets,
signatures, encryption, hostile-native-code isolation, and cross-platform deployment are separate
campaigns. Each needs an active threat model and end-to-end acceptance. Linux x86-64 under one
trusted local operator remains the only verified deployment.

## Rich TUI editor and explorer readiness

Current classification: lkjscript can own a bounded deterministic editor core, typed persistent
application state, and semantic-project browsing data. It cannot own a production terminal editor or
filesystem explorer. Terminal events/rendering/session lifecycle, selected filesystem authority,
file conflict publication, background work, cancellation, clipboard, and process invocation are
absent. No TUI probe was retained because the completed `lkjwork` migration already exercised the
semantic-authoring blockers and no current product consumes the missing host interfaces.

Stages below mean: **supported** is exercised by current platform/product contracts; **model-only**
can be expressed as bounded pure/application state but lacks a complete consumer or efficient
operation; **absent** has no accepted host or semantic contract.

| capability | stage | exact current gap | minimum activation gate |
|---|---|---|---|
| D.1 pure editor-state core | model-only | products/sums/sequences can model buffers, modes, panes, and commands, but no retained editor workload exists | build a bounded pure insert/delete/move/undo reference-model differential through project targets |
| D.2 buffer identity | model-only | nominal IDs can distinguish buffers from paths/content, but allocation, close, and reopen policy is unspecified | freeze a multi-buffer workflow with nonreuse and duplicate-content cases |
| D.3 large text representation | model-only | immutable UTF-8 text has no range insert/delete and localized updates would copy/scan excessively | compare current text, line sequence, piece table, and rope-like design over 1,000 localized edits; retain only a material complete-workflow win |
| D.4 cursor semantics | absent | no accepted byte/scalar/grapheme/line-column indexing contract | choose one indexing domain for a real editor and test multibyte, combining, boundary, and edit invalidation cases |
| D.5 selection semantics | absent | no anchor/head/range update contract | first consumer supports one linear selection with exact replacement behavior |
| D.6 undo/redo | model-only | application history can be data, but retention, branching-after-undo, and crash semantics are unspecified | bounded pure command history plus durable-instance restart; never move development HEAD backward |

| D.27 diagnostics and annotations | model-only | typed diagnostics are expressible, but source snapshot/range identity and stale rejection are absent | read-only semantic diagnostic view bound to one exact buffer revision |
| D.28 read-only semantic explorer | supported data, no TUI | project list/inspect/context/log/diff provide bounded exact data; interactive terminal rendering is absent | retain a UI only after it demonstrably improves navigation over the existing CLI without new broad authority |
| D.29 agent-authored editor subsystem | supported authoring, no consumer | `lkjwork why` proves bounded CLI authoring/history/target rebuild, but no editor project exists | add one pure editor command only after D.1 has a named retained product target |
| D.30 readiness class | partial | deterministic logic, durable state, pure queries, one-shot blob commands, and semantic authoring are exercised; live terminal/filesystem resources are absent | no production-TUI claim until D.7–D.14 and D.19–D.20 close in one complete product |

Additional readiness facts: project paths are safe deployment locators, not a general application
path value; product undo is distinct from immutable development history; hostile text is escaped by
current bounded CLI/product renderers, but grapheme width and terminal-cell safety remain part of a
future rendering contract; and no cross-platform terminal behavior is claimed.
