# Typed HTML composition with an ordinary native library

The literal [HTML library](examples/html.lkjc) and its independently authored
[article consumer](examples/html-consumer.lkjc) work on public **v0.1.44**.
They add no Rust implementation, intrinsic, new router or compiler syntax.
The accepted meaning graph remains the editable authority; these declaration
files are reproducible proposals, not a second synchronized source of truth.

This is a deliberately small example library, not a complete web framework or a
new built-in standard package. It demonstrates recursive nominal data, ordinary
function composition, exact offline package transport and standalone execution.
The [execution record](../campaigns/202609242152.md) distinguishes completed tests
from the unfinished larger external test matrix.

## Separate inline and block content

The library exposes two ordinary recursive variants:

| Type | Cases | Rendering |
| --- | --- | --- |
| `inline` | `text(Text)`, `strong(List<inline>)`, `emphasis(List<inline>)`, `code(Text)`, `line-break` | Escaped text, `strong`, `em`, `code`, `br`. |
| `block` | `paragraph(List<inline>)`, `heading(Text)`, `code-block(Text)`, `unordered-list(List<List<block>>)`, `section(List<block>)` | `p`, `h2`, `pre` with inner `code`, `ul` with one `li` per item, `section`. |

`render-inline`, `render-inlines`, `render-block` and `render-blocks` return `Text`.
`document(language, title, blocks)` adds the doctype, one quoted `lang` attribute,
UTF-8 metadata, escaped title and body. Empty input, empty list items and authored
order are preserved. The private balanced join combines rendered text chunks;
it is not a new text-buffer implementation or a measured performance claim.

A paragraph accepts inline content, not another block. Emphasis and strong content
have the same restriction. List items and sections can contain blocks recursively.
This avoids asking an HTML parser to repair a paragraph containing another
paragraph or a heading. It is not a model of every HTML content category.

All text leaves, title and language use the exact standard's existing
`html-escape-text`. Existing entity text is escaped again as text, not accepted as
markup. Tags are fixed by the native cases; the generic wrapping helper is private.
There is no raw-markup, arbitrary-tag, arbitrary-attribute or URL constructor.

These are typed composition and output-context choices, **not an HTML sanitizer or
a hostile-code boundary**. The result is ordinary `Text`; application code can
still concatenate other text. `lang` is escaped but not validated as a language
tag. Do not reuse HTML escaping as JavaScript, CSS or URL validation. The native
text tests preserve NUL and line endings in the serialized result; browser text
round-tripping for those inputs is not claimed. General browser compatibility,
accessibility auditing and a security certification are outside this example.

## Create and check the library

Place a compatible `lkjscript` executable and both literal inputs in an otherwise
empty working directory outside the compiler checkout. Use an absolute executable
path so changing directories does not select another program. The commands below
use a POSIX shell for launching and substituting observed identities only; the
public product parses, validates and accepts all program meaning.

```sh
work="$(pwd)"
LKJ="$work/lkjscript"
"$LKJ" new html --template minimal
"$LKJ" package builtin inspect
"$LKJ" package builtin export --kind transport --output "$work/standard.lkjp"
```

Read `revision`, `package-revision` and `transport` from the `package` record of
`package builtin inspect`. Set `STANDARD_REVISION`, `STANDARD_PACKAGE_REVISION`
and `STANDARD_TRANSPORT` to those exact values. A minimal project has no staged
standard dependency: the declaration's explicit `add.dependency` is not a substitute
for staging its complete source closure.

```sh
cd "$work/html"
"$LKJ" package dependency stage --transport "$STANDARD_TRANSPORT" \
  --input-file "$work/standard.lkjp"
"$LKJ" status
```

Set `LIBRARY_BASE` to the `revision id` from this project's status, then bind the
literal request. No source graph is generated by this substitution.

```sh
sed -e "s/LIBRARY_BASE/$LIBRARY_BASE/g" \
  -e "s/STANDARD_PACKAGE_REVISION/$STANDARD_PACKAGE_REVISION/g" \
  -e "s/STANDARD_REVISION/$STANDARD_REVISION/g" \
  "$work/html.lkjc" > "$work/html-bound.lkjc"
"$LKJ" change plan --input-file "$work/html-bound.lkjc"
```

Review the plan and set `PLAN` to its exact `plan token`. The recorded fresh
library creates 262 owners, updates and deletes none, and adds one dependency.
Its 16 local tests have not run merely because a plan is prepared or accepted.

```sh
"$LKJ" change apply --input-file "$work/html-bound.lkjc" --plan "$PLAN"
"$LKJ" check
"$LKJ" package current export --kind transport --output "$work/html.lkjp"
```

On public v0.1.44, the check passes 61 tests: 16 library tests plus 45 from its
exact standard, with production/reference agreement. Another standard selection
can change the total. The export reports the library's `id`, `revision`,
`package-revision` and `transport`; retain them as `HTML_PACKAGE`, `HTML_REVISION`,
`HTML_PACKAGE_REVISION` and `HTML_TRANSPORT`.

## Import from a separate application

```sh
cd "$work"
"$LKJ" new article --template minimal
cd "$work/article"
"$LKJ" package dependency stage --transport "$HTML_TRANSPORT" \
  --input-file "$work/html.lkjp"
"$LKJ" status
```

Staging the library transports its exact standard closure too. The consumer still
explicitly declares both dependencies because it also calls the standard. Set
`CONSUMER_BASE` from the new project's status and bind its literal input. Replace
`HTML_PACKAGE_REVISION` before `HTML_PACKAGE`, since one placeholder is a prefix
of the other.

```sh
sed -e "s/CONSUMER_BASE/$CONSUMER_BASE/g" \
  -e "s/STANDARD_PACKAGE_REVISION/$STANDARD_PACKAGE_REVISION/g" \
  -e "s/STANDARD_REVISION/$STANDARD_REVISION/g" \
  -e "s/HTML_PACKAGE_REVISION/$HTML_PACKAGE_REVISION/g" \
  -e "s/HTML_REVISION/$HTML_REVISION/g" \
  -e "s/HTML_PACKAGE/$HTML_PACKAGE/g" \
  "$work/html-consumer.lkjc" > "$work/html-consumer-bound.lkjc"
"$LKJ" change plan --input-file "$work/html-consumer-bound.lkjc"
```

Review this separate plan and update `PLAN` to its token before applying it.
The recorded consumer creates 74 owners, updates and deletes none, and selects
two exact dependencies.

```sh
"$LKJ" change apply --input-file "$work/html-consumer-bound.lkjc" --plan "$PLAN"
"$LKJ" check
"$LKJ" build --output "$work/article.lkja"
"$LKJ" run page --arguments \
  '["ja","Notes",[{"title":"one","body":"<&>"}]]' \
  --result-file "$work/page-result.json"
```

The consumer has its own nominal `entry` record. Its ordinary function maps entries
to library-owned blocks; no library edit or application-specific intrinsic is
needed. The recorded check passes 64 tests: three consumer, 16 library and 45
standard tests, with production/reference agreement.

The other pure target, `render`, accepts the recursive block model directly:

```sh
"$LKJ" run render --arguments \
  '["ja","sample",[{"case":"heading","value":"<hi>"}]]' \
  --result-file "$work/tree-result.json"
```

Both result files contain a **JSON string**, not an unquoted HTML file. Decode that
string before treating it as HTML. These output paths must not already exist, and
an output parent containing `..` rejects. Use new absolute paths for subsequent runs.

## Standalone execution and HTTP composition

A `command` project template supplies a product-owned command deployment descriptor.
For standalone use, copy that descriptor beside `article.lkja`, set `artifact` to
`article.lkja` and `target` to `render` or `page`, and retain the other fields.
Run it from a directory containing only the compatible executable, artifact and
descriptor, using `run --deployment PATH`. No authoring project or library transport
is required in that runtime directory. The command is pure and needs no grants.
The recorded detached `render` run succeeds after both authoring projects have
been moved away from their original paths; the originals are retained, not deleted.

The resulting text can be supplied to the separate native HTTP response library
with `text/html; charset=utf-8` and the existing text-to-bytes function. That is a
composition direction, **not a tested HTTP integration of this library**. No server
was started in this campaign, and resident runtime policy is unchanged.

The next acceptance work is the larger detached input matrix and independent
HTML-tree checks for nonempty adversarial text, followed by an actual typed HTTP
consumer. The first detached empty-text tree passed exact output and independent
parse5 structure checks, but the larger driver stopped on an incorrectly assumed
cleanup-summary spelling. Its attempted correction then had a JavaScript syntax
error; a further correction was blocked by the tool safety check and not retried.
Do not report the planned 88 rendering cases or six malformed-input cases as passed.
