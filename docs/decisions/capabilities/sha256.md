# SHA-256 Digest Capability

## Purpose

Allow `.lkjscript` products to retain only a verifier for high-entropy access
keys and sessions, and to checksum durable import/projection records. Token
policy, encoding, comparison, key rotation, and schema remain language code.

## Status

**Current.** The fixed digest primitive, source consumer, and configured
verification registrations are implemented. Command evidence is recorded in
[current state](../../current-state.md).

## Decision

`sha256: fn inputs byte-slice output bytes` validates the
checked shared view, computes the exact 32-byte SHA-256 digest, and returns new
immutable bytes. The implementation is a small owned Rust primitive; it takes no
algorithm, output-size, key, or caller-supplied state argument. It adds no
third-party crate.

The language product must encode/verifier-compare safely and use its own
constant-time policy where relevant. HMAC, password KDF, encryption, and
WebAuthn are not implied.

## Verification

NIST known-answer vectors cover the empty input, `abc`, the standard long
message, and one million `a` bytes. VM coverage verifies zero-length and
bounded-view calls return exact immutable bytes; host coverage verifies
binary/NUL input, invalid/oversized views, a fresh exact 32-byte output, and
wrong-view errors. Compiler and core tests cover the fixed signature, effects,
opcode mapping, stack metadata, and malformed type stacks. The canonical source
consumer prints the first byte of SHA-256(`abc`) (`186`) and is registered with
xtask, release smoke, and Docker verification.
