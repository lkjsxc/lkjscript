# Typed named references over accepted meaning

The accepted graph already supports the composition used by the task/foreground libraries, but
their consumer builder needed separate host maps of standard and library member identities.
Request-local creation symbols did not address that burden. Compact `reference.package` and
`reference.owner` records now lower into typed, interned selector paths before symbol collection
and canonical intent encoding. Existing references remain supported.

The preparation owner resolves local namespaces against the unchanged accepted base and foreign
names against the explicit candidate dependency selection. Each dependency interface is admitted
once for this resolution and indexed by exact parent/class/name. Exported declarations have no
module metadata, so duplicate exported names reject; an exact exported declaration alias is the
escape hatch. No interface, graph, artifact or data representation changes to expose module names.
Module and target names are local only. Subtype, scope, visibility and complete-candidate validation
remain the use-site authority. Selection never acquires a grant or loads operational state.

The canonical prelude omits alias labels/order but retains all declared selectors, including unused
ones. Raw records remain charged before equivalent paths are deduplicated. New owner allocation
uses the existing ordering and intent seed; selected existing owners do not allocate. Old authored
intent bytes, request commitments and allocation identities retain their original encoding/domain.

Prepared review additionally binds the entire capabilities and internal-verifier registry. New
discovery necessarily changes that ephemeral binding. Old plan tokens therefore reject explicitly
and require re-review; preserving a frozen obsolete verifier context would create competing review
authorities. Both plan and apply can use the accepted-idempotency owner's retained historical base.
The accepted receipt is preserved and publication still rejects inconsistent requests. A changed
embedded supplier changes normalized request intent before repository access; original accepted
retries require their original exact supplier inputs, or a classified mismatch with exact-package
re-planning. No silent retry conversion is introduced.

The maintained foreground proof now uses a readable prelude. A separate literal cells-library
witness covers generic records/variants/helpers, local edits and exact dependency replacement.
These changes do not solve request-wide expression-symbol naming, flat expression verbosity,
implicit capture, type inference, requirement parameters or broader resource signatures. Those
remain independently selectable work after observing the public authoring cycle.

This source increment is accepted separately from the installer release at `037a1348`. Its additional
publication is batched with the next accepted non-delivery capability campaign, with at most one
such subsequent acceptance before selecting their combined publication. If none is selected, the
next architect should select an authoring release from this accepted source; a verified recovery
need can justify earlier additive publication. No later tag is preallocated.
