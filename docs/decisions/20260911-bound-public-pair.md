# Bound public-pair acceptance

The public job at source `7ea9c99a` ran the same five owners serially for each of two
byte-identical deliveries. Run 34557393945/1 spent 52 minutes 30 seconds in that step;
this is one hosted observation, not a matched performance baseline.

Keep independent anonymous acquisition/authentication, strict extraction and a small real command
lifecycle for both routes. Bind full-content equality and execution policy, then run the complete
existing five-owner suite once freshly within that pair. Exact is fresh; latest is bound to the
actual exact aggregate within the same invocation. The pair reader delegates substantive acceptance
to the existing typed readers and never creates a latest child aggregate.

The static executable embeds built-in package/template assets. Explicit project/artifact paths and
fresh private working directories remove checkout and executable-location dependencies. Candidate
environments are cleared; each full owner retains its own data, HTTP/TLS and scratch isolation.
Archive payloads and modes, verifier/handoff, target policy and non-secret hosted context are bound.
Runner services, kernel and scheduling remain trusted environmental dependencies shared by this one
operation. Pre/post observations detect drift, not arbitrary hostile mutation.

This changes only the public evidence mechanism in `docs/spec/verification.md`. It is not a cache,
cross-run receipt reuse, scheduler, smaller semantic suite, product format change or release.
Independent source-full, exact six-owner target and pre-publication five-owner proof remain.
Removing five expensive executions is deterministic; elapsed savings require measured evidence.
Historical failures and old receipt meanings remain intact. Reverse sharing if dependency binding
or mutation/cancellation sensitivity fails. The old workflow remains until replacement proof passes.
