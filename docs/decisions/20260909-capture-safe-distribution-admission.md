# Capture-safe distribution admission

The source already implements constrained generic environments, persistent lists, private bound
callbacks, and exact offline code closures at 0.1.28. The distribution workflow still admitted only
three HTTP witnesses and rejected the current six-oracle target summary. Campaign 202609092050
supersedes the blocked 202609091945 version freeze and adopts the completed semantic/consumer
cutover. Publishing this compositional boundary is the selected outcome; no language generation,
maintained graph identity, application-data layout, deployment, or additional target is changed.

`release/transferred.rs` owns one finite five-role inventory used by target admission, schema-4
verifier handoff, and pre-publication/exact-download/latest-download orchestration. Each child's
existing typed reader remains its behavioral authority. The aggregate binds actual candidate and
verifier bytes, manifest/capabilities, source/publication/boundary, child receipts and bounded logs,
and cleanup. Incomplete receipts precede child execution. The process owner tracks a bounded tree
of verifier descendants, including separately grouped runners, and uses PID lifetime witnesses and
pidfds for termination; it does not establish hostile-code sandboxing. A scoped Tokio signal
listener translates SIGINT/SIGTERM into bounded child termination and is joined before return.
This adds a direct contributor dependency on the already locked Tokio version without changing the
product dependency closure. Each retry gets a new root. Uncatchable process/host termination can
leave incomplete evidence and requires owned-resource inspection before retry; it never yields a pass.

The workflow retains its exact artifact ID/digest/run/attempt checks and externally supplied verifier
hash before execution. Only the publication job has contents-write authority; it has no checkout and
executes no repository code. Draft resumption, exact missing-assets-only upload, GitHub digests,
immutable administrator binding, and release/asset attestations remain required. Both anonymous
asset pairs are independently admitted before their bytes are compared.

each fault/rejection. This supplements ordinary owner tests and real public execution.

Count-only repair, shell behavioral duplication, a generic plugin framework, a monomorphic factory
substitute, and another language feature were rejected: none closes the specified public boundary
with one clear proof owner. Schema-3 verifier production admission and old three-HTTP workflow
branches are removed; predecessor fixtures remain negative tests. No product/generated asset
regeneration is required by this tooling-only cutover unless its actual producer inputs change.

Reconsider this finite inventory only when a newly selected public workload changes the supported
release boundary, with migrated callers, an independent omission test, and all affected public
acceptance. Exact source/target/transferred/public execution results belong to the
