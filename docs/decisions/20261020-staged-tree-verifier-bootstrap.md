# Exact staged-tree verifier bootstrap

## Slice decision

- Boundary: the verifier's generated-input identity during precommit acceptance.
  The production call-scope change alters the source-derived validator hash, so
  a checker compiled from the baseline cannot admit the new generated bytes.
- Priority: this is a demonstrated verification dependency of restricted E1.
  Cargo successfully built the candidate, but the existing complete-byte binding
  correctly refused its different generated input. No semantic gate is relaxed.
- Expected effect: build the unchanged checker acceptance logic against the exact
  finalized candidate tree before changed/full acceptance and the final commit.
- Acceptance: retain default clean-commit admission; admit an explicitly declared
  staged tree only with its exact base HEAD and matching actual working files;
  reject wrong identities, conflicts, incomplete/hidden index states, unstaged or
  untracked inputs and source/context drift; preserve Cargo output identity and
  failure receipts; pass the bootstrap fixtures and the complete gate registry.
- Remaining limits: source identity is not independent proof of checker behavior.
  This transition changes no checker gate or generated-output acceptance logic.
  The single source writer must remain quiescent throughout bootstrap and checks;
  before/after observations cannot detect transient mutation followed by restoration.

## Contract

The default bootstrap still requires clean committed source. An additional explicit
`--expected-tree TREE --expected-source COMMIT` mode binds a staged candidate before
commit. COMMIT is the unchanged base HEAD; TREE is the actual candidate source, not
an assertion that the base commit contains it. Record both the committed tree and
candidate tree, the admission mode and source status in the bootstrap receipt.

Require a complete conflict-free index, no unstaged changes or nonignored untracked
files, ordinary index entries without assume-unchanged/skip-worktree flags, and only
regular indexed files with matching Git object hashes and executable modes. Hash
working files without Git clean filters so the tree identifies the bytes Cargo
reads. Reject unsupported symlinks/submodules and filter-transformed source rather
than inferring a source binding. Repeat admission after Cargo and require identical
source and build-context observations before publishing success. Existing canonical
checkout, one-target lease, Cargo environment/configuration, selected executable,
fresh/reused observation and compact failure-receipt contracts remain in force.

Finish every source, specification and status edit, stage the candidate, and test
this capability independently before adopting it. Bootstrap the declared tree, run
`check changed` while the candidate remains staged and `check full --fresh`, then
commit only that same tree. Verify the delivered commit's tree and ordinary remote
ancestry. An altered candidate requires a new bootstrap and acceptance. Do not use
this mode to waive a failed gate, change generated expectations after compilation,
or claim release publication authority.

## Focused acceptance

The real bootstrap owner passes its owned Git/mock-toolchain fixture, including
unchanged clean-source controls, explicit staged admission and Cargo reuse, wrong
HEAD/tree, missing base, unstaged/untracked files, hidden index flags, executable
mode changes, clean-filter/raw-byte disagreement, intent-to-add, conflicts and
symlink refusal. Mutations to working source, index, HEAD and untracked inventory
during the build invalidate admission. Existing output/configuration/context and
compact failure-receipt controls remain active. No checker acceptance code changes.
