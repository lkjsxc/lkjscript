# SHA-256 Digest Capability

## Purpose

Allow `.lkjscript` products to retain only a verifier for high-entropy access
keys and sessions, and to checksum durable import/projection records. Token
policy, encoding, comparison, key rotation, and schema remain language code.

## Status

**Accepted Target.** No digest primitive is implemented yet.

## Decision

Add `sys-sha256 Buf I64 I64 -> Result Buf Str`. It validates the existing
bounded byte range, computes the exact 32-byte SHA-256 digest, and returns a
new buffer. The implementation is a small owned Rust primitive; it takes no
algorithm, output-size, key, or caller-supplied state argument. It adds no
third-party crate.

The language product must encode/verifier-compare safely and use its own
constant-time policy where relevant. HMAC, password KDF, encryption, and
WebAuthn are not implied.

## Verification

Use NIST known-answer vectors, zero-length and range vectors, binary/NUL input,
invalid ranges, opcode validation, and an `.lkjscript` consumer. Run canonical,
release, and Docker gates.
