## 2. Primary objective

Directly cut over the released public `query` operation to normalized authority by implementing exactly these three machine-discoverable, revision-pinned operations:

1. bounded enumeration of live semantic owners;
2. exact namespace lookup by canonical class, parent, and name; and
3. bounded incoming or outgoing semantic-relation lookup for one exact local owner or the current package.

The final public operation must read only the current normalized `GraphRepository`, emit deterministic compact records, paginate by stateless logical continuations, report dimension-separated work, reject predecessor projects and predecessor query grammar, and perform no accepted or derived writes.

The campaign is not a comprehensive query-language redesign. It deliberately excludes context traversal, generic impact prediction, fuzzy or substring search, historical-revision query, saved queries, arbitrary request documents, and compiler/runtime cutover.

## 3. Why this objective is selected now

The normalized public slice can create a project, orient to its current revision, inspect an owner when its exact typed identity is already known, and perform the current compact semantic changes. It cannot rediscover owner identities after an allocation receipt or prior agent context is lost, cannot resolve an exact name within a canonical namespace, and cannot navigate the committed relation graph. The broad public `query` command still enters predecessor `SemanticWorkspace`/`SemanticQueryIndex` paths and therefore cannot operate on the normalized project.

That is now the smallest direct blocker to reliable multi-session AI authoring. A future agent should be able to copy the executable, create or open a normalized project, rediscover semantic identities from accepted meaning, and collect the exact references needed for the next change without source text, a repository checkout, a hidden index authority, or remembered receipts.

## 6. Decision classification

### 6.1 Mandates

The following are not implementation options.

1. Accepted normalized semantic graph revisions remain the sole authority for program meaning.
2. Public query is read-only and must never advance HEAD, create a draft, write an index, persist a continuation, or alter a repository.
3. Public query operates only on normalized `GraphRepository` authority and rejects predecessor projects. No dual dispatch, compatibility reader, silent fallback, or environment-selected edition is permitted.
4. The public output is the existing compact line-record protocol, not JSON, source text, raw storage records, Rust debug output, or a complete schema dump.
5. The exhaustive public query grammar and finite vocabularies are executable-owned and discoverable through the registry/capabilities path.
6. Names are exact locators. Query never treats a name as continuity, performs fuzzy matching, case folding, substring search, or silently selects among candidates.
7. Owner continuity and relation endpoints use typed exact identities. Foreign identity domains reject.
8. Results are pinned to one observed accepted revision. Continuations are stateless, strict, revision-bound, selector-bound, and based on logical ordering rather than page coordinates.
9. Physical query indexes and caches are not required for correctness. This campaign must not add a query cache, daemon, session, registry layer, scheduler, database, memory mapping, custom allocator, `unsafe`, or new runtime dependency.
10. Internal resource admission remains multidimensional. Do not retain or introduce one scalar `work`/`fuel` value as the public or internal substitute for map, store, decode, item, and byte limits.
11. The complete canonical reconstruction and relation extractor remain independent test oracles. Ordinary query must not call them.
12. Public predecessor query aliases and request-document paths are deleted in the same cutover.
13. Context and impact are not implemented under another spelling. In particular, generic `impact OWNER` is forbidden because exact impact depends on which semantic dimensions and candidate changes differ; it belongs with reviewed change-plan evidence.
14. Preserve unrelated work and out-of-scope maintained consumers. Do not delete an internal predecessor helper still required by an unrelated predecessor command merely to maximize diff size.
15. Use stable Rust, the locked dependency graph, safe code, existing first-party tooling, and current repository lint policy.

### 6.2 Selected design

Implement one transport-neutral normalized query model with three variants, one renderer, one continuation codec, and one set of query descriptors.

The released grammar is:

```text
query owners [--kind KIND] [--limit N] [--bytes N] [--continuation TOKEN]
query find CLASS NAME [--parent OWNER]
query relations OWNER|package --direction incoming|outgoing [--kind KIND] [--limit N] [--bytes N] [--continuation TOKEN]
```

Global project selection remains the existing `--project PATH` contract and is not redesigned.

`KIND` for owner enumeration is the canonical snake-case name of `kernel::OwnerKind`. `CLASS` is the canonical snake-case name of `kernel::NamespaceClass`. Relation `KIND` is the canonical snake-case name of `kernel::RelationKind`. The executable registry must enumerate every accepted value from the same exhaustive inventories used by parsing and rendering.

The public logical defaults and hostile maxima remain the already normative values unless active HEAD has intentionally changed them:

- default page item limit: 50 items;
- maximum page item limit: 10,000 items;
- default output-byte limit: 64 KiB;
- maximum output-byte limit: 4 MiB, also bounded by the global compact-response limit.

Use named constants, checked conversions, and registry discovery. A lower minimum necessary to hold the fixed envelope may be retained. Do not add public `--work`, `--depth`, or `--fanout` options in this campaign.

Internally define a typed query admission that keeps at least these dimensions distinct:

- result items;
- rendered output bytes;
- persistent-map pages read;
- persistent-map bytes read;
- persistent-map entries visited;
- object-catalog lookups;
- object-store objects read;
- object-store bytes read;
- canonical records decoded; and
- witness records decoded.

Derive bounded physical admission from the logical page request, storage contract limits, and a named bounded scan quantum. A kind-filtered owner page may return fewer than the requested item count, including zero, while still returning a continuation that advances beyond every visited key. It must never rescan from the beginning or loop on the same continuation. Report exact observed dimensions in the compact result.

## 7. Target public behavior

### 7.1 Common request and observation rules

All three operations:

1. parse and normalize the complete request before opening graph authority when possible;
2. discover exactly one normalized repository using the existing safe project-discovery path;
3. open one immutable current `RepositoryView` and retain its repository, package, and revision binding for the complete operation;
4. reject a continuation before map traversal when its contract, repository, package, revision, operation, or normalized selector does not match;
5. use deterministic canonical ordering;
6. render through the bounded compact response writer;
7. leave stderr empty for classified finite outcomes under the current compact CLI policy;
8. perform no writes; and
9. return the exact registry digest used to classify the response.

The transport-neutral request model must be independent of raw CLI strings. CLI parsing, continuation decoding, engine execution, and compact rendering should be separate layers. Do not place semantic traversal inside `src/bin/lkjscript.rs` or duplicate query semantics in the registry renderer.

Recommended dependency direction:

```text
released argv/process boundary
    -> exhaustive query descriptor and strict parser
    -> typed normalized query request
    -> revision-pinned query engine
    -> RepositoryView / PersistentMap / canonical kernel and witness decoders
    -> typed query page and work report
    -> compact response renderer
```

The predecessor workspace/query modules must not appear in this path.

### 7.2 `query owners`

`query owners` enumerates live local semantic owners from the accepted canonical owner map.

Semantics:

- The canonical order is `EncodedOwnerKey` byte order.
- `--kind KIND` is an optional exact `OwnerKind` filter.
- Retirements, tombstones, package metadata, type objects, witness objects, compiler units, artifacts, and runtime handles are not owners in this result.
- The page begins strictly after the continuation's last visited owner key, or at the first key without a continuation.
- The engine visits a bounded logical range. It may inspect binding kind before decoding an owner object to skip a nonmatching kind.
- Each emitted owner is read from canonical authority. The record's key, header identity, and actual kind must agree.
- When the owner participates in a canonical namespace, include its exact `name`, `class`, and `parent` (`package` for a root namespace or the exact parent owner identity). Owners without a namespace omit those fields; do not synthesize names for bindings, expressions, documentation, or annotations.
- Do not emit complete bodies, type graphs, documentation, annotations, summary digests, or relation lists. Exact detail remains the role of `inspect owner` and future focused operations.
- The continuation stores the last logical owner key visited, not merely the last emitted key, so filtered pagination always makes progress.
- Determine `truncated` by bounded lookahead or equivalent exact map evidence. Do not emit an endless terminal continuation. An empty filtered page with a progressing continuation is valid.

The page output must be independently comparable with a sorted projection of `RepositoryView::reconstruct_full_oracle()`.

### 7.3 `query find`

`query find CLASS NAME [--parent OWNER]` performs one exact canonical namespace lookup.

Semantics:

- `CLASS` is one of `NamespaceClass::ALL`, not `OwnerKind`.
- `NAME` is decoded by the current canonical `Name` contract. No normalization beyond that contract, fuzzy match, substring match, or case folding is permitted.
- `module` and `target` are package-root namespaces: `--parent` is forbidden.
- `declaration`, `type_parameter`, `field`, `case`, `operation`, `parameter`, `requirement`, and `port` require one exact typed local `--parent OWNER`.
- Validate the parent's identity domain and, where canonical data can decide it cheaply, its live kind. A parameter parent may be a declaration or operation as defined by the kernel namespace model.
- Look up exactly one `NamespaceKey` in the committed namespace witness.
- A missing key is a successful `match=false` result, not a process failure.
- A present key must resolve to a live canonical owner whose key, kind, canonical namespace class, parent, and name exactly reproduce the requested namespace key. Any disagreement is corruption, not `no-match` and not an index miss.
- Namespace uniqueness means there is no ambiguous-success state. Duplicate or conflicting evidence is corruption.
- Emit the same compact owner projection used by `query owners` for a match.
- `query find` has no continuation and no item-limit option. Its output remains globally byte-bounded.

This operation is the primary recovery path for agents that know semantic names and scopes but no longer hold allocation receipts.

### 7.4 `query relations`

`query relations OWNER|package --direction incoming|outgoing [--kind KIND] ...` reads one exact relation prefix.

Semantics:

- `OWNER` is a live exact local owner identity. `package` selects the current package endpoint so exact package-dependency relations are queryable without inventing a package-owner ID.
- `--direction` is required. Do not default to or implement `both`; separate directions preserve one canonical order and one continuation domain.
- `--kind KIND` is an optional exact `RelationKind` filter. Prefix the committed map by endpoint and kind when kind is present rather than filtering a broad scan after decoding.
- Incoming results use the reverse-relation map; outgoing results use the forward-relation map.
- The page begins strictly after the continuation's last full logical relation key.
- Decode every selected key strictly and verify that its observed endpoint, direction, and optional relation kind match the request prefix. Relation values must have the canonical empty representation.
- Emit exact source and target endpoints. An endpoint record contains a package identity and, for an owner endpoint, a typed owner identity. Do not collapse package and owner domains into an ambiguous string.
- Foreign package/owner endpoints already bound by accepted relations may appear in output. They are observations, not permission to open ambient foreign repositories.
- A nonexistent local owner input is a classified semantic failure rather than an empty relation page. This prevents a mistyped identity from masquerading as a valid owner with no relations.
- A current package endpoint is always valid.
- Ordering is the canonical relation-key order already defined by witness encoding.

The concatenation of all pages must equal the requested projection of a sorted canonical relation set produced independently by full snapshot reconstruction and `kernel::extract_relations`.

### 7.5 Compact response model

Use one shared renderer and one registry-owned field inventory. Exact field spelling may be adjusted only to conform to the current compact-record conventions, but the semantic records below are required.

Every successful response begins with:

```text
result status=success command=query.owners|query.find|query.relations
project path=... name=... repository=... package=...
revision observed=...
query operation=... digest=...
```

Owner results use repeated `owner` records containing:

- `id`;
- `kind`;
- `named=true|false`;
- when named, `name`, `class`, and `parent=package|OWNER`.

Relation results use repeated `relation` records containing:

- `kind`;
- `source-package` and optional `source-owner`;
- `target-package` and optional `target-owner`.

A terminal `summary` record contains at least:

- `returned`;
- `visited`;
- `match=true|false` for `find` or an equivalent closed field;
- `truncated=true|false` for paged operations.

When and only when more logical results may remain, emit one `continuation token=...` record.

A `work` record reports at least:

- map pages read;
- map bytes read;
- map entries visited;
- catalog lookups;
- store objects read;
- store bytes read;
- canonical records decoded;
- witness records decoded; and
- exact rendered output bytes if the writer can report it without a second full render.

End with the current schema/registry binding used by other compact commands.

Do not emit Rust type names, physical page digests, filesystem pack coordinates, complete owner bytes, complete schemas, or passing-oracle detail. If exact current compact field naming uses hyphens rather than underscores, preserve that convention consistently in the registry, parser, renderer, tests, and generated docs.

### 7.6 Continuation contract

Implement a new normalized query continuation contract rather than accepting predecessor continuation bytes.

The canonical payload contains at least:

- continuation contract version;
- query contract version;
- repository identity;
- package identity;
- exact observed revision;
- query operation;
- digest of the normalized semantic selector and ordering fields;
- exclusive logical resume key; and
- a domain-separated integrity digest over the canonical payload.

Rules:

1. Encode through the repository's strict bounded packed-data conventions and a canonical URL-safe textual representation suitable for one compact field. Do not use serde/Rust enum layout as the contract.
2. Bound encoded and decoded length before allocation. The payload is fixed metadata plus one logical map key whose storage contract is already bounded; select the smallest named cap that safely covers the exact canonical maximum and record its rationale. It should not approach the 4 MiB response limit.
3. Reject unknown version, foreign domain, wrong fixed length, malformed base encoding, padding variants when the selected textual contract forbids them, noncanonical bytes, bad integrity digest, trailing bytes, invalid logical key, and reserved identities.
4. The selector digest includes operation, owner/package seed, namespace class/name/parent where applicable, relation direction, relation-kind filter, owner-kind filter, and canonical ordering contract.
5. The selector digest deliberately excludes `--limit`, `--bytes`, and the continuation itself so a later page may choose different valid page/output bounds without changing semantic selection.
6. Bind exact current revision. Do not silently continue against a newer HEAD, even when the resume key still exists.
7. Use the last logical key visited and resume exclusively after it. Never expose or bind a physical map page, file offset, pack coordinate, process-local index, or memory address.
8. Store no server-side or repository-side continuation state.
9. A query with no more possible entries emits no continuation.
10. Add a separate query digest domain from the continuation integrity domain. A digest identifies the normalized query; it is not authentication, provenance, or secrecy.

### 7.7 Persistent-map traversal requirement

Add only the smallest reusable persistent-map read primitive needed for paged query.

It must support:

- full-map or prefix-map traversal;
- an optional exclusive logical lower bound;
- deterministic sorted visitation;
- early stop after a caller-owned item/scan boundary;
- exact `MapWork`/remaining admission propagation;
- corruption checks equal to existing lookup/prefix traversal; and
- no materialization of the complete map.

Do not create a second map implementation or query-specific page decoder. The primitive must be tested against `BTreeMap` or an independently sorted vector across empty maps, one-entry maps, multiple page shapes, prefix boundaries, lower bounds before/equal/inside/after the key set, page splits, malformed pages, and admission exhaustion.

A later continuation page must descend from the logical lower bound rather than visit and discard every earlier key. Instrumented tests must prove that `entries_visited` is bounded by the current page/scan quantum and does not grow with the number of earlier entries.

### 7.8 Error and failure behavior

Use current stable diagnostic classes and exit mapping. Add stable query-specific codes for at least:

- usage/unknown action or option;
- invalid owner kind, namespace class, relation kind, direction, identity, parent rule, limit, or byte limit;
- owner not found;
- predecessor project/grammar/continuation;
- malformed, oversized, noncanonical, foreign, mismatched, or stale continuation;
- output item too large for the requested byte limit;
- map/store/decoder admission exhaustion by owning dimension;
- missing canonical owner or witness object;
- owner key/header/kind disagreement;
- namespace witness/canonical owner disagreement;
- relation prefix/key/value disagreement; and
- infrastructure I/O failure.

Read-only semantic no-match is not a failure. Resource exhaustion is not corruption. Missing required accepted/witness objects and impossible cross-bindings are corruption, not cache misses. A failed query leaves HEAD and every repository byte unchanged.

Do not leak unbounded token bytes, owner bodies, file contents, secrets, or stack traces into diagnostics. Include the failed boundary, stable code, observed revision when safely available, and an actionable correction.

## 8. Target authority, state, ownership, and dependency boundaries

After completion:

- **Program meaning authority:** accepted normalized canonical graph revision.
- **Required derived read evidence:** the accepted revision's committed namespace, ownership, summary, and relation witness roots.
- **Query request:** transient typed process input.
- **Query result:** transient compact projection of one observed revision.
- **Continuation:** transient stateless projection binding a logical resume position; never program or repository authority.
- **Query digest:** identity of normalized selection, not meaning or authentication.
- **Full snapshot/relation extraction:** independent test and doctor oracle, not ordinary query execution.
- **Predecessor query indexes:** private residue only while exact out-of-scope consumers remain; never public normalized authority.

Resource ownership is lexical to one query invocation. Map readers, object readers, buffers, decoded records, output writer, and continuation bytes are released on success, no-match, exhaustion, cancellation, corruption, and infrastructure failure. No cleanup command is required because no durable query state is created.

Keep the query engine independent of CLI string parsing and compact rendering so a future transport can reuse the typed request without inheriting argv or line-record details. Do not make that future transport public in this campaign.

The final response must be concise and must not paste large diffs or logs. Return a structured evidence packet containing:

1. starting branch and HEAD;
2. final branch and HEAD;
3. every coherent commit SHA and purpose;
4. implemented public grammar and one concise workflow example;
5. changed authority, query, continuation, registry, and response boundaries;
6. exact predecessor actions, adapters, schemas, indexes, fixtures, tests, and docs removed;
7. exact internal predecessor query residue retained, its consumers, and why deletion was out of scope;
8. every deviation from this selected design;
9. the exact checkout evidence that justified each deviation;
10. focused verification commands and summarized results;
11. the fresh full verification command, receipt path/digest, gate count, and result;
12. explicit classification of checks as fresh, reused, skipped, unavailable, or failed;
13. benchmark/scale fixture, commands, environment, observations, and evidence path/digest;
14. proof that query wrote zero repository bytes and did not advance HEAD;
15. generated-document verification result;
16. known limitations and unresolved empirical questions;
17. `git status --short` and branch status;
18. whether a normal push was performed and its remote/branch, without exposing credentials; and
19. the smallest next campaign candidates in priority order.

The next-candidate list should normally begin with:

1. dependency-closed normalized command template plus `check`/`build`/`run` and maintained standard/`lkjournal` migration planning;
2. exact change-plan impact-detail export, followed only then by a public impact projection;
3. bounded context traversal with an independently justified stateless or explicit-file continuation design;
4. remaining authored semantic operations; and
5. later package/service/worker cutovers.

If evidence changes that order, explain it with exact repository facts.

The final working tree must be clean except for explicitly identified preserved user work. Documentation, generated discovery, implementation, tests, evidence, and the campaign ledger must describe the same final state.
