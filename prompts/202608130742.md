## The concrete contradiction to remove

The public workspace type boundary is already identity-based.
`SemanticType::Product` carries a stable product entity.
`SemanticType::Enum` carries a stable enum constructor identity.
The private compiler type representation is not consistently identity-based.

- `Type::Product(String)` currently uses a mutable declaration name as product type identity.
- `Type::Enum` currently stores both `EnumId` and a mutable declaration name.
- Private type equality and hashing currently include the enum name.
- Workspace conversion currently recovers a product entity through a product-name index.
- Product field resolution may recover a declaration through the product name stored in the type.
- A naive product rename would require sweeping every nested type occurrence by old text.
- A naive enum rename would leave equality, hashing, and display copies inconsistent unless every occurrence were swept.
- A global name sweep would make a presentation edit masquerade as semantic type mutation.
- A global name sweep would increase the chance of missed occurrences in signatures, fields, patterns, match plans, expressions, witnesses, or incomplete records.
- A global name sweep would preserve the wrong authority.

Do not implement nominal rename by globally replacing embedded type names.
Remove the name-based private type identity instead.

## Focused evidence quality

- A projection-only test is insufficient for compiler integration.
- A compile-only test is insufficient for runtime semantics.
- A runtime-only test is insufficient for identity continuity.
- An identity-only test is insufficient for collision behavior.
- A success-only test is insufficient for transaction atomicity.
- A product rename test without later compaction is insufficient for the ProductId cutover.
- An enum rename test without equality/hash coverage is insufficient for removing enum names from types.
- An imported test without parser/load counters is insufficient for proving source independence when those hooks exist.
- A bytecode equality assertion is optional when names intentionally enter debug metadata; runtime and semantic identity assertions remain mandatory.
- A native-path assertion must prove actual native entry rather than infer it from eligibility.
- A VM fallback assertion must prove pre-entry decline and exactly-once execution.
- A deep test should reuse existing scale infrastructure rather than duplicate huge fixtures.
