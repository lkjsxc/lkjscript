## 22. Source-Free Hello Construction Sequence

1. Create an empty workspace.

2. Record revision 1 and its missing-entry blocker.

3. Create `fact` with one `i64` parameter and `i64` result.

4. Create `main` with one stdio capability parameter and `unit` result.

10. Use stable entity identity for the recursive call.

11. Use canonical operations for comparison, decrement, and multiplication.

12. Assert that `fact` body publication preserves the function and parameter identities.

13. Fill `main` through a later revision-checked transaction.

14. Load the stable stdio capability parameter.

15. Call `fact(10)` by stable function identity.

16. Convert or format the result through the canonical string operation.

17. Print through the canonical stdio operation.

18. Assert that the final snapshot has no completeness blockers.

19. Assert that final effects are known.

20. Assert that main's effect summary includes host I/O.

21. Assert that call and reference edges target the stable identities.

22. Assert that no source or path attachment was fabricated.

## 27. Avoiding a Second Operation Authority

The following designs are suspect and require rejection unless evidence proves otherwise:

```text
workspace/draft.rs:
    const ALLOWED_OPERATIONS = [...]

workspace/query.rs:
    match operation { ... result type ... }

workspace/transaction.rs:
    match operation { ... ownership ... }

workspace/docs:
    copied operation table
```

The canonical operation module already owns operation semantics.

Workspace code should consume those semantics.

A small workspace-specific constructibility predicate may exist only if it owns a real authoring representability invariant.

That predicate must not repeat signature, effect, capability, ownership, or runtime semantics.

The predicate must be exhaustive over the closed enum.

The query and direct construction path must share it.

If no representability invariant remains after canonical validation, delete the predicate entirely.

Do not create a dynamic registry to avoid an exhaustive match.

A closed exhaustive match is simpler and safer when a real classification remains.
