## Primary falsifiable hypothesis

Hypothesis: native-image contract digests and configurable contract injection are redundant on the current in-process typed native-image path.
The suspected redundancy is specific to the native image and installer path.
It does not imply that persistent package manifests, package locks, source hashes, module-interface hashes, memory-interface hashes, or other independent artifacts should lose validation.

Confirm the hypothesis only when all of the following are true:
- Every production `InstallableImage` is created by current native-crate code in the same build as its installer.
- Safe external code cannot construct or mutate an `InstallableImage` with arbitrary private fields.
- There is no current serialization, plugin, dynamic-library, IPC, cache, disk image, network image, or cross-version loader for native images.
- The digest comparison does not protect an FFI or unsafe memory boundary that structural integrity validation cannot protect.
- The digest comparison does not select runtime behavior or prevent a real same-build type confusion.
- The mismatch state exists only because the public `EncodingConfig` deliberately permits injection.
- Removing the metadata does not weaken image structural validation, relocation validation, runtime-slot validation, source-map validation, accounting, W^X, or entry verification.
- Removing the metadata does not alter package-lock or required-package validation.
- Removing the metadata does not create an unvalidated independently produced artifact route.

Falsify the hypothesis when any current producer or consumer crosses an independent version, process, serialization, dynamic-code, cache, or trust boundary that genuinely needs explicit contract identity.

## Selection rubric

Score candidates qualitatively; do not build or commit a scoring framework.
- Prefer a candidate with a concrete current producer and consumer.
- Prefer a candidate whose invalid state is fabricated by configuration rather than arising at a real boundary.
- Prefer a candidate that deletes a representation or validation pass.
- Prefer a candidate that reduces public API surface.
- Prefer a candidate that removes a dependency edge without moving shared facts arbitrarily.
- Prefer a candidate that removes test-only construction of impossible production states.
- Prefer a candidate that clarifies a trust boundary.
- Prefer a candidate that reduces recurring agent orientation cost.
- Prefer a candidate whose correctness can be protected by focused existing tests.
- Prefer a candidate whose cutover is dependency-closed.
- Prefer a candidate that leaves no migration or compatibility layer.
- Prefer a candidate with a clear reversal condition.
- Reject a candidate selected only because its crate is small.
- Reject a candidate selected only because its name is old.
- Reject a candidate that creates a new facade to hide fan-in.
- Reject a candidate that moves types solely to alter `cargo tree` output.
- Reject a candidate that weakens a real unsafe or persistent artifact boundary.
- Reject a candidate that requires broad semantic redesign to save a few fields.
- Reject a candidate that adds more code than it removes without a stronger invariant.
- Reject a candidate that opens several unrelated implementation areas.
