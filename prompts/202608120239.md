## 10. Normative public edit contract

### 10.1 Preferred operation shape

```rust
Edit::MoveSequenceChild {
    sequence: NodeId,
    child: NodeId,
    before: Option<NodeId>,
}
```

Use this name and shape unless focused inspection reveals an established repository convention that materially improves clarity.

Any adjusted name must preserve the same narrow semantics.

`sequence` identifies the existing sequence expression that owns the order being changed.

`child` identifies one existing direct semantic child of that sequence.

`before` identifies another existing direct child of the same sequence, or is `None` to append the moved child after every remaining child.

The edit uses stable semantic identities only.

Do not accept a numeric source index, preorder, dense index, path, span, textual location, or debug label as input.

### 10.2 Order law

- Read the base revision named by the transaction.
- Validate that `sequence` is a live node in that base revision.
- Validate that the node kind is exactly the semantic sequence kind.
- Validate that `child` is a live direct child of `sequence` in that base revision.
- When `before` is `Some(anchor)`, validate that `anchor` is a live direct child of the same sequence.
- Reject `before == Some(child)`.
- Remove `child` from the ordered direct-child list.
- When `before` is `Some(anchor)`, insert `child` immediately before `anchor` in the remaining list.
- When `before` is `None`, append `child` to the end of the remaining list.
- Interpret the anchor after removing the moved child so movement direction cannot create an off-by-one ambiguity.
- Preserve the internal structure and order of the moved subtree.
- Preserve the internal structure and order of every sibling subtree.
- Do not clone semantic meaning merely to implement the permutation.
- Treat sequence child order as semantic evaluation order.
- Recompute the sequence result from the new final child according to existing language semantics.
- Preserve empty-sequence semantics, but an empty sequence has no movable child.
- A one-child sequence has no distinct semantic reorder.
- Do not flatten nested sequences as an incidental consequence.
- Do not normalize, sort, deduplicate, or otherwise rewrite sibling expressions beyond the requested move.
- Do not infer movement intent from equal content.

### 10.3 No-op law

A movement edit whose resulting order is exactly the base order must not publish meaningless semantic churn.

Use the repository's established transaction no-op convention if one is explicit and well tested.

If no established convention governs this case, reject the movement as an invalid transaction before publication.

Do not allocate identities, increment the revision, drop provenance, or emit a movement diff for a rejected no-op.

Document and test the selected behavior.

Do not create a general no-op normalization framework for this task.

### 10.4 Identity continuity law

- The sequence node retains its `NodeId`.
- The moved direct-child root retains its `NodeId`.
- Every descendant of the moved child retains its `NodeId`.
- Every sibling direct-child root retains its `NodeId` even when its semantic ordinal changes.
- Every descendant of every shifted sibling retains its `NodeId`.
- Every ancestor of the sequence retains its `NodeId`.
- Every node elsewhere in the owning callable retains its `NodeId`.
- Every unaffected node elsewhere in the workspace retains its `NodeId`.
- Stable entities owned by or referenced from moved subtrees retain their `EntityId` values.
- Lexical locals, payload bindings, parameters, callable identities, nominal identities, and member identities retain identity unless another explicit edit removes them.
- Typed holes inside moved subtrees retain their `HoleId` values.
- Unresolved value references inside moved subtrees retain their unresolved identity values.
- No stable identity slot is consumed solely because a node changed semantic order.
- No surviving identity is tombstoned solely because a node changed semantic order.
- Private preorder, address, dense, place, slot, binding, plan, and layout coordinates may change.
- Private relocation is not exposed as deletion and creation.
- Old immutable snapshots retain the old address-to-identity relation and remain queryable.
- The new snapshot owns the new address-to-identity relation.
- Do not use names, source spans, source text, hashes, expression equality, debug output, or fingerprints to decide continuity.
- Continuity must come from the explicit movement operation and validated base identities.

## 17. Test organization requirements

- Add one focused regression test before broad implementation when practical.
- Prefer focused movement test modules over extending a six-hundred-thousand-byte undifferentiated test file.
- Reuse deterministic namespace helpers.
- Reuse expression draft builders.
- Reuse imported/source-free convergence helpers.
- Reuse compiler and runtime execution helpers.
- Reuse source-loader and parser counters.
- Reuse allocation-failure hooks and allocator-state assertions.
- Reuse small-stack worker helpers.
- Reuse existing normalized semantic comparisons.
- Do not duplicate complete source fixtures when generated semantic construction is clearer.
- Do not make tests depend on private vector positions unless the test specifically protects internal mapping arithmetic.
- Public contract tests should assert stable IDs, semantic ordinals, structured diffs, queries, projections, and outcomes.
- Decode structured output as a consumer would.
- Do not assert only debug substrings for machine-facing facts.
- Do not weaken existing replacement, deletion, hole, unresolved-reference, loop-control, ownership, or convergence tests.
- Delete any obsolete test that encoded the absence of movement as a permanent constraint.
- Keep largest geometries ignored and locked-release when they are expensive.
- Ensure default tests cross the relevant representation boundaries without repeating excessive stress.
- Do not add a new test runner solely for this vertical.

## 18. Performance and complexity protocol

Performance is a secondary acceptance property after semantic correctness.

The current measured architecture retains full recomputation for semantic edits because compilation dominates representative checks and no general incremental mechanism is justified.

Do not reverse that decision without new representative evidence.

The movement implementation must nevertheless avoid introducing an accidental superlinear identity-mapping path.

1. State the performance hypothesis before measurement.
2. State equivalent semantics.
3. State the exact movement workload.
4. State environment, build profile, cache state, sample protocol, and selection threshold.
5. Prefer deterministic work counts for reconciliation complexity.
6. Measure transaction, query, projection, compile, and optional VM phases separately when the existing harness makes this cheap.
7. Keep raw output outside Git.
8. Commit only compact reproducible evidence when a decision changes.
9. Do not add a benchmark framework.
10. Do not add an allocator framework solely for this task.
11. Do not add a cache.
12. Do not add parallelism.
13. Do not measure provider token billing by guessing from Rust value sizes.
14. Do not infer user-visible runtime improvement from edit payload size.
15. Use a generated large sibling sequence only to establish correctness and complexity shape.
16. Use a representative agent workflow only when one actually exists.
17. Keep full recomputation when movement transaction cost remains small relative to compilation.
18. Reverse a local optimization if it adds more maintenance than the removed measured work.
19. Remove temporary counters when no continuing regression test consumes them.
20. Record movement as an invalidation of the existing conservative domains unless evidence and a current consumer justify narrower invalidation.

## 19. Agent API-cost discipline

Reducing the API cost of agents that develop `lkjscript` is desirable but subordinate to correctness and maintainability.

This task should improve cost primarily through a smaller repository policy file, focused retrieval, compact evidence, and the constant-size semantic movement operation.

Do not create cost accounting infrastructure.

- Search symbols before opening large files.
- Read diffs and focused ranges before full files.
- Do not dump the complete semantic program, HIR, SSA, bytecode, machine code, or generated tests.
- Do not return complete successful logs.
- Use quiet native command flags.
- Capture failures and surface only relevant excerpts plus a local log path.
- Reuse compact subagent evidence packets.
- Do not have multiple agents inspect the same broad files.
- Do not ask multiple agents to solve the same architecture question.
- Do not ask subagents for long generic summaries.
- Run the smallest command that can falsify the current hypothesis.
- Do not repeat an unchanged successful command.
- Do not rerun full verification from every subagent.
- Count movement operation fields and replacement draft nodes only as a structural comparison.
- Label provider token or billing impact as unknown absent a real measured consumer.
- Do not optimize output so aggressively that failures become hidden.
- Do not make diagnostics cryptic merely to save bytes.
- Do not add abbreviations to public semantic facts when clear names are cheaper to maintain.
- Prefer deterministic concise projections over source reconstruction.
- Prefer one-shot semantic operations over many low-level round trips.
- Do not add a service solely to retain model context.
- Do not add persistent agent memory to the repository.
- Do not commit task prompts or conversation transcripts.
- Report actual command count, output bytes, model round trips, or context reductions only when measured.
- State estimated savings with explicit assumptions and uncertainty.

## 20. Anti-overengineering rejection checklist

Reject a proposed design if any of the following is true and no current evidence overrides the rejection.

- It introduces a generic movement abstraction before a second current movement consumer exists.
- It introduces coordinates or paths as public identity.
- It stores movement history in snapshots.
- It adds a second mutable semantic tree.
- It serializes semantic state merely to move a node.
- It renders and reparses source.
- It uses content hashes as mutable identity.
- It compares whole trees to guess continuity.
- It adds a graph rewrite engine.
- It adds a visitor framework for one local traversal.
- It adds a trait hierarchy to share two short movement functions.
- It adds an event bus for one transaction result.
- It adds a transaction dependency planner for one rejected overlap case.
- It adds an incremental query system.
- It adds a cache without measured repeated dominant work.
- It adds parallelism to identity reconciliation without measured separable dominance.
- It adds persistence or a journal.
