## Primary objective

Make the owned structural-value execution boundary demonstrably safe for arbitrarily deep valid values, with work proportional to the represented value rather than to depth squared, while simplifying contradictory or duplicated traversal behavior.

The selected vertical is the path by which nested collector-free product and enum values are constructed, validated, cloned where cloning is intentionally supported, compared, returned as `OwnedValue`, summarized or formatted, exported or imported by retained product code, and destroyed.

This objective is based on a concrete repository hypothesis, not a mandate to implement a preconceived patch:

- `SemanticChildren` already has explicit iterative clone and drop behavior.
- `SemanticValue::try_equal` already provides fallible iterative equality.
- Several surrounding types still appear to derive recursive `Debug`, `PartialEq`, or related behavior over the same nested tree.
- `validate_structural_snapshot` appears to retain an ancestry vector and perform `active.contains(...)` for each visited node even though the safe owned tree representation may make cycles unrepresentable.
- `docs/status.md` still says that runtime structural-value paths do not all have deep-stack evidence.

Verify each statement against the current checkout. If the hypothesis is wrong or the path has already been repaired, do not manufacture work. Select the highest-leverage remaining user-depth stack-safety defect in the current local compile/run or semantic-workspace product, document why it outranks this candidate, and complete one similarly narrow vertical. ## Implementation requirements

Implement the smallest coherent correction supported by the investigation.

### Stack safety

No operation reachable from valid user-controlled structural depth may rely on native recursion unless the recursion is statically bounded independently of the value.

Replace or remove recursive derived behavior when it is reachable through the selected boundary. In particular, audit recursive derives rather than assuming custom clone/drop on `SemanticChildren` makes every enclosing trait stack-safe.

Use explicit work stacks or another simpler non-recursive mechanism. Prefer local traversal code over a universal visitor framework. A small shared helper is justified only when it removes real duplicated traversal logic without obscuring failure and ownership behavior.

### Equality

Preserve equality laws.

Do not implement infallible `PartialEq` by calling a fallible comparison and converting allocation failure into `false`; a value must not become unequal to itself because temporary allocation failed.

Acceptable outcomes include:

- a direct iterative `PartialEq` implementation with ordinary Rust allocation behavior, alongside a fallible boundary API where typed allocation failure is required; or
- deletion of an unnecessary `PartialEq` contract and migration of real consumers to an explicit fallible comparison.

Choose from actual consumers and total complexity. Do not keep a recursive trait path and a stack-safe explicit path in parallel without a concrete reason.

Comparison must cover equal values and mismatches in type, payload kind, enum tag, child count, shallow leaves, and deep leaves.

### Debug and summaries

Diagnostic formatting must not recurse on user depth or emit an accidentally unbounded full tree.

Prefer a deterministic bounded summary that reports the useful structural kind, type identity, field count, and optionally validated metrics over a recursive derived dump. Preserve detailed inspection only where a real consumer needs it, and make expansion explicit.

Do not let test assertion formatting reintroduce a deep recursive `Debug` path.

### Validation and complexity

Prove whether the safe owned semantic-value representation can contain a cycle.

If cycles are impossible without violating Rust safety or a private invariant, remove impossible cycle detection from this tree validator and document the representation invariant in the narrow owning module. A depth-linear ancestry scan is not useful defense if the state cannot occur.

If a real aliasing or graph construction path can create cycles, retain validation at the correct boundary but replace depth-squared ancestry lookup with an algorithm proportional to nodes and edges. Do not add hashes, global identities, or a graph framework to an ordinary tree.

Validation must remain fail-closed for malformed type/payload combinations, invalid UTF-8 strings, invalid paths, arithmetic overflow, and allocation failure.

### Clone, destruction, and failure paths

Preserve collector-free ownership and deterministic cleanup.

Do not introduce tracing GC, hidden reference-counting semantics, raw-pointer language surface, retain/release APIs, a custom allocator, a general arena, or a second structural representation merely to solve traversal.

Deep destruction must remain iterative for:

- fully constructed values;
- clones;
- partially built conversion state;
- validation or publication failure;
- VM/JIT decline before entry;
- entered failure and outcome cleanup where applicable.

Do not leak or double-release runtime-owned structural objects. Preserve failure-atomic publication and exactly-once effects.

### Representation discipline

Prefer repairing the existing owned tree if it remains the simplest correct representation.

Do not convert it to the semantic DAG representation merely to reuse graph machinery. Do not merge tree, DAG, runtime handle, and native-layout concepts unless the audit proves that the current separation is the root cause and the replacement is smaller.

Delete obsolete derives, helpers, tests, or duplicated traversal paths in the same change. There is no compatibility obligation for internal APIs or debug output.
