## Primary outcome

A caller starting from `Workspace::empty` must be able to:

1. create a non-generic enum with payload-bearing variants;
2. create functions and/or `main`;
3. fill a typed hole with a flat, non-recursive source-free draft containing an ordered exhaustive match;
4. bind selected payload fields in exactly the corresponding arm scope;
5. use those bindings in arm bodies;
6. query and project the resulting semantic state without source attachments;
7. compile the complete snapshot directly through `compile_snapshot`;
8. execute it through the production validated bytecode/VM route;
9. obtain the same language result, ownership behavior, cleanup behavior, and relevant semantic observations as an equivalent imported program; and
10. prove that source loading and parsing were not invoked by the source-free path.

A representative acceptance program should be equivalent to:

```text
enum Choice {
    Some { value: i64 }
    None
}

main() -> i64 {
    match Choice::Some { value: 42 } {
        Choice::Some { value } => value
        Choice::None => 0
    }
}
```

## Semantic requirements

### Match evaluation

- Evaluate the scrutinee exactly once.
- Preserve deterministic arm order.
- Select the first useful matching arm according to the accepted language semantics.
- Require at least one arm.
- Reject non-exhaustive matches.
- Reject statically useless, duplicate, or subsumed arms.
- Join reachable arm body types using the canonical control-flow type rule.
- Preserve `never` behavior correctly.
- Derive effects from the scrutinee and reachable arm bodies using the existing canonical effect machinery.
- Preserve the existing unreachable marker and verifier invariants, or replace them through a complete simpler cutover. Do not leave two lowering models.

### Initial pattern surface

Implement the smallest coherent pattern surface that closes the enum-payload vertical.

At minimum it must express:

- wildcard patterns;
- named payload binding patterns; and
- enum variant patterns whose fields are identified by stable workspace field identities and have one nested pattern per declared field.

The implementation may support additional already-canonical closed patterns, such as Boolean, integer, product, or nested aggregate patterns, only when doing so materially simplifies reuse of the existing checker or avoids a knowingly throwaway representation. Do not broaden the task merely for symmetry.

Do not design a universal pattern DSL, protocol, registry, visitor framework, macro system, or extensible plugin architecture.

A strong default is a flat non-recursive pattern draft with transaction-local pattern node IDs, analogous to `ExpressionDraft`. This is not an API compatibility requirement. Choose a better shape if the actual code shows one, but preserve these properties:

- physical vector order is not semantic;
- every child identity is checked;
- the pattern is one connected tree;
- cycles, reused children, disconnected nodes, stale children, and host-index overflow reject;
- user-controlled pattern depth does not recurse on the native stack;
- enum, variant, and field references use opaque stable workspace identities, not names, source positions, compiler-dense IDs, or layout IDs;
- pattern-local binding handles cannot escape their draft; and
- publication produces stable workspace identities only for user-semantic bindings.

### Pattern bindings and scope

Pattern bindings are semantic locals, not textual substitutions.

- A binding is visible only in its corresponding arm body and nested expressions.
- It is not visible in the scrutinee, another arm, an earlier field pattern, or outside the match.
- Duplicate names or duplicate draft binding handles within one arm reject deterministically.
- A binding has the exact instantiated payload type.
- References to a binding from another arm or outside its scope reject before publication.
- User-authored pattern bindings receive normal stable workspace entity identities and participate in definition, reference, type, projection, diff, and hole-context queries.
- Compiler-only hidden scrutinee or projection temporaries must not become authorable semantic entities or legal constructor candidates.

Audit the imported path for compiler-hidden match locals. If they are currently exposed as ordinary public workspace entities, correct both imported and source-free behavior in this same vertical rather than perpetuating the leak. Do not hide genuine user pattern bindings.

Do not solve scope by name lookup after lowering. Scope and identity must be explicit before publication.

### Ownership and cleanup

Reuse the canonical complete-HIR ownership checker and existing match lowering semantics. Do not create a source-free ownership checker.

Preserve:

- exactly-once scrutinee ownership;
- movement or projection of payloads according to existing language semantics;
- no use after move;
- no move while borrowed;
- arm-local lifetime and cleanup;
- cleanup of unselected and partially projected payloads;
- cleanup on normal return, trap, error, cancellation, and early exit where the existing language path supports them; and
- no double cleanup.

Do not add a source-free-only ban on otherwise valid enum payload types merely to simplify match authoring. The current source-free declaration API may retain its independently justified field restrictions during this turn, but matching an imported valid enum must not be reinterpreted or made unsafe. Keep one match semantic model that can be widened without replacement.

Do not introduce GC, reference-counting language semantics, manual `free`, or a second ownership mode.
