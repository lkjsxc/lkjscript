## 14. Text engine campaign

The current flat immutable scalar sequence is the correctness baseline, not the required final
production representation.

The current 1,000-growing-insert result is too slow for the intended product.

Do not solve it by raising fuel.

2. persistent piece tree over immutable original and append stores;
3. chunked persistent text sequence with line aggregates;
4. gap buffer or mutable piece table hidden inside one foreground runtime owner;
5. retain current flat text with a specialized transient edit builder;
6. deletion of unnecessary application-level text copying plus resident runtime state.

The candidate comparison must include:

- insertion near beginning, middle, and end;
- deletion near beginning, middle, and end;
- growing insert;
- large paste;
- line navigation;
- grapheme navigation if retained;
- current-buffer literal search;
- undo and redo;

- frame construction of a small viewport over a large file;
- save materialization;
- memory retention under undo;
- deterministic fuel;
- canonical fallback;
- malformed and excessive input;
- restart and cache loss where relevant.

The preferred long-term direction is a persistent UTF-8 representation with structural sharing,
bounded chunks, and exact line aggregates if it wins.

Persistent structure aligns naturally with immutable application values and undo roots.

## 17. Unicode contract

## 40. Performance targets

The following are ambitious campaign targets, not permission to fabricate success:

### 40.1 Local interaction

On a representative 120-by-40 terminal with a 1 MiB UTF-8 file:

- common Normal-mode movement input-to-logical-frame p95 at or below 8 ms;
- common Insert-mode single-grapheme edit input-to-logical-frame p95 at or below 16.7 ms;
- input decode plus host frame-diff and encode p95 at or below 4 ms excluding terminal device wait;
- no local edit should require project or filesystem I/O.

- 10,000 mixed local events at or below 10 seconds process-inclusive;

  typical terminal size;

  before retention;

- local input remains responsive while a bounded selected-root search runs;
- search result pages are bounded and appear incrementally or at a documented completion point;
- closing the search tab never blocks terminal shutdown indefinitely;
- project target work never mutates editor state outside typed outcome integration.
