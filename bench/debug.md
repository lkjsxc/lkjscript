# Debug formatting and derived implementations

Debug formatting is an ordinary source contract in library/fmt.lkj. The ? and
alternate #? modes call Debug::fmt through Formatter and source builders; no
raw representation, trusted reflection or formatting instruction is added.

Implementations cover integers, bool, char, str/String, references, Box,
slices/arrays/Vec, Option/Result, unit and tuples with one through twelve
fields. DebugStruct, DebugTuple and DebugList preserve field order, alternate
indentation and formatter errors. The Unicode 17.0.0 scalar escape intervals
in library/text_debug.lkj are generated by the independent Rust scalar witness
in tools/debug-unicode-witness.rs; the table is ordinary checked source.

derive(Debug) generates checked implementations for ordinary and generic
structs and enums. Unused generic bodies still require the field contracts.
Conflicting or repeated derives refuse. Tuple matching checks actual tuple
identity and field count, so an applied nominal type cannot masquerade as a
tuple merely because it has type arguments.

## Source operations and boundaries

Queries preserve the trait, implementation and generated-method identities.
Checked renames and authored body edits retain these meanings. Captured or
generated edits refuse where the origin cannot justify an authored change.
Ten malformed generated-origin controls exercise that distinction on both
engines.

Float implementations, additional container builders, x?/X? formatting,
dynamic width/precision and arbitrary Write sinks remain boundaries.
write!/writeln! currently target String or Formatter. These limits do not
claim that a surrounding original large root admits.
