# Frozen native experiment inputs

These are the exact literal native requests used in the three measured stages.
They are kept separately from the smaller maintained library/consumer pair so a
future library edit cannot silently relabel the historical timing evidence.
Their first-line revisions identify the original disposable project, not another
user's project. An experiment request is a proposal, not accepted meaning authority.

To repeat the workload, create a fresh command project with the selected executable.
For each request in order, copy the literal file, replace only its first-line base
with the current observed revision, plan the copied request, apply its exact token,
check and build. Stage 1 is `workload.lkjc`, target `measure`; stage 2 is
`diagnosis.lkjc`, target `diagnose`; stage 3 is `blocked.lkjc`, target `blocked`.
Each stage adds a module and retains the preceding ones. Build a separate artifact
and descriptor for each stage; never overwrite the recorded originals. Deployment
arguments are `[n, rounds, mode]`. The same-artifact mode meanings are in
[the study](../study.md). Compare full returned values, not only process success.

For stages 1, 2 and 3, modes cover 0–4, 0–7 and 0–9 respectively. All lengths,
repetition counts, run order, retained warm-up handling, measurement phases and
limitations are specified in the study and original predeclarations. A new authored
project has new graph/artifact identities; it is a reproduction, not the original
byte-bound observation. Keep source preparation separate from runtime invocation.

The TSV files retain all grouped matrix points, including empty Maps, zero repeats
and unfavorable results. Every group contains nine measured samples after the
separately retained run-zero warm-up. Minimum and maximum are observed extrema,
not confidence intervals. These TSV files are derived summaries, not replacements
for raw stdout/stderr/result bytes and per-process identity checks.

host-language implementation of these folds.
